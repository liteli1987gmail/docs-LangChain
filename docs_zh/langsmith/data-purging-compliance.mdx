本指南涵盖了数据到达 LangSmith Cloud 服务器后可用的各种功能，以帮助您实现隐私目标。

## 数据保留

LangSmith 提供自动数据保留功能，以帮助进行合规性和存储管理。数据保留策略可以在组织和项目级别配置。

有关数据保留配置和管理的详细信息，请参阅[数据保留概念](/langsmith/administration-overview#data-retention)文档。

## 自定义扩展保留策略

<Note>
此功能适用于[企业版](/langsmith/pricing-plans)客户。对于[自托管](/langsmith/self-hosted)企业版客户，请参阅[工作区级别配置部分](#workspace-level-extended-retention-for-self-hosted)。
</Note>

[企业版](/langsmith/pricing-plans)客户可以自定义[工作区](/langsmith/administration-overview#workspaces)级别追踪的扩展数据保留期，以满足特定的合规性要求。默认情况下，扩展保留期设置为 400 天，但您可以根据组织的需要进行调整。对保留期的更改仅适用于新追踪。

### 配置扩展保留

<Note>
以下 UI 步骤需要**组织管理员**或**组织操作员**角色（`organization:manage` 权限）。工作区管理员也可以通过 API 直接为其自己的工作区设置扩展保留时长（`workspaces:manage` 权限）。有关完整权限参考，请参阅[组织和 Workspace 操作](/langsmith/organization-workspace-operations)。
</Note>

在 [LangSmith UI](https://smith.langchain.com) 中：

1. 导航到页面底部的 **Settings**。
1. 从左侧菜单中选择 **Usage configuration**。
1. 在列表中找到要配置的工作区。
1. 点击该工作区 **Data retention policy** 列下的值。
1. 在 **workspace usage configurations** 模态框中，使用 **Extended - All traces are retained for** 选项的下拉菜单自定义扩展策略。
1. 选择 **Save**。

### 自托管的工作区级别扩展保留

[企业版](/langsmith/pricing-plans)自托管客户也可以使用工作区级别扩展保留配置，而非系统范围的 TTL 设置。这为不同工作区的数据保留提供了更细粒度的控制，无需更改环境变量。

<Warning>
如果您使用 blob 存储，您**必须**为每个配置的自定义保留期添加生命周期规则。例如，将工作区设置为 90 天保留意味着 blob 数据被写入 `ttl_90d/` 前缀，这需要一个匹配的生命周期规则来自动清理。请参阅 [blob 存储 TTL 配置](/langsmith/self-host-blob-storage#custom-workspace-level-retention-prefixes)了解详情和示例。
</Warning>

要为自托管部署进行配置，请参阅[自托管 TTL 文档](/langsmith/self-host-ttl)了解旧版系统范围方法或联系[支持](https://support.langchain.com)。

## 追踪删除

您可以使用 API 完成追踪删除。API 支持两种删除追踪的方法：

1. **按追踪 ID 和会话 ID**：通过提供追踪 ID 列表及其对应的会话 ID 来删除特定追踪（每个请求最多 1000 个追踪）
2. **按元数据**：删除与指定的元数据键值对匹配的工作区中的追踪

有关更多详细信息，请参阅 [API 规范](https://api.smith.langchain.com/redoc#tag/run/operation/delete_runs_api_v1_runs_delete_post)。

<Warning>
所有追踪删除都将删除相关实体，如所有数据存储中的反馈、聚合和统计。
</Warning>

### 删除时间线

追踪删除在非高峰使用时间处理，并非即时删除。LangChain 在周末运行删除作业。没有删除确认——您需要再次查询数据以验证它已被删除。

### 删除特定追踪

要通过追踪 ID 从单个会话中删除特定追踪：

<Note>
`session_id` 是您要删除的追踪的项目 ID。您可以在 LangSmith UI 的追踪项目页面上找到它。
</Note>

```bash
curl -X POST "https://api.smith.langchain.com/api/v1/runs/delete" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "trace_ids": ["trace-id-1", "trace-id-2", "trace-id-3"],
    "session_id": "session-id-1"
  }'
```

### 按元数据删除

按元数据删除时：

- 接受键值对的 `metadata` 对象。KV 对匹配使用 **或** 条件。如果追踪在元数据中具有**任何**指定的键值对，它将匹配（不是全部）
- 按元数据删除时不需要指定会话 ID。删除将应用于整个工作区。

要基于工作区中的元数据删除追踪（匹配**任何**元数据键值对）：

```bash
curl -X POST "https://api.smith.langchain.com/api/v1/runs/delete" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {
      "user_id": "user123",
      "environment": "staging"
    }
  }'
```

这将删除在其元数据中具有 `user_id: "user123"` **或** `environment: "staging"` 的追踪。

<Warning>
请记住，每个会话每请求只能安排最多 1000 个追踪。对于更大的删除，您需要发出多个请求。
</Warning>

## 示例删除

您可以通过我们的 API 自助删除数据集示例，根据您的数据保留需要支持软删除和硬删除两种方法。

<Warning>
硬删除将永久从整个数据集历史记录的所有版本中删除输入、输出和元数据。
</Warning>

### 删除示例是一个两步过程

对于批量操作，示例删除遵循两步过程：

#### 1. 按元数据搜索示例

在工作区中的所有数据集中查找具有匹配元数据的所有示例。

[GET /examples](https://api.smith.langchain.com/redoc#tag/examples/operation/read_examples_api_v1_examples_get)

- `as_of` 必须明确指定为时间戳。只有在 `as_of` 日期之前创建的示例才会被返回

```bash
curl -X GET "https://api.smith.langchain.com/api/v1/examples?as_of=2024-01-01T00:00:00Z" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "metadata": {
      "user_id": "user123",
      "environment": "staging"
    }
  }'
```

这将返回在工作区中所有数据集内其元数据中具有 `user_id: "user123"` **或** `environment: "staging"` 的示例。

#### 2. 硬删除示例

一旦您有了示例 ID，发送删除请求。这将从该示例的数据集的所有版本中清零输入、输出和元数据。

[POST /v1/platform/datasets/examples/delete/](https://api.smith.langchain.com/redoc?#tag/examples/paths/~1v1~1platform~1datasets~1examples~1delete/post)

- 在请求正文中指定 `example_ids`（示例 ID 列表）和 `hard_delete`（布尔值）

```bash
curl -X POST "https://api.smith.langchain.com/v1/platform/datasets/examples/delete/" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "example_ids": ["example-id-1", "example-id-2", "example-id-3"],
    "hard_delete": true
  }'
```

### 删除类型

#### 软删除（默认）

- 在数据集中创建带有 NULL 输入/输出的墓碑条目
- 保留历史数据并维护数据集版本控制
- 仅影响数据集的当前版本

#### 硬删除

- 从所有数据集版本中永久删除输入、输出和元数据
- 当合规性要求在所有版本中清零时完整移除数据
- 在请求正文中设置 `"hard_delete": true`
