<Note>
此功能仅在 Helm chart 版本 0.10.27（应用程序版本 0.10.74）及更高版本中可用。
</Note>

许多模型提供商支持通过环境变量设置凭据和其他配置选项。这对于你想要避免在代码或配置文件中硬编码敏感信息的自托管部署很有用。在 LangSmith 中，大多数模型交互是通过 `playground` 服务完成的，它允许你直接在 pod 本身上配置许多这些环境变量。这对于避免在 UI 中设置凭据很有用。

## 要求

* 运行 `playground` 服务的自托管 LangSmith 实例。
* 你要配置的提供商必须支持用于配置的环境变量。有关更多信息，请查看提供商的 Chat Model [文档](https://docs.langchain.com/oss/python/integrations/providers/overview)。
* 你可能想要附加到 `playground` 服务的 secrets/roles。
  * 请注意，对于 [IRSA](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html)，你可能需要授予 `langsmith-playground` 服务账户访问云提供商中的 secrets 或 roles 所需的权限。

## 配置

使用上述参数，你可以将 LangSmith 实例配置为使用模型提供商的环境变量。你可以通过修改 LangSmith Helm Chart 安装的 `langsmith_config.yaml` 文件或 Docker 安装的 `docker-compose.yaml` 文件来执行此操作。

<CodeGroup>

```yaml Helm
playground:
  deployment:
    extraEnv:
      - name: OPENAI_BASE_URL
        value: https://<my_proxy_url>
      - name: OPENAI_API_KEY
        valueFrom:
          secretKeyRef:
            name: <your_secret_name>
            key: api_key
  serviceAccount: # 如果你想使用 IRSA 或工作负载身份，这会很有用
    annotations:
      eks.amazonaws.com/role-arn: <your_role_arn>
```

```yaml Docker
# 在你的 docker-compose.yaml 文件中
langchain-playground:
  environment:
    .. # 其他环境变量
    - OPENAI_BASE_URL=https://<my_proxy_url>
    - OPENAI_API_KEY=<your_key> # 这将设置在 .env 文件中
```

</CodeGroup>

## VertexAI 配置

你可以使用带有 secrets 的环境变量或工作负载身份（GKE 的 GCP Workload Identity 或 EKS 的 AWS IRSA）为 playground 服务配置 VertexAI 凭据。

### 使用 secrets

使用 Kubernetes secrets 配置 VertexAI 凭据：

<CodeGroup>

```yaml Helm
playground:
  deployment:
    extraEnv:
      # Playground 特定的 secret（推荐）
      - name: GOOGLE_VERTEX_AI_WEB_CREDENTIALS
        valueFrom:
          secretKeyRef:
            name: gcp-vertexai-secret
            key: credentials_json  # 你的完整服务账户 JSON 作为字符串
      # 标准后备选项
      - name: GOOGLE_APPLICATION_CREDENTIALS
        value: /secrets/gcp-key.json
      # 可选：如果不在模型配置中，设置项目/位置
      - name: GOOGLE_CLOUD_PROJECT
        value: "your-gcp-project-id"
      - name: VERTEXAI_PROJECT_ID
        value: "your-gcp-project-id"
      - name: VERTEXAI_LOCATION
        value: "us-central1"
    extraVolumeMounts:
      - name: gcp-secret-volume
        mountPath: /secrets
        readOnly: true
    extraVolumes:
      - name: gcp-secret-volume
        secret:
          secretName: gcp-key-json  # JSON 文件 secret
          defaultMode: 0444
```

```yaml Docker
# 在你的 docker-compose.yaml 文件中
langchain-playground:
  environment:
    .. # 其他环境变量
    - GOOGLE_VERTEX_AI_WEB_CREDENTIALS=<your_service_account_json>  # 完整 JSON 作为字符串
    # 或使用文件路径
    - GOOGLE_APPLICATION_CREDENTIALS=/secrets/gcp-key.json
    - GOOGLE_CLOUD_PROJECT=your-gcp-project-id
    - VERTEXAI_PROJECT_ID=your-gcp-project-id
    - VERTEXAI_LOCATION=us-central1
  volumes:
    - ./gcp-key.json:/secrets/gcp-key.json:ro
```

</CodeGroup>

### 使用工作负载身份

你可以将 playground 服务账户配置为使用工作负载身份来承担 GCP 服务账户角色，而不是存储凭据。这是 GKE 集群的推荐方法。

#### GCP Workload Identity (GKE)

对于 GKE 集群，使用 GCP Workload Identity：

<CodeGroup>

```yaml Helm
playground:
  deployment:
    extraEnv:
      # 可选：如果不在模型配置中，设置项目/位置
      - name: GOOGLE_CLOUD_PROJECT
        value: "your-gcp-project-id"
      - name: VERTEXAI_PROJECT_ID
        value: "your-gcp-project-id"
      - name: VERTEXAI_LOCATION
        value: "us-central1"
    # 不需要凭据 - pod 通过注释承担 GCP SA 角色
  serviceAccount:
    create: true  # 如果不存在则启用
    annotations:
      iam.gke.io/gcp-service-account: "vertexai-sa@your-gcp-project.iam.gserviceaccount.com"
```

</CodeGroup>

<Note>
使用 GCP Workload Identity 时，确保 GCP 服务账户具有所需的 VertexAI 权限（例如 `roles/aiplatform.user`）。
</Note>

#### AWS IRSA (EKS)

对于 EKS 集群，你可以使用 AWS IRSA 来承担 GCP 服务账户角色：

<CodeGroup>

```yaml Helm
playground:
  deployment:
    extraEnv:
      # 可选：如果不在模型配置中，设置项目/位置
      - name: GOOGLE_CLOUD_PROJECT
        value: "your-gcp-project-id"
      - name: VERTEXAI_PROJECT_ID
        value: "your-gcp-project-id"
      - name: VERTEXAI_LOCATION
        value: "us-central1"
    # 不需要凭据 - pod 通过 AWS IAM 角色承担 GCP SA 角色
  serviceAccount:
    create: true  # 如果不存在则启用
    annotations:
      eks.amazonaws.com/role-arn: arn:aws:iam::<account>:role/LangSmith-VertexAI-Role
```

</CodeGroup>

<Note>
使用 AWS IRSA 时，确保你的 AWS IAM 角色有所需的权限来承担 GCP 服务账户角色，并且 GCP 服务账户具有所需的 VertexAI 权限。
</Note>
