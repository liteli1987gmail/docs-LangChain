LangSmith 提供了灵活的控件来管理使用[单点登录（SSO）身份验证](/langsmith/authentication-methods)时用户如何加入你的[组织](/langsmith/administration-overview#organizations)。你可以独立启用或禁用即时配置（JIT）和用户邀请，以匹配你组织的安全和入职要求。

启用 SSO 后，你有两个独立设置：[JIT 配置](#jit-provisioning) 在用户通过 SSO 登录时自动添加用户，而[邀请](#invites) 允许管理员在用户访问组织之前手动邀请用户。你可以通过任何组合配置这些[设置](#configuration-scenarios)来控制你的用户入职工作流程。

本页说明这些设置如何工作以及如何配置它们。

## 设置

你可以独立控制以下两个设置来管理用户如何加入你的组织。

### JIT 配置

`jit_provisioning_enabled` 设置控制自动用户配置。启用后，通过 SSO 提供商进行身份验证的用户会自动添加到你的[组织](/langsmith/administration-overview#organizations)，并被分配到具有默认[角色](/langsmith/rbac)的默认[工作区](/langsmith/administration-overview#workspaces)。有关详细信息，请参阅[配置默认 SSO 设置](#configure-default-sso-settings)。禁用后，用户必须通过邀请或 [SCIM](#scim-integration) 明确添加，然后才能访问组织。

### 邀请

`invites_enabled` 设置控制手动用户邀请。启用后，[组织管理员](/langsmith/administration-overview#organization-roles)可以向用户发送邀请，然后用户才能登录。通过 SSO 登录时，受邀用户可以认领他们的邀请。禁用后，不允许手动邀请，用户只能通过 JIT 配置或 [SCIM](#scim-integration) 加入。

### 更新设置

你可以通过 LangSmith UI 或 LangSmith API 更新这些设置：

<Tabs>
<Tab title="UI" icon="layout">

在 [LangSmith UI](https://smith.langchain.com) 中：

1. 导航到 **设置** → **组织** → **访问和安全** → **常规**。
1. 根据需要切换 **启用 JIT 配置** 和 **允许邀请**。
1. 在 **设置** → **组织** → **SSO 配置** 中[配置默认 SSO 工作区和角色](#configure-default-sso-settings)。

</Tab>
<Tab title="API" icon="code">

使用[更新组织信息](https://api.smith.langchain.com/redoc#tag/orgs/operation/update_current_organization_info_api_v1_orgs_current_info_patch)端点以编程方式更新组织设置：

```bash
curl -X PATCH https://api.smith.langchain.com/api/v1/organizations/current/info \
  -H "Authorization: Bearer $LANGSMITH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "jit_provisioning_enabled": true,
    "invites_enabled": true
  }'
```

响应包含更新的当前组织配置：

```json
{
  "id": "org-uuid",
  "display_name": "My Organization",
  "jit_provisioning_enabled": true,
  "invites_enabled": true,
  "sso_login_slug": "my-org",
  ...
}
```

</Tab>
</Tabs>

<Note>
如果你使用的是 [LangSmith 自托管](/langsmith/self-hosted)，请考虑以下事项：

- JIT 配置和邀请设置仅适用于默认组织（由 `default_sso_provision=true` 标识）。其他组织必须在自托管中使用邀请。
- 环境变量 `SELF_HOSTED_JIT_PROVISIONING_ENABLED` 可以全局覆盖 JIT 配置设置。设置为 `false` 时，无论各组织的单独设置如何，JIT 配置都将对所有组织禁用。
- 有关其他自托管用户管理自定义项，请参阅[自定义用户管理](/langsmith/self-host-user-management)。
</Note>

## 用户访问如何工作

当用户尝试通过 SSO 登录时，LangSmith 遵循此决策流程：


1. 用户通过 SSO 提供商进行身份验证。
1. LangSmith 检查用户是否已有组织访问权限：
    ```
    ├─ 是 → 用户已登录
    └─ 否 → 继续步骤 3
    ```
1. 检查邀请是否已启用 **并且** 存在待处理邀请：
    ```
   ├─ 是 → 使用邀请的组织角色配置进入组织；如果邀请包含工作区，则配置进入工作区
   └─ 否 → 继续步骤 4
    ```
1. 检查 JIT 配置是否已启用：
    ```
   ├─ 是 → 使用默认 SSO 工作区/角色自动配置用户
   └─ 否 → 拒绝访问（用户必须通过 SCIM 或由管理员添加）
    ```

<Note>
当 JIT 配置和邀请都已启用时，**邀请优先**。如果用户有待处理邀请，则使用邀请的内容添加用户，而不是默认 SSO 设置。
</Note>

## 配置场景

### 开放访问（两者都启用）

**配置：**
- ✓ 启用 JIT 配置
- ✓ 启用邀请

**行为：**
- 用户可以通过 SSO 立即登录并自动配置。
- 管理员可以发送邀请以分配特定角色或工作区。
- 受邀用户获得邀请配置；非受邀用户获得默认 SSO 配置。

**示例：**
```
用户 alex@company.com 通过 SSO 登录：
  - 不存在邀请 → 以查看者角色添加到默认工作区

用户 billy@company.com 通过 SSO 登录：
  - 存在"生产"工作区的编辑者角色邀请 → 仅添加到"生产"工作区并具有编辑者角色（邀请优先）
```

### 仅 JIT（邀请禁用）

**配置：**
- ✓ 启用 JIT 配置
- ✗ 禁用邀请

**行为：**
- 所有通过 SSO 进行身份验证的用户都会自动配置。
- 管理员无法发送邀请。
- 所有新用户接收相同的默认工作区和角色。

### 仅邀请（JIT 禁用）

**配置：**
- ✗ 禁用 JIT 配置
- ✓ 启用邀请

**行为：**
- 用户必须先被邀请，然后才能访问组织。
- 没有邀请的用户即使拥有有效的 SSO 凭据也会被拒绝访问。
- 精细控制谁可以访问组织。

**示例：**
```
用户 alex@company.com 通过 SSO 登录：
  - 有待处理邀请 → 成功加入组织

用户 billy@company.com 通过 SSO 登录：
  - 没有邀请 → 访问被拒绝（必须向管理员请求邀请）
```

### 封闭访问（两者都禁用）

**配置：**
- ✗ 禁用 JIT 配置
- ✗ 禁用邀请

**行为：**
- SSO 用户无法自动加入组织。
- 无法发送邀请。
- 用户必须通过 SCIM 或由管理员直接配置，一旦他们已通过 SCIM 成为组织的一部分。

## 用户访问快速参考

| JIT 启用 | 邀请启用 | 待处理邀请 | 结果 |
|-------------|-----------------|----------------|---------|
| ✓ | ✓ | 是 | 认领邀请（使用邀请配置） |
| ✓ | ✓ | 否 | 自动配置（默认 SSO 配置） |
| ✓ | ✗ | 不适用 | 自动配置（默认 SSO 配置） |
| ✗ | ✓ | 是 | 认领邀请 |
| ✗ | ✓ | 否 | **访问被拒绝** - 必须被邀请 |
| ✗ | ✗ | 不适用 | **访问被拒绝** - 必须使用 [SCIM](#scim-integration) 或管理员 |

## 配置默认 SSO 设置

当[启用 JIT 配置](#jit-provisioning)时，为新用户配置默认设置：

1. 默认工作区角色。选择自动配置时用户接收的[工作区角色](/langsmith/rbac#workspace-roles)。有关每个角色可以执行的操作的详细信息，请参阅[组织和工作区操作](/langsmith/organization-workspace-operations)。选项包括：

    - **[查看者](/langsmith/rbac#workspace-viewer)**：只读访问
    - **[用户](/langsmith/rbac#organization-user)**：标准访问
    - **[编辑者](/langsmith/rbac#workspace-editor)**：可以修改资源
    - **[管理员](/langsmith/rbac#workspace-admin)**：完全控制工作区

1. 默认工作区。选择用户自动添加到的一个或多个工作区。用户会在所有选中的工作区中收到相同的角色。配置方法：

    1. 进入 **设置** → **组织** → **SSO 配置**。
    1. 设置 **默认工作区角色**。
    1. 选择 **默认工作区**。
    1. 保存你的配置。

## SCIM 集成

如果你的组织使用 [SCIM](/langsmith/user-management#set-up-scim-for-your-organization)（跨域身份管理系统），用户可以通过你的身份提供商自动配置和管理。SCIM 提供了与 JIT 和邀请设置一起工作的额外用户管理机制。

<Note>
SCIM 组 membership 覆盖手动分配的角色或通过 JIT 配置分配的角色。如果你使用 SCIM，考虑禁用 JIT 配置以避免冲突。
</Note>

## SSO 组同步

[SSO 组同步](/langsmith/user-management#sso-groups-sync-alternative) 是 SCIM 的替代方案，它在登录时从 SSO 令牌中读取组 membership，并使用 SCIM 命名约定分配组织和工作区角色。同步在每次登录时在 JIT 和邀请解析之后运行，并且仅拥有它创建的 membership。

**与 JIT、邀请和 SCIM 的优先级：**

- **SCIM 来源的** membership 从不会被 SSO 组同步修改。
- **SSO 组同步来源的** membership 在每次登录时根据令牌中的组 membership 完全替换。
- **手动和 JIT 配置的** membership 不会被 SSO 组同步修改。

我们建议每个组织选择 SCIM 或 SSO 组同步之一，而不是两者，以避免混淆的优先级行为。有关配置和权衡，请参阅 [SSO 组同步](/langsmith/user-management#sso-groups-sync-alternative)。
