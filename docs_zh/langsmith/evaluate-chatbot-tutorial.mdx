在本指南中，我们将为聊天机器人设置评估。这些评估让您能够衡量应用程序在一组数据上的表现。能够快速可靠地获得这种洞察，将使您能够自信地进行迭代。

从高层次来看，在本教程中我们将：

* *创建一个初始黄金数据集来衡量性能*
* *定义用于衡量性能的指标*
* *在几个不同的提示词或模型上运行评估*
* *手动比较结果*
* *随时间追踪结果*
* *设置自动化测试以在 CI/CD 中运行*

要了解 LangSmith 支持的评估工作流程的更多信息，请查看[操作指南](/langsmith/evaluation)，或参阅 @[evaluate][Client.evaluate] 及其异步对应函数 @[aevaluate][Client.aevaluate] 的参考文档。

内容很多，让我们开始吧！

## 创建数据集

在准备好测试和评估您的应用程序时，第一步是定义您想要评估的数据点。有几个方面需要考虑：

* 每个数据点的模式应该是什么？
* 我应该收集多少个数据点？
* 我应该如何收集这些数据点？

**模式：** 每个数据点至少应该包含应用程序的输入。如果您有能力，定义预期的输出也非常有用——这些代表您期望一个正常运作的应用程序输出的内容。通常您无法定义完美的输出——这没关系！评估是一个迭代过程。有时您可能还需要为每个示例定义更多信息——比如 RAG 中要获取的预期文档，或者代理要执行的预期步骤。LangSmith 数据集非常灵活，允许您定义任意模式。

**数量：** 没有硬性规定您应该收集多少个。主要是确保您对可能需要防范的边缘情况有适当的覆盖。即使是 10-50 个示例也能提供很多价值！不要担心一开始就获得大量数据——您可以（而且应该）随着时间的推移不断增加！

**如何获取：** 这可能是最棘手的部分。一旦您知道要收集数据集……您实际上如何去做？对于大多数刚开始一个新项目的团队，我们通常看到他们开始手动收集前 10-20 个数据点。在从这些数据点开始后，这些数据集通常是*活着的*结构，会随着时间的推移而增长。它们通常在看到真实用户将如何使用您的应用程序、看到存在的痛点，然后将其中一些数据点移入这个集合后增长。还有一些方法，如综合生成数据，可用于扩充您的数据集。对于初学者，我们建议不要担心那些，手动标注大约 10-20 个示例即可。

一旦您有了数据集，有几种不同的方式将它们上传到 LangSmith。对于本教程，我们将使用客户端，但您也可以通过 UI 上传（甚至可以在 UI 中创建它们）。

对于本教程，我们将创建 5 个数据点进行评估。我们将评估一个问答应用程序。输入将是一个问题，输出将是一个答案。由于这是一个问答应用程序，我们可以定义预期的答案。让我们展示如何创建并将此数据集上传到 LangSmith！

```python
from langsmith import Client

client = Client()

# Define dataset: these are your test cases
dataset_name = "QA Example Dataset"
dataset = client.create_dataset(dataset_name)

client.create_examples(
    dataset_id=dataset.id,
    examples=[
        {
            "inputs": {"question": "What is LangChain?"},
            "outputs": {"answer": "A framework for building LLM applications"},
        },
        {
            "inputs": {"question": "What is LangSmith?"},
            "outputs": {"answer": "A platform for observing and evaluating LLM applications"},
        },
        {
            "inputs": {"question": "What is OpenAI?"},
            "outputs": {"answer": "A company that creates Large Language Models"},
        },
        {
            "inputs": {"question": "What is Google?"},
            "outputs": {"answer": "A technology company known for search"},
        },
        {
            "inputs": {"question": "What is Mistral?"},
            "outputs": {"answer": "A company that creates Large Language Models"},
        }
    ]
)
```

## 定义指标

创建数据集后，我们现在可以定义一些指标来评估我们的响应。由于我们有预期的答案，我们可以在评估中将其进行比较。然而，我们并不期望我们的应用程序输出那些**精确的**答案，而是期望输出相似的内容。这使我们的评估稍微复杂一些。

除了评估正确性，我们还要确保我们的答案简短精炼。这会更容易——我们可以定义一个简单的 Python 函数来测量响应的长度。

让我们继续定义这两个指标。

对于第一个，我们将使用一个 LLM 来**判断**输出是否正确（相对于预期的输出）。这种 **LLM-as-a-judge** 对于太复杂而无法用简单函数衡量的案例来说是相对常见的。我们可以在这里定义我们自己的提示词和 LLM 来用于评估：

```python
import openai
from langsmith import wrappers

openai_client = wrappers.wrap_openai(openai.OpenAI())

eval_instructions = "You are an expert professor specialized in grading students' answers to questions."

def correctness(inputs: dict, outputs: dict, reference_outputs: dict) -> bool:
    user_content = f"""You are grading the following question:
{inputs['question']}
Here is the real answer:
{reference_outputs['answer']}
You are grading the following predicted answer:
{outputs['response']}
Respond with CORRECT or INCORRECT:
Grade:"""
    response = openai_client.chat.completions.create(
        model="gpt-5.4-mini",
        temperature=0,
        messages=[
            {"role": "system", "content": eval_instructions},
            {"role": "user", "content": user_content},
        ],
    ).choices[0].message.content
    return response == "CORRECT"
```

对于评估响应的长度，这就容易多了！我们只需要定义一个简单的函数来检查实际输出是否小于预期结果长度的 2 倍。

```python
def concision(outputs: dict, reference_outputs: dict) -> bool:
    return int(len(outputs["response"]) < 2 * len(reference_outputs["answer"]))
```

## 运行评估

太好了！现在我们如何运行评估？既然我们有了数据集和评估器，我们所需要的就是我们的应用程序了！我们将构建一个简单的应用程序，它只有一个包含响应说明的系统消息，然后将其传递给 LLM。我们将使用 OpenAI SDK 直接构建这个：

```python
default_instructions = "Respond to the users question in a short, concise manner (one short sentence)."

def my_app(question: str, model: str = "gpt-5.4-mini", instructions: str = default_instructions) -> str:
    return openai_client.chat.completions.create(
        model=model,
        temperature=0,
        messages=[
            {"role": "system", "content": instructions},
            {"role": "user", "content": question},
        ],
    ).choices[0].message.content
```

在通过 LangSmith 评估运行这个之前，我们需要定义一个简单的包装器，将输入键从我们的数据集映射到我们想要调用的函数，然后将函数的输出映射到我们期望的输出键。

```python
def ls_target(inputs: str) -> dict:
    return {"response": my_app(inputs["question"])}
```

太好了！现在我们准备好运行评估了。让我们开始吧！

```python
experiment_results = client.evaluate(
    ls_target, # Your AI system
    data=dataset_name, # The data to predict and grade over
    evaluators=[concision, correctness], # The evaluators to score the results
    experiment_prefix="openai-4o-mini", # A prefix for your experiment names to easily identify them
)
```

instructions_v3 = "Respond to the users question in a short, concise manner (one short sentence). Do NOT use more than ten words."

        model="gpt-4-turbo",

## 比较结果

太棒了，我们已经评估了三次不同的运行。但是我们如何比较结果呢？第一种方法是通过在 `Experiments` 选项卡中查看运行来实现。如果我们这样做，我们可以看到每次运行的高层次指标概览：

![Testing tutorial compare metrics](/langsmith/images/testing-tutorial-compare-metrics.png)

我们可以看出 GPT-4 在了解各公司方面比 GPT-3.5 更好，而且严格的提示词对长度有很大帮助。但是如果我们想更详细地探索呢？

为了做到这一点，我们可以选择我们想要比较的所有运行（在这种情况下是全部三个），并将它们在一个比较视图中打开。我们立即看到所有三个测试并排显示。某些单元格用颜色编码——这显示的是相对于某个基线的某个指标的回归。我们自动选择基线和指标的默认值，但您可以自己更改它们。您还可以使用 `Display` 控件选择您看到的列和指标。您还可以通过点击顶部的图标自动过滤以仅查看有改进/回归的运行。

## 在 CI/CD 中设置自动化测试

现在我们已经以一种一次性的方式运行了这一点，我们可以将其设置为以自动化方式运行。我们可以很容易地将其作为一个 pytest 文件包含在 CI/CD 中。作为其中的一部分，我们可以记录结果 OR 设置一些标准来确定它是否通过。例如，如果我想确保我们始终获得至少 80% 的生成响应通过 `length` 检查，我们可以设置一个如下所示的测试：

```python
def test_length_score() -> None:
    """Test that the length score is at least 80%."""
    experiment_results = evaluate(
        ls_target, # Your AI system
        data=dataset_name, # The data to predict and grade over
        evaluators=[concision, correctness], # The evaluators to score the results
    )
    # This will be cleaned up in the next release:
    feedback = client.list_feedback(
        run_ids=[r.id for r in client.list_runs(project_name=experiment_results.experiment_name)],
        feedback_key="concision"
    )
    scores = [f.score for f in feedback]
    assert sum(scores) / len(scores) >= 0.8, "Aggregate score should be at least .8"
```

## 结论

这就是本教程的全部内容！

我们已经介绍了如何创建初始测试集、定义一些评估指标、运行实验、手动比较、设置 CI/CD 以及随时间追踪结果。这可以帮助您自信地进行迭代。

这只是开始。如前所述，评估是一个持续的过程。例如——您可能希望评估的数据点很可能随着时间的推移而继续变化。您可能希望探索许多类型的评估器。有关此信息，请查看[操作指南](/langsmith/evaluation)。

此外，还有其他方法可以评估数据，除了这种"离线"方式（例如，您可以评估生产数据）。有关在线评估的更多信息，请查看[设置 LLM-as-a-judge 在线评估器](/langsmith/online-evaluations-llm-as-judge)。
