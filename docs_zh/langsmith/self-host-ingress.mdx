默认情况下，LangSmith 会为 `langsmith-frontend` 配置一个 LoadBalancer 服务。根据你的云提供商，这可能会导致服务被分配一个公共 IP 地址。如果你希望使用自定义域名或更好地控制到 LangSmith 安装的流量路由，你可以配置 Ingress、Gateway API 或 Istio Gateway。

## 要求

* 一个现有的 Kubernetes 集群
* 在你的 Kubernetes 集群中安装以下之一：
  * Ingress Controller（用于标准 Ingress）
  * Gateway API CRD 和 Gateway 资源（用于 Gateway API）
  * Istio（用于 Istio Gateway）

## 参数

你可能需要向 LangSmith 安装提供某些参数来配置 Ingress。此外，我们需要将 `langsmith-frontend` 服务转换为 ClusterIP 服务。

* *Hostname（可选）*：你希望用于 LangSmith 安装的主机名。例如 `"langsmith.example.com"`。如果留空，ingress 将服务 LangSmith 安装的所有流量。

* *BasePath（可选）*：如果你希望在 URL basePath 下服务 LangSmith，可以在此指定。例如，添加 `"langsmith"` 将把应用程序服务在 `"example.hostname.com/langsmith"`。这将适用于 UI 路径和 API 端点。

* *IngressClassName（可选）*：你希望使用的 Ingress 类的名称。如果未设置，将使用默认 Ingress 类。

* *Annotations（可选）*：添加到 Ingress 的其他注释。某些提供商（如 AWS）可能使用注释来控制 TLS 终止等事项。

  例如，你可以使用以下注释使用 AWS ALB Ingress Controller 将 ACM 证书附加到 Ingress：

  ```yaml
  annotations:
    alb.ingress.kubernetes.io/certificate-arn: "<your-certificate-arn>"
  ```

* *Labels（可选）*：添加到 Ingress 的其他标签。

* *TLS（可选）*：如果你希望通过 HTTPS 服务 LangSmith，可以在此添加 TLS 配置（许多 Ingress 控制器可能有其他控制 TLS 的方式，因此通常不需要）。这应该是一个 TLS 配置数组。每个 TLS 配置应具有以下字段：

  * hosts：证书应对其有效的主机数组。例如 `["langsmith.example.com"]`

  * secretName：包含证书和私钥的 Kubernetes secret 的名称。此 secret 应具有以下键：

    * tls.crt：证书
    * tls.key：私钥

  * 有关更多信息，请参阅[创建 TLS secret](https://kubernetes.io/do/langsmith/observability-concepts/services-networking/ingress/#tls)。

## 配置

你可以将 LangSmith 实例配置为使用三种路由选项之一：标准 Ingress、Gateway API 或 Istio Gateway。选择最适合你基础设施的选项。

### 选项 1：标准 ingress

有了这些参数，你就可以配置 LangSmith 实例使用 Ingress。你可以通过修改 LangSmith Helm Chart 安装的 `config.yaml` 文件来执行此操作。

```yaml
config:
  hostname: "" # LangSmith 的主域名
  basePath: "" # 如果你想在 URL 基础路径下服务 langsmith（例如 /langsmith）
ingress:
  enabled: true
  hostname: "" # 已弃用：在 v0.12.0 之后使用 config.hostname
  subdomain: "" # 已弃用：在 v0.12.0 之后使用 config.hostname
  ingressClassName: "" # 如果未设置，将使用默认 ingress 类
  annotations: {} # 根据需要添加注释
  labels: {} # 根据需要添加标签
  tls: [] # 根据需要添加 TLS 配置
frontend:
  service:
    type: ClusterIP
```

配置后，你需要更新 LangSmith 安装。如果一切配置正确，你的 LangSmith 实例现在应该可以通过 Ingress 访问。你可以运行以下命令来检查 Ingress 的状态：

```bash
kubectl get ingress
```

你应该在输出中看到类似这样的内容：

```
NAME                         CLASS   HOSTS    ADDRESS          PORTS     AGE
langsmith-ingress            nginx   <host>   35.227.243.203   80, 443   95d
```

<Warning>
如果你没有自动 DNS 设置，你需要将 IP 地址手动添加到你的 DNS 提供商。
</Warning>

### 选项 2：Gateway API

<Note>
Gateway API 支持从 LangSmith v0.12.0 开始可用
</Note>

如果你的集群使用 [Kubernetes Gateway API](https://gateway-api.sigs.k8s.io/)，你可以配置 LangSmith 来配置 HTTPRoute 资源。这将为 LangSmith 创建一个 HTTPRoute，并为每个[代理部署](/langsmith/deployment)创建一个 HTTPRoute。

#### 参数

* *name（必填）*：要引用的 Gateway 资源的名称
* *namespace（必填）*：Gateway 资源所在的命名空间
* *hostname（可选）*：你希望用于 LangSmith 安装的主机名。例如 `"langsmith.example.com"`
* *basePath（可选）*：如果你希望在基础路径下服务 LangSmith，可以在此指定。例如 "example.com/langsmith"
* *sectionName（可选）*：Gateway 中要使用的特定监听器部分的名称
* *annotations（可选）*：添加到 HTTPRoute 资源的其他注释
* *labels（可选）*：添加到 HTTPRoute 资源的其他标签

#### 配置

```yaml
config:
  hostname: "" # LangSmith 的主域名
  basePath: "" # 如果你想在基础路径下服务 langsmith。例如 "example.com/langsmith"
gateway:
  enabled: true
  name: "my-gateway" # 你的 Gateway 资源名称
  namespace: "gateway-system" # 你的 Gateway 资源命名空间
  sectionName: "" # 可选：特定监听器部分名称
  annotations: {} # 根据需要添加注释
  labels: {} # 根据需要添加标签
frontend:
  service:
    type: ClusterIP
```

配置后，你可以检查 HTTPRoutes 的状态：

```bash
kubectl get httproute
```

### 选项 3：Istio Gateway

<Note>
Istio Gateway 支持从 LangSmith v0.12.0 开始可用
</Note>

如果你的集群使用 [Istio](https://istio.io/)，你可以配置 LangSmith 来配置 VirtualService 资源。这将为 LangSmith 创建一个 VirtualService，并为每个[代理部署](/langsmith/deployment)创建一个 VirtualService。

#### 参数

* *name（可选）*：要引用的 Istio Gateway 资源的名称。默认为 `"istio-gateway"`
* *namespace（可选）*：Istio Gateway 资源所在的命名空间。默认为 `"istio-system"`
* *hostname（可选）*：你希望用于 LangSmith 安装的主机名。例如 `"langsmith.example.com"`
* *basePath（可选）*：如果你希望在基础路径下服务 LangSmith，可以在此指定。例如 "example.com/langsmith"
* *annotations（可选）*：添加到 VirtualService 资源的其他注释
* *labels（可选）*：添加到 VirtualService 资源的其他标签

#### 配置

```yaml
config:
  hostname: "" # LangSmith 的主域名
  basePath: "" # 如果你想在单独的基础路径上服务 langsmith。例如 "example.com/langsmith"
istioGateway:
  enabled: true
  name: "istio-gateway" # 你的 Istio Gateway 资源名称
  namespace: "istio-system" # 你的 Istio Gateway 资源命名空间
  annotations: {} # 根据需要添加注释
  labels: {} # 根据需要添加标签
frontend:
  service:
    type: ClusterIP
```

配置后，你可以检查 VirtualServices 的状态：

```bash
kubectl get virtualservice
```
