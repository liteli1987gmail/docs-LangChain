LangSmith Self-Hosted 通过 OAuth2.0 和 OIDC 提供 SSO。这会将身份验证委托给你的身份提供商（IdP）来管理对 LangSmith 的访问。

我们的实现支持几乎任何符合 OIDC 的东西，只有少数例外。配置后，你会看到这样的登录屏幕：

![带有 OAuth SSO 的 LangSmith UI](/langsmith/images/langsmith-ui-sso.png)

## 概述

<Note>
你可以将 [基本 auth](/langsmith/self-host-basic-auth) 安装升级到此模式，但不能升级 [无 auth](/langsmith/authentication-methods#none) 安装。要升级，只需删除基本 auth 配置并添加下面显示的必需配置参数。然后用户只能通过 OAuth 登录。**为了在升级后保持访问权限，你必须能够通过 OAuth 访问使用以前通过基本 auth 登录的电子邮件地址登录。**
</Note>

<Warning>
LangSmith 目前不支持在自托管中将 SSO 移至基本 auth 模式。我们也不支持在带客户端密钥的 OAuth 模式和无客户端密钥的 OAuth 模式之间移动，反之亦然。最后，我们不支持同时使用基本 auth 和 OAuth。在启用 OAuth 时确保禁用基本 auth 配置。
</Warning>

## 使用客户端密钥（推荐）

默认情况下，LangSmith Self-Hosted 支持带 `Client Secret` 的 `Authorization Code` 流程。在此流程版本中，你的客户端密钥安全地存储在 LangSmith 中（而不是前端），并用于身份验证和建立 auth 会话。

### 前置条件

* 你必须是自托管的并且在 Enterprise 计划上。
* 你的 IdP 必须支持带 `Client Secret` 的 `Authorization Code` 流程。
* 你的 IdP 必须支持使用外部发现/颁发者 URL。我们将使用它来获取 IdP 的必要路由和密钥。
* 你必须向 LangSmith 提供 `OIDC`、`email` 和 `profile` 范围。我们使用这些来获取用户的必要用户信息和电子邮件。
<Note>

LangSmith SSO 仅通过 `https` 支持。
</Note>

### 配置

* 你需要在 IdP 中将回调 URL 设置为 `https://<host>/api/v1/oauth/custom-oidc/callback`，其中 host 是你为 LangSmith 实例配置域名或 IP。你的 IdP 会在用户身份验证后将用户重定向到此处。
* 要在注销时终止 IdP 会话（以便用户必须重新身份验证），请将你的 LangSmith URL（例如 `https://<host>`）注册为 **post-logout redirect URI**（有时称为"Sign-out redirect URI"），然后在你的环境中设置 `OAUTH_IDP_LOGOUT_ENABLED=true`（通过 Helm 中的 `commonEnv` 或 Docker Compose 中的 `.env` 文件）。
* 你需要在 `values.yaml` 文件中提供 `oauthClientId`、`oauthClientSecret`、`hostname` 和 `oauthIssuerUrl`。这是你将配置 LangSmith 实例的地方。
* 如果你**尚未**使用客户端密钥配置 Oauth，或者你只有个人 orgs，你必须提供电子邮件地址作为新配置 SSO org 的初始 org 管理员。如果你从基本 auth 升级，你现有的 org 将被重用。

<CodeGroup>

```yaml Helm
config:
  authType: mixed
  hostname: https://langsmith.example.com
  initialOrgAdminEmail: test@email.com # 如果需要的话设置这个
  oauth:
    enabled: true
    oauthClientId: <YOUR CLIENT ID>
    oauthClientSecret: <YOUR CLIENT SECRET>
    oauthIssuerUrl: <YOUR DISCOVERY URL>
    oauthScopes: "email,profile,openid"
```

```bash Docker
# 在你的 .env 文件中
AUTH_TYPE=mixed
INITIAL_ORG_ADMIN_EMAIL=test@email.com
LANGSMITH_URL=https://langsmith.example.com
OAUTH_CLIENT_ID=your-client-id
OAUTH_CLIENT_SECRET=your-client-secret
OAUTH_ISSUER_URL=https://your-issuer-url
OAUTH_SCOPES=email,profile,openid
```

</CodeGroup>

### 会话长度控制

<Note>
本节中的所有环境变量都适用于 `platform-backend` 服务，可以通过 Helm 中的 `platformBackend.deployment.extraEnv` 添加。
</Note>

* 默认情况下，会话长度由身份提供商返回的身份令牌的过期时间控制
* 大多数设置应使用刷新令牌来启用超过身份令牌过期的会话长度扩展，最长可达 `OAUTH_SESSION_MAX_SEC`，可能需要通过添加到 `oauthScopes`（Helm）或 `OAUTH_SCOPES`（Docker）来包含 `offline_access` 范围
* `OAUTH_SESSION_MAX_SEC`（默认 1 天）可以被覆盖为最多一周（`604800`）
* 对于不支持刷新令牌的身份提供商，设置 `OAUTH_OVERRIDE_TOKEN_EXPIRY="true"` 将把 `OAUTH_SESSION_MAX_SEC` 作为会话长度，忽略身份令牌过期

### 覆盖 sub 声明

在某些情况下，可能需要覆盖用作 IdP 中 `sub` 声明的声明。
例如，在 SCIM 中，解析的 `sub` 声明和 SCIM `externalId` 必须匹配才能使登录成功。
如果对 `sub` 声明的源属性和/或 SCIM `externalId` 有某些限制，请设置 `ISSUER_SUB_CLAIM_OVERRIDES` 环境变量来选择用作 `sub` 的 OIDC JWT 声明。

如果颁发者 URL **以** 此配置中的 URL 开头，则从指定的字段名中获取 `sub` 声明。
例如，使用以下配置，具有颁发者 `https://idp.yourdomain.com/application/uuid` 的令牌将使用 `customClaim` 值作为 `sub`：

```
ISSUER_SUB_CLAIM_OVERRIDES='{"https://idp.yourdomain.com": "customClaim"}'
```

如果未设置，此配置的默认值在使用 Azure Entra ID 作为身份提供商时使用 `oid` 声明：

```
ISSUER_SUB_CLAIM_OVERRIDES='{"https://login.microsoftonline.com/": "oid", "https://sts.windows.net/": "oid", "https://login.microsoftonline.us/": "oid", "https://login.partner.microsoftonline.cn/": "oid"}'
```

### SSO 组同步

<Note>
自托管上的 SSO 组同步需要 LangSmith chart 版本 **0.15.0-rc.3**（应用程序版本 **0.15.2rc1**）或更高版本。
</Note>

[SSO 组同步](/langsmith/user-management#sso-groups-sync-alternative) 让 LangSmith 从 OIDC 令牌上的组 membership 声明中分配组织和工作区角色，作为 [SCIM](/langsmith/user-management#set-up-scim-for-your-organization) 的更简单替代方案。在自托管上，你必须将 IdP 配置为在 OIDC ID 令牌中包含组，然后 LangSmith 才能读取它们。

**IdP 端配置（因提供商而异）：**

1. 配置你的 IdP 应用程序以在 OIDC ID 令牌中发出组 membership 声明。源属性和生成的声明名称因 IdP 而异。常见示例包括 `groups`、`roles` 或自定义声明名称。LangSmith 不规定源属性。
2. 根据你的 IdP，你可能需要向 `oauthScopes` 添加额外范围（通常 `groups`）以接收声明。请查看你的 IdP 的文档以了解所需的范围以及在令牌中包含组 membership 所需的任何其他配置。
3. 组名称必须遵循 [SCIM 命名约定](/langsmith/user-management#group-naming-convention)（例如 `LS:Organization Admin`、`LS:Organization User:prod:Editor`）。分隔符通过 [`scim_group_name_separator`](/langsmith/user-management#configure-custom-separator) 与 SCIM 共享。

**Helm 配置：**

如果你的 IdP 需要额外的 OIDC 范围来在令牌中包含组（通常为 `groups`），请将其添加到 `oauthScopes`：

<CodeGroup>

```yaml Helm
config:
  authType: mixed
  hostname: https://langsmith.example.com
  oauth:
    enabled: true
    oauthClientId: <YOUR CLIENT ID>
    oauthClientSecret: <YOUR CLIENT SECRET>
    oauthIssuerUrl: <YOUR DISCOVERY URL>
    oauthScopes: "email,profile,openid,groups"
```

```bash Docker
# 在你的 .env 文件中
AUTH_TYPE=mixed
LANGSMITH_URL=https://langsmith.example.com
OAUTH_CLIENT_ID=your-client-id
OAUTH_CLIENT_SECRET=your-client-secret
OAUTH_ISSUER_URL=https://your-issuer-url
OAUTH_SCOPES=email,profile,openid,groups
```

</CodeGroup>

确切的范围名称（`groups`、`roles` 等）取决于你的 IdP。请查看你的 IdP 的 OIDC 文档。

**LangSmith 端配置：**

每个提供商的 SSO 组同步设置存储在 SSO 提供商记录中，并通过 [LangSmith UI](https://smith.langchain.com) 或 [API](/langsmith/reference) 切换（不是通过 Helm values）。一旦你的 IdP 发出组声明，从 UI 中的 **设置** → **成员和角色** → **SSO 配置** → **SSO 组同步** 配置 SSO 组同步。或者，按照 [主要 SSO 组同步文档](/langsmith/user-management#sso-groups-sync-alternative) 中所述通过 API 进行配置。**组声明字段**中配置的声明名称必须与你的 IdP 发出的声明匹配。

### Google workspace IdP 设置

你可以使用 Google Workspace 作为使用 [OAuth2.0 和 OIDC](https://developers.google.com/identity/openid-connect/openid-connect) 的单点登录（SSO）提供商，无需 PKCE。

<Note>
你必须拥有组织的 Google Cloud Platform (GCP) 账户的管理员级访问权限才能创建新项目，或者有权为现有项目创建和配置 OAuth 2.0 凭据。我们建议创建一个新项目来管理访问权限，因为每个 GCP 项目只有一个 OAuth 同意屏幕。
</Note>

1. 创建一个新的 GCP 项目，请参阅 Google 文档主题[创建和管理项目](https://cloud.google.com/resource-manager/docs/creating-managing-projects)

2. 创建项目后，在 Google API Console 中打开[凭据](https://console.developers.google.com/apis/credentials)页面（确保左上角的项目正确）

3. 创建新凭据：`创建凭据 → OAuth 客户端 ID`

4. 选择 `Web 应用程序` 作为 `应用程序类型`并输入应用程序名称，例如 `LangSmith`

5. 在 `授权的 JavaScript 来源`中输入 LangSmith 实例的域名，例如 `https://langsmith.yourdomain.com`

6. 在 `授权的重定向 URI`中输入 LangSmith 实例的域名，后跟 `/api/v1/oauth/custom-oidc/callback`，例如 `https://langsmith.yourdomain.com/api/v1/oauth/custom-oidc/callback`

7. 点击 `创建`，然后下载 JSON 或复制并保存 `客户端 ID`（以 `.apps.googleusercontent.com` 结尾）和 `客户端密钥` 到安全的地方。**你可以稍后在此访问这些。**

8. 从左侧导航菜单中选择 `OAuth 同意屏幕`

   1. 选择应用程序类型为 `Internal`。**如果你选择 `Public`，任何拥有 Google 账户的人都可以登录。**
   2. 输入描述性的 `应用程序名称`。此名称在用户登录时显示在同意屏幕上。例如，使用 `LangSmith` 或 `<organization_name> SSO for LangSmith`。
   3. 验证 Google API 的范围仅列出 email、profile 和 openid 范围。单点登录只需要这些范围。如果你授予额外范围，会增加暴露敏感数据的风险。

9. （可选）控制组织内谁可以访问 LangSmith：[https://admin.google.com/ac/owl/list?tab=configuredApps](https://admin.google.com/ac/owl/list?tab=configuredApps)。有关其他详细信息，请参阅 [Google 的文档](https://support.google.com/a/answer/7281227?hl=en&fl=1&sjid=9554153972856467090-NA)。

10. 配置 LangSmith 使用此 OAuth 应用程序。例如，以下是用于 Kubernetes 配置的 `config` 值：

    1. `oauthClientId`：`客户端 ID`（以 `.apps.googleusercontent.com` 结尾）
    2. `oauthClientSecret`：`客户端密钥`
    3. `hostname`：LangSmith 实例的域名，例如 `https://langsmith.yourdomain.com`（无尾部斜杠）
    4. `oauthIssuerUrl`：`https://accounts.google.com`
    5. `oauth.enabled`：`true`
    6. `authType`：`mixed`

## 无客户端密钥 (PKCE)（已弃用）

如果可能，我们建议使用 `Client Secret` 运行（之前我们不支持这个）。但是，如果你的 IdP 不支持此功能，你可以使用 `Authorization Code with PKCE` 流程。

此流程*不需要* `Client Secret`。有关替代工作流程，请参阅[使用客户端密钥](#with-client-secret-recommended)。

### 要求

使用 LangSmith 的 OAuth SSO 有几个要求：

* 你的 IdP 必须支持 `Authorization Code with PKCE` [流程](https://www.oauth.com/oauth2-servers/pkce)（例如，Google 不支持此流程，但请参阅上面的[替代配置](#with-client-secret-recommended)，这是 Google 支持的）。这通常在你的 OAuth 提供商中显示为配置"单页应用程序 (SPA)"
* 你的 IdP 必须支持使用外部发现/颁发者 URL。我们将使用它来获取 IdP 的必要路由和密钥。
* 你必须向 LangSmith 提供 `OIDC`、`email` 和 `profile` 范围。我们使用这些来获取用户的必要用户信息和电子邮件。
* 你需要在 IdP 中将回调 URL 设置为 `http://<host>/oauth-callback`，其中 host 是你为 LangSmith 实例配置域名或 IP。你的 IdP 会在用户身份验证后将用户重定向到此处。
* 你需要在 `values.yaml` 文件中提供 `oauthClientId` 和 `oauthIssuerUrl`。这，是你将配置 LangSmith 实例的地方。

<CodeGroup>

```yaml Helm
config:
  oauth:
    enabled: true
    oauthClientId: <YOUR CLIENT ID>
    oauthIssuerUrl: <YOUR DISCOVERY URL>
```

```bash Docker
# 在你的 .env 文件中
AUTH_TYPE=oauth
OAUTH_CLIENT_ID=your-client-id
OAUTH_ISSUER_URL=https://your-issuer-url
```

</CodeGroup>
