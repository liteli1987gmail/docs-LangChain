</Note>

## 概述

在大型语言模型应用程序中实现有效的可观测性需要主动检测故障、性能下降和回归。LangSmith 的警报功能有助于识别关键问题，例如：

- 模型提供商的 API 速率限制违规
- 应用程序延迟增加
- 影响反映最终用户体验的反馈分数的应用程序更改
- 大型语言模型使用带来的意外成本峰值

LangSmith 中的警报是项目作用域的，需要为每个受监控的项目单独配置。

## 配置警报

### 步骤 1：导航到创建警报

在 [UI](https://smith.langchain.com) 中，导航到您要为其配置警报的追踪项目。点击页面右上角的**警报**图标，查看该项目的现有警报并设置新警报。

### 步骤 2：选择指标类型

LangSmith 在以下指标上提供基于阈值的警报：

| 指标类型 | 描述 | 用例 |
| ------------------ | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **运行计数** | 跟踪一段时间窗口内的运行总数。 | 监控管道是否以预期容量产生运行，并在意外下降时发出警报。 |
| **成本** | 跟踪一段时间窗口内运行的总成本 | 监控大型语言模型支出，以便在成本超过预期阈值时发出警报。需要配置[成本跟踪](/langsmith/cost-tracking)。 |
| **错误** | 跟踪具有错误状态的运行。针对错误总数或错误百分比（错误运行占所有运行的比率）发出警报。 | 监控应用程序中的故障，或在错误率超过可接受阈值时发出警报。 |
| **反馈分数** | 测量平均反馈分数 | 跟踪[最终用户反馈](/langsmith/attach-user-feedback)或[在线评估结果](/langsmith/online-evaluations-llm-as-judge)以在回归时发出警报。 |
| **延迟** | 测量平均运行执行时间 | 跟踪应用程序的延迟以在峰值和性能瓶颈时发出警报。 |

此外，对于**错误**和**延迟**，您可以定义过滤器来缩小触发警报的运行范围。例如，您可以为所有标记为 `support_agent` 的 `llm` 运行创建错误警报过滤器，这些运行遇到 `RateLimitExceeded` 错误。

### 步骤 2：定义警报条件

警报条件由几个组件组成：

- **聚合方法**：平均值、百分比或计数
- **比较运算符**：`>=`、`<=` 或超过阈值
- **阈值**：触发警报的数值
- **聚合窗口**：指标计算的时间段（目前选择 5 或 15 分钟）
- **反馈键**（仅反馈分数警报）：要监控的特定反馈指标

### 步骤 3：配置通知渠道

<Tabs>
  <Tab title="PagerDuty">
    使用 PagerDuty 的 [Events API v2](https://developer.pagerduty.com/docs/events-api-v2-overview) 将 PagerDuty 配置为通知渠道。此集成允许关键的大型语言模型应用程序问题触发 PagerDuty 事件，通过您现有的事件管理工作流程实现快速响应。

    **前置条件**

    - 具有管理员访问权限的活跃 PagerDuty 账户
    - PagerDuty 中适当的服务级权限

    如果使用 LangSmith 的自定义部署，请确保没有防火墙设置阻止来自 LangSmith 服务的出口流量。

    #### 1. 在 PagerDuty 中创建服务

    1. 登录您的 PagerDuty 账户
    2. 导航到 **Services → Service Directory**
    3. 点击 **+ New Service**
    4. 填写以下字段：
       - **名称**：提供描述性名称（例如 "LangSmith Monitoring"）
       - **描述**：添加有关受监控应用程序的详细信息
       - **升级策略**：选择适当的团队升级策略
       - **集成类型**：选择 "Events API V2"
    5. 点击 **Add Service** 创建服务

    #### 2. 获取集成密钥

    创建服务后，检索集成密钥：

    1. 从 **Service Directory**，找到并点击您新创建的服务
    2. 选择 **Integrations** 选项卡
    3. 找到 "Events API V2" 集成
    4. 复制 **Integration Key**（32 个字符的字母数字字符串）

    ![PagerDuty 集成密钥位置](/langsmith/images/pager-duty.png)

    #### 3. 使用 PagerDuty 配置 LangSmith 警报

    <Info>
    要在同一警报触发后一小时内再次接收同一警报，您必须在 PagerDuty 中解决由该警报创建的活动事件。
    </Info>

    ![PagerDuty 设置](/langsmith/images/pagerduty-setup.png)

    1. 在 LangSmith 中的警报设置的通知部分，选择 **PagerDuty**
    2. 点击密钥图标将 Integration Key 保存为工作区密钥，或选择现有的工作区密钥。作为最佳实践，我们建议将 Integration Key 保存为工作区密钥，而不是直接添加。这将允许您在工作区的多个警报中重复使用同一个密钥。
    3. 配置其他通知选项：
       - **严重性**：映射到 PagerDuty 事件优先级
    4. 通过点击 **Send Test Alert** 发送测试警报
    5. 验证事件是否由 PagerDuty 触发并包含相关的 LangSmith 警报信息

    #### 故障排除

    如果事件未在 PagerDuty 中创建：

    - 验证 Integration Key 在 LangSmith 中输入正确
    - 确保 PagerDuty 服务处于活动状态且不在维护模式
    - 检查您的 PagerDuty 账户是否启用了 Events API v2
    - 如果 PagerDuty 中缺少警报触发器，请检查预期的触发是否发生在同一警报规则的先前触发后一小时内，以及先前警报创建的事件是否仍然开放。
    - 如果您的 LangSmith 实例在防火墙后面，请检查网络连接

    #### 其他资源

    - [PagerDuty Events API v2 文档](https://developer.pagerduty.com/docs/events-api-v2/overview/)
    - [PagerDuty 集成指南](https://support.pagerduty.com/docs/services-and-integrations)
  </Tab>
  <Tab title="Dynatrace">
    使用 Dynatrace 的 [Events API v2](https://docs.dynatrace.com/docs/dynatrace-api/environment-api/events-v2/post-event) 将 Dynatrace 配置为通知渠道。此集成将 LangSmith 警报事件发送到您的 Dynatrace 环境，实现与您更广泛的基础设施监控的关联。

    **前置条件**

    - 活跃的 Dynatrace 环境（SaaS 或托管）。
    - 具有 `events.ingest` 范围的 Dynatrace API 访问令牌。

    如果您使用的是 LangSmith 的自定义[部署](/langsmith/self-hosted)，请确保没有防火墙设置阻止来自 LangSmith 服务的出口流量。

    #### 1. 在 Dynatrace 中创建 API 令牌

    1. 登录您的 Dynatrace 环境。
    1. 导航到 **Access Tokens**。
    1. 点击 **Generate new token**。
    1. 提供描述性名称（例如 "LangSmith Alerts"）。
    1. 在 **Scopes** 下，搜索并启用 `events.ingest`（摄入事件）。
    1. 点击 **Generate token**。
    1. 复制生成的令牌并安全存储。该令牌仅显示一次。

    #### 2. 获取您的 Dynatrace 环境 URL

    您的 Dynatrace 环境 URL 遵循此格式：

    ```
    https://{your-environment-id}.live.dynatrace.com
    ```

    登录 Dynatrace 时，您可以在浏览器 URL 栏中找到您的环境 ID。

    #### 3. 使用 Dynatrace 配置 LangSmith 警报

    1. 在 LangSmith 中的警报设置的 **Notifications Settings** 中，选择 **Dynatrace**。
    1. 输入您的 Dynatrace 环境 URL。
    1. 点击密钥图标将 API 令牌保存为工作区密钥，或选择现有的工作区密钥。作为最佳实践，将 API 令牌保存为工作区密钥而不是直接添加。这允许您在工作区的多个警报中重复使用同一个令牌。
    1. 配置其他通知选项：
       - **事件类型**：选择 Dynatrace 事件类型（例如 `CUSTOM_ALERT`、`ERROR_EVENT`）
    1. 通过点击 **Send Test Notification** 发送测试通知。
    1. 验证事件是否出现在您的 Dynatrace 环境中。

    #### 故障排除

    如果事件未出现在 Dynatrace 中：

    - 验证 API 令牌具有 `events.ingest` 范围且未过期。
    - 确保环境 URL 正确且包含您的环境 ID。
    - 确认 `Authorization` 头格式使用 `Api-Token`（不是 `Bearer`）。
    - 检查您的 Dynatrace 环境是否处于活动状态且可访问。
    - 如果您的 LangSmith 实例在防火墙后面，请检查网络连接。

    #### 其他资源

    - [Dynatrace Events API v2 文档](https://docs.dynatrace.com/docs/dynatrace-api/environment-api/events-v2/post-event)
    - [Dynatrace 访问令牌](https://docs.dynatrace.com/docs/manage/access-control/access-tokens)
  </Tab>
  <Tab title="Webhook">
    Webhook 通过在触发警报条件时发送 HTTP POST 请求来启用与自定义服务和第三方平台的集成。使用 webhook 将警报数据转发到工单系统、聊天应用程序或自定义监控解决方案。

    **前置条件**

    - 可接收 HTTP POST 请求的端点
    - 接收服务的适当身份验证凭据（如果需要）

    #### 1. 准备您的接收端点

    在 LangSmith 中配置 webhook 之前，确保您的接收端点：

    - 接受 HTTP POST 请求
    - 可以处理 JSON 有效载荷
    - 可从外部服务访问
    - 有适当的身份验证机制（如果需要）

    如果使用 LangSmith 的自定义部署，请确保没有防火墙设置阻止来自 LangSmith 服务的出口流量。

    #### 2. 配置 webhook 参数

    ![Webhook 设置](/langsmith/images/webhook-setup.png)

    在警报的通知部分，使用以下参数完成 webhook 配置：

    **必填字段**

    - **URL**：您接收端点的完整 URL
      - 示例：`https://api.example.com/incident-webhook`

    **可选字段**

    - **Headers**：与 webhook 请求一起发送的 JSON 键值对
      - 常见 headers 包括：
        - `Authorization`：用于身份验证令牌
        - `Content-Type`：通常设置为 `application/json`（默认）
        - `X-Source`：识别来源为 LangSmith
      - 如果没有 headers，使用 `{}`

    - **请求正文模板**：自定义发送到您端点的 JSON 有效载荷
      - 默认：LangSmith 发送定义的有效载荷和以下附加键值对：
        - `project_name`：触发警报的项目名称
        - `alert_rule_id`：用于识别 LangSmith 警报的 UUID。这可用作 webhook 服务中的去重密钥。
        - `alert_rule_name`：警报规则的名称。
        - `alert_rule_type`：警报类型（截至 04/01/2025，所有警报类型均为 `threshold`）。
        - `alert_rule_attribute`：与警报规则关联的属性 - `error_count`、`feedback_score`、`latency` 或 `cost`。
        - `triggered_metric_value`：触发阈值时的指标值。
        - `triggered_threshold`：触发警报的阈值。
        - `timestamp`：触发警报的时间戳。

    #### 3. 测试 webhook

    点击 **Send Test Alert** 发送 webhook 通知以确保通知按预期工作。

    #### 故障排除

    如果 webhook 通知未送达：

    - 验证 webhook URL 正确且可访问
    - 确保任何身份验证 headers 格式正确
    - 检查您的接收端点是否接受 POST 请求
    - 检查您端点的日志以获取已接收但被拒绝的请求
    - 验证您的自定义有效载荷模板是有效的 JSON 格式

    #### 安全注意事项

    - 为 webhook 端点使用 HTTPS
    - 为 webhook 端点实施身份验证
    - 考虑在 headers 中添加共享密钥以验证 webhook 来源
    - 在处理之前验证传入的 webhook 请求

    #### 发送警报到 Slack

    <Accordion title="通过 webhook 配置 Slack 通知">
      以下是配置 LangSmith 警报以使用 [`chat.postMessage`](https://api.slack.com/methods/chat.postMessage) API 向 Slack 频道发送通知的示例。

      **前置条件**

      - 访问 Slack 工作区
      - 用于设置警报的 LangSmith 项目
      - 创建 Slack 应用程序的权限

      **步骤 1：创建 Slack 应用程序**

      1. 访问 [Slack API 应用程序页面](https://api.slack.com/apps)
      2. 点击 **Create New App**
      3. 选择 **From scratch**
      4. 提供 **App Name**（例如 "LangSmith Alerts"）
      5. 选择您要安装应用程序的工作区
      6. 点击 **Create App**

      **步骤 2：配置 bot 权限**

      1. 在 Slack 应用程序配置的左侧边栏中，点击 **OAuth & Permissions**
      2. 向下滚动到 **Scopes** 下的 **Bot Token Scopes**，点击 **Add an OAuth Scope**
      3. 添加以下范围：
         - `chat:write`（作为应用程序发送消息）
         - `chat:write.public`（向应用程序不在的频道发送消息）
         - `channels:read`（查看基本频道信息）

      **步骤 3：将应用程序安装到您的工作区**

      1. 向上滚动到 **OAuth & Permissions** 页面的顶部
      2. 点击 **Install to Workspace**
      3. 审查权限并点击 **Allow**
      4. 复制出现的 **Bot User OAuth Token**（以 `xoxb-` 开头）

      **步骤 4：将 bot 添加到 Slack 频道**

      将 bot 添加到您要接收警报的特定频道。您可以通过在消息字段中提及其名称来将 bot 添加到 Slack 频道（例如 `@botname`）。

      您还需要频道 ID 来在 LangSmith 中配置 webhook 警报。您可以通过打开频道详情 > 关于来找到频道 ID。

      **步骤 5：在 LangSmith 中配置 webhook 警报**

      1. 在 LangSmith 中，导航到您的项目
      2. 选择 **Alerts → Create Alert**
      3. 定义您的警报指标和条件
      4. 在通知部分，选择 **Webhook**
      5. 使用以下设置配置 webhook：

      **Webhook URL**

      ```json
      https://slack.com/api/chat.postMessage
      ```

      **Headers**
      <Note>将 `xoxb-your-token-here` 替换为您的 Bot 的 User OAuth Token</Note>

      ```json
      {
        "Content-Type": "application/json",
        "Authorization": "Bearer xoxb-your-token-here"
      }
      ```

      **请求正文模板**
      <Note>需要填写从步骤 4 中找到的 `{channel_id}`。<br /><br />其余字段：`alert_name`、`project_name` 和 `project_url` 可选择地向警报消息添加额外上下文。您可以在浏览器的 URL 栏中找到您的 `project_url`。复制到但不包括任何查询参数的部分。</Note>

      ```json
      {
        "channel": "{channel_id}",
        "text": "{alert_name} triggered for {project_name}",
        "blocks": [
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "🚨{alert_name} has been triggered"
            }
          },
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "Please check the following link for more information:"
            }
          },
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "<{project-url}|View in LangSmith>"
            }
          }
        ]
      }
      ```

      6. 点击 **Save** 激活 webhook 配置

      **步骤 6：测试集成**

      1. 在 LangSmith 警报配置中，点击 **Test Alert**
      2. 检查您指定的 Slack 频道是否有测试通知
      3. 验证消息包含预期的警报信息

      **（可选）步骤 7：在请求正文中链接到警报预览**

      创建警报后，您可以选择在 webhook 的请求正文中链接到其预览。

      ![警报预览窗格](/langsmith/images/alert-preview-pane.png)

      要配置此功能：

      1. 保存您的警报
      2. 在警报表中找到您保存的警报并点击它
      3. 复制显示的 URL
      4. 点击 "Edit Alert"
      5. 用复制的警报预览 URL 替换现有的项目 URL
    </Accordion>

## 最佳实践

- 根据应用程序关键性调整灵敏度
- 从更广泛的阈值开始，根据观察到的模式进行细化
- 确保警报路由到达适当的值班人员
