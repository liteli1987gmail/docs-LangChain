在 [Google Cloud Platform (GCP)](https://cloud.google.com/) 上运行 LangSmith 时，您可以设置[完全自托管](/langsmith/self-hosted)或[混合](/langsmith/hybrid)模式。完全自托管模式部署完整的 LangSmith 平台，包含可观测性功能以及创建代理部署的选项。混合模式仅包含在您的云中运行数据平面代理的基础设施，而我们的 SaaS 提供控制平面和可观测性功能。

本页提供：

- 部署到 GKE、配置托管服务和设置身份验证的[初始设置步骤](#initial-setup)。
- [GCP 特定架构模式](#reference-architecture)和参考图表。
- [服务建议](#compute-options)和最佳实践。
- [Google Cloud Well-Architected 最佳实践](#google-cloud-well-architected-best-practices)，用于运营卓越、安全性和可靠性。

<Note>
LangChain 提供专门用于 GCP 的 Terraform 模块，以帮助为 LangSmith 配置基础设施。这些模块可以快速设置 GKE 集群、Cloud SQL、Memorystore Redis、Cloud Storage 和网络资源。

查看 [GCP Terraform 模块](https://github.com/langchain-ai/terraform/tree/main/modules/gcp)获取文档和示例。
</Note>

## 初始设置

<Steps>
  <Step title="部署到 Kubernetes">
    按照 [Kubernetes 安装指南](/langsmith/kubernetes)进行操作。LangSmith 在 Google Kubernetes Engine (GKE) 上进行了测试。

    **GKE 特定注意事项：**
    - LangSmith 适用于标准 GKE 集群
    - 使用 GCE 持久磁盘存储类
  </Step>

  <Step title="配置外部服务">
    对于生产部署，连接到 GCP 托管服务：

    <CardGroup cols={2}>
      <Card title="Google Cloud Storage" icon="database" href="/langsmith/self-host-blob-storage#google-cloud-storage">
        在 GCS 中存储追踪数据
      </Card>
      <Card title="Cloud SQL" icon="database" href="/langsmith/self-host-external-postgres#google-cloud-sql">
        PostgreSQL 数据库
      </Card>
      <Card title="Memorystore" icon="cpu" href="/langsmith/self-host-external-redis#google-cloud-memorystore">
        用于缓存的 Redis 或 Valkey
      </Card>
      <Card title="ClickHouse Cloud" icon="chart-line" href="/langsmith/self-host-external-clickhouse">
        分析数据库
      </Card>
    </CardGroup>
  </Step>

  <Step title="设置身份验证">
    使用 [Workload Identity](https://cloud.google.com/kubernetes-engine/docs/how-to/workload-identity) 对 LangSmith pods 进行身份验证以访问 GCP 服务。

    **关键页面：**
    - [GCS HMAC 密钥身份验证](/langsmith/self-host-blob-storage#google-cloud-storage)
    - [Cloud SQL IAM 身份验证](/langsmith/self-host-external-postgres#iam-authentication)
    - [Memorystore IAM 身份验证](/langsmith/self-host-external-redis#iam-authentication)
  </Step>
</Steps>

完成这些初始设置步骤后，您可以查看下面完整的 GCP 架构和最佳实践。

## 参考架构

我们建议利用 GCP 的托管服务来提供可扩展、安全和有弹性的平台。以下架构适用于自托管和混合部署，并与 [Google Cloud Well-Architected Framework](https://docs.cloud.google.com/architecture/framework) 保持一致：

![显示 GCP 与 LangSmith 服务关系的架构图](/langsmith/images/gcp-architecture-self-hosted.png)

- <Icon icon="globe" /> **入口和网络**：请求通过您的 [VPC](https://cloud.google.com/vpc) 中的 [Cloud Load Balancing](https://cloud.google.com/load-balancing) 进入，使用 [Cloud Armor](https://cloud.google.com/armor) 和基于 [IAM](https://cloud.google.com/iam/) 的身份验证进行保护。
- <Icon icon="cube" /> **前端和后端服务：** 容器在 [Google Kubernetes Engine (GKE)](https://cloud.google.com/kubernetes-engine) 上运行，在负载均衡器后面编排。根据需要将请求路由到集群内的其他服务。
- <Icon icon="database" /> **存储和数据库：**
  - [Cloud SQL for PostgreSQL](https://cloud.google.com/sql/docs/postgres)：元数据、项目、用户以及已部署代理的短期和长期记忆。LangSmith 支持 PostgreSQL 版本 14 或更高。
  - [Memorystore](https://cloud.google.com/memorystore)（[Redis](https://cloud.google.com/memorystore/docs/redis) 或 [Valkey](https://cloud.google.com/memorystore/docs/valkey)）：缓存和作业队列。Memorystore 可以是单实例或集群模式。LangSmith 需要 Redis OSS 版本 5 或更高，或 Valkey 8。
  - ClickHouse + [Persistent Disks](https://cloud.google.com/compute/docs/disks)：分析和追踪存储。
    - 我们建议使用[外部托管的 ClickHouse 解决方案](/langsmith/self-host-external-clickhouse)，除非安全或合规原因阻止您这样做。
    - 混合部署不需要 ClickHouse。
  - [Cloud Storage](https://cloud.google.com/storage)：用于追踪制品和遥测的对象存储。

- <Icon icon="sparkles" /> **LLM 集成：** 可选择将请求代理到 [Vertex AI](https://cloud.google.com/vertex-ai) 用于 LLM 推理。
- <Icon icon="chart-line" /> **监控和可观测性：** 与 [Cloud Monitoring](https://cloud.google.com/monitoring) 和 [Cloud Logging](https://cloud.google.com/logging) 集成


## 计算选项

根据您的需求，LangSmith 支持多种计算选项：

| 计算选项 | 描述 | 适用于 |
|-----------------|-------------|--------------|

## Google Cloud Well-Architected 最佳实践

本参考旨在与 Google Cloud Well-Architected Framework 的六个支柱保持一致：

### 运营卓越

- 使用 IaC（[Terraform](https://www.terraform.io/) / [Deployment Manager](https://cloud.google.com/deployment-manager)）自动化部署。
- 使用 [Secret Manager](https://cloud.google.com/secret-manager) 进行配置和敏感数据管理。
- 将您的 LangSmith 实例配置为[导出遥测数据](/langsmith/export-backend)，并通过 [Cloud Logging](https://cloud.google.com/logging) 持续监控。
- 管理 [LangSmith 部署](/langsmith/deployment) 的首选方法是创建 CI 流程来构建 [Agent Server](/langsmith/agent-server) 镜像并将其推送到 [Artifact Registry](https://cloud.google.com/artifact-registry)。在合并 PR 之前，为拉取请求创建测试部署，然后再将新修订版部署到暂存或生产环境。

### 安全性

- 使用具有最小权限策略的 [IAM](https://cloud.google.com/iam/) 角色和 [Workload Identity](https://cloud.google.com/kubernetes-engine/docs/how-to/workload-identity) 进行安全的 pod 到 GCP 服务身份验证。
- 启用静态加密（[Cloud SQL](https://docs.cloud.google.com/sql/docs/postgres/cmek)、[Cloud Storage](https://cloud.google.com/storage/docs/encryption)、持久磁盘）和传输中加密（TLS 1.2+）。
- 与 [Secret Manager](https://cloud.google.com/secret-manager) 集成以获取凭据。
- 使用 [Identity Platform](https://cloud.google.com/identity-platform) 或 [Workload Identity Federation](https://cloud.google.com/iam/docs/workload-identity-federation) 作为 IDP，结合 LangSmith 内置的身份验证和授权功能来保护对代理及其工具的访问。

### 可靠性

- 跨区域复制 LangSmith [数据平面](/langsmith/data-plane)：为 LangSmith 部署在不同的区域中的 Kubernetes 集群部署相同的数据平面。跨多个区域部署 [Cloud SQL](https://cloud.google.com/sql/docs/postgres/high-availability) 和 [GKE](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/configuration-overview) 服务。
- 使用 [Horizontal Pod Autoscaler](https://cloud.google.com/kubernetes-engine/docs/concepts/horizontalpodautoscaler) 和 [Cluster Autoscaler](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler) 实施后端工作程序的[自动扩展](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler)。
- 使用 [Cloud DNS](https://cloud.google.com/dns) 健康检查和故障转移策略。

### 性能优化

- 利用具有[机器类型选择](https://cloud.google.com/compute/docs/machine-types)的优化计算的 [Compute Engine](https://cloud.google.com/compute) 实例。
- 对不频繁访问的追踪数据使用 [Cloud Storage 生命周期策略](https://cloud.google.com/storage/docs/lifecycle)，转移到 [Nearline](https://cloud.google.com/storage/docs/storage-classes#nearline) 或 [Coldline](https://cloud.google.com/storage/docs/storage-classes#coldline) 存储类。

### 成本优化

- 使用[committed use discounts](https://cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts) 和 [Sustained Use Discounts](https://cloud.google.com/compute/docs/sustained-use-discounts) 正确调整 [GKE](https://cloud.google.com/kubernetes-engine) 集群的大小。
- 使用 [Cloud Billing](https://cloud.google.com/billing/docs) 仪表板和 [Cost Management](https://cloud.google.com/cost-management) 工具监控成本 KPI。

### 可持续性

- 使用按需计算和[自动扩展](https://cloud.google.com/kubernetes-engine/docs/concepts/cluster-autoscaler)最小化空闲工作负载。
- 使用 [Cloud Storage 生命周期策略](https://cloud.google.com/storage/docs/lifecycle) 将遥测存储在低延迟、低成本层中。
- 使用[计划操作](https://cloud.google.com/compute/docs/instances/schedule-instance-start-stop)为非生产环境启用自动关闭。

## 安全性和合规性

LangSmith 可以配置为：

- 仅 [Private Service Connect](https://cloud.google.com/vpc/docs/private-service-connect) 访问（除出口计费外不暴露在公共互联网上）。
- 使用 [Cloud KMS](https://cloud.google.com/kms) 基于加密密钥用于 Cloud Storage、Cloud SQL 和持久磁盘。
- 审计日志到 [Cloud Logging](https://cloud.google.com/logging) 和 [Cloud Audit Logs](https://cloud.google.com/logging/docs/audit)。

客户可以根据需要部署在 [Assured Workloads](https://cloud.google.com/assured-workloads) 区域以符合 ISO、HIPAA 或其他监管要求。

## 监控和评估

使用 LangSmith：

- 从运行在 [Vertex AI](https://cloud.google.com/vertex-ai) 上的 LLM 应用捕获追踪。
- 通过 [LangSmith 数据集](/langsmith/manage-datasets)评估模型输出。
- 跟踪延迟、令牌使用情况和成功率。

与以下服务集成：

- [Cloud Monitoring](https://cloud.google.com/monitoring) 仪表板。
- [OpenTelemetry](https://opentelemetry.io/) 和 [Prometheus](https://prometheus.io/) 导出器。
