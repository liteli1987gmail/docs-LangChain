<Note>
本节与使用 LangSmith JS SDK 版本 0.2.0 及更高版本的用户相关。如果你在无服务器环境中使用 LangChain.js 或 LangGraph.js 进行追踪，请参阅[本指南](https://js.langchain.com/docs/how_to/callbacks_serverless)。
</Note>

追踪 JavaScript 函数时，LangSmith 默认会在后台追踪运行以避免增加延迟。在执行上下文可能突然终止的无服务器环境中，重要的是确保所有追踪数据在函数完成之前正确刷新。

为确保发生这种情况，你可以：

* 将名为 `LANGSMITH_TRACING_BACKGROUND` 的环境变量设置为 `"false"`。这将导致你追踪的函数在返回之前等待追踪完成。
  * 请注意，这与 LangChain.js 中的[环境变量](https://js.langchain.com/docs/how_to/callbacks_serverless)命名不同，因为 LangSmith 可以在不使用 LangChain 的情况下使用。
* 将自定义客户端传递到你追踪的运行中，并 `await` `client.awaitPendingTraceBatches();` 方法。

以下是 alongside [`traceable`](/langsmith/annotate-code) 方法使用 `awaitPendingTraceBatches` 的示例：

```typescript
import { Client } from "langsmith";
import { traceable } from "langsmith/traceable";
const langsmithClient = new Client({});
const tracedFn = traceable(
  async () => {
    return "Some return value";
  },
  {
    client: langsmithClient,
  }
);
const res = await tracedFn();
await langsmithClient.awaitPendingTraceBatches();
```

## 高并发时的速率限制[ ](#rate-limits-at-high-concurrency "到高并发时速率限制的直接链接")

默认情况下，LangSmith 客户端会在你追踪的运行执行时批量处理操作，每隔几毫秒发送一个新批次。

这在大多数情况下效果很好，但如果你追踪的函数长时间运行并且你有非常高的并发，你也可能遇到与整体请求计数相关的速率限制。

如果你看到与此相关的速率限制错误，可以尝试在客户端中设置 `manualFlushMode: true`，如下所示：

```typescript
import { Client } from "langsmith";
const langsmithClient = new Client({  manualFlushMode: true,});
const myTracedFunc = traceable(
  async () => {
    // 你的逻辑在这里...
  },
  { client: langsmithClient }
);
```

然后在无服务器函数关闭前手动调用 `client.flush()`，如下所示：

```typescript
try {
  await myTracedFunc();
} finally {
  await langsmithClient.flush();
}
```

请注意，在调用 `.flush()` 之前，运行不会出现在 LangSmith UI 中。
