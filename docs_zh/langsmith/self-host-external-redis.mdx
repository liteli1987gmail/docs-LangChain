LangSmith 使用 Redis 来支持我们的队列/缓存操作。默认情况下，LangSmith Self-Hosted 将使用内部 Redis 实例。但是，你可以将 LangSmith 配置为使用外部 Redis 实例。通过配置外部 Redis 实例，你可以更轻松地管理备份、扩展和 Redis 实例的其他运营任务。

[Valkey](https://valkey.io/) 也被正式支持作为 Redis 的直接替代品。在本指南中任何提及 Redis 的地方，你都可以使用兼容的 Valkey 实例。请参阅[要求](#requirements)了解支持的版本。

<Warning>
每个 LangSmith 安装必须使用自己的专用 Redis 实例。Redis 不能在独立的 LangSmith 安装之间共享（例如，在迁移期间在现有集群和新集群之间）。跨安装共享会导致部署任务被路由到错误的集群。
</Warning>

<Tip>
**如果你使用的是托管 Redis 服务**，我们推荐：
- [Amazon ElastiCache](https://aws.amazon.com/elasticache/redis/) (AWS)
- [Google Cloud Memorystore](https://cloud.google.com/memorystore) (GCP)
- [Azure Cache for Redis](https://azure.microsoft.com/en-us/services/cache/) (Azure)

有关特定于云的 IAM/工作负载身份验证，请参阅 [IAM 身份验证部分](#iam-authentication)。
</Tip>

## 要求

* 一个已配置的 Redis 或 [Valkey](https://valkey.io/) 实例，你的 LangSmith 实例可以访问该实例的网络。我们建议使用托管服务，例如：

  * [Amazon ElastiCache](https://aws.amazon.com/elasticache/redis/) (Redis 或 Valkey)
  * [Google Cloud Memorystore](https://cloud.google.com/memorystore) (Redis 或 Valkey)
  * [Azure Cache for Redis](https://azure.microsoft.com/en-us/services/cache/)

* **支持的版本：** Redis >= 5，或 Valkey 8。Valkey 在本指南中被视为 Redis 的直接替代品。
* 我们同时支持独立模式和 Redis Cluster（包括 Valkey Cluster）。请参阅相应部分了解部署说明。
* 我们支持无身份验证、密码和 [IAM/工作负载身份](#iam-authentication) 身份验证。
* 默认情况下，我们建议使用至少 2 个 vCPU 和 8GB 内存的实例。但是，实际要求取决于你的追踪工作负载。我们建议监控你的 Redis 实例并根据需要扩展。

## 独立 Redis

### 连接字符串

你需要为 Redis 实例组装连接字符串。此连接字符串应包含以下信息：

* Host
* Database
* Port
* URL params

这将采用以下形式：

```
"redis://host:port/db?<url_params>"
```

例如，连接字符串可能如下所示：

```
"redis://langsmith-redis:6379/0"
```

注意：如果你的独立 Redis 需要身份验证或 TLS，请将这些直接包含在连接 URL 中：

- 当你的 Redis 服务器启用 TLS 时使用 `rediss://`。
- 在连接字符串中提供密码。

例如：

```text
rediss://langsmith-redis:6380/0?password=foo
```

对于 IAM 身份验证，使用标识作为用户名（无密码）：

```text
rediss://<iam-identity>@host:6380
```

### 配置

有了连接字符串，你就可以将 LangSmith 实例配置为使用外部 Redis 实例。你可以通过修改 LangSmith Helm Chart 安装的 `values` 文件或 Docker 安装的 `.env` 文件来执行此操作。

<CodeGroup>

```yaml Helm
redis:
  external:
    enabled: true
    connectionUrl: "你的连接 url"
```

```bash Docker
# 在你的 .env 文件中
REDIS_DATABASE_URI="你的连接 url"
```


</CodeGroup>

你也可以将连接 URL 存储在现有的 Kubernetes Secret 中，并在 Helm values 中引用它。

<CodeGroup>

```yaml Helm（使用现有 Secret）
redis:
  external:
    enabled: true
    # 包含连接 URL 的现有 Secret 的名称
    existingSecretName: "my-redis-secret"
    # Secret 中存储连接 URL 的键（显示默认值）
    connectionUrlSecretKey: "connection_url"
```

```yaml Kubernetes Secret
apiVersion: v1
kind: Secret
metadata:
  name: my-redis-secret
type: Opaque
stringData:
  # 完整连接 URL，例如，使用带密码的 TLS
  connection_url: "rediss://langsmith-redis:6380/0?password=foo"
```

</CodeGroup>

配置后，你应该能够重新安装 LangSmith 实例。如果一切配置正确，你的 LangSmith 实例现在应该使用你的外部 Redis 实例。

## Redis cluster
从 LangSmith helm 版本 **0.12.25** 开始，我们正式支持 **Redis Cluster**。

### 主机名

使用 Redis Cluster 时，请提供节点主机名和端口的列表。每个节点 URI 必须采用以下形式：

```text
redis://hostname:port
```

例如：

```text
redis://redis-node-0:6379
redis://redis-node-1:6379
redis://redis-node-2:6379
```

不要在这些 URI 中包含密码，也不要在此使用 `rediss`。对于 Redis Cluster：

- 通过 `redis.external.cluster.password` 或使用 `passwordSecretKey` 通过 Secret 分别提供密码。
- TLS 默以为 Redis Cluster 启用（`redis.external.cluster.tlsEnabled: true`）。如果你的集群不使用 TLS，请将 `tlsEnabled: false`。

### 配置

连接到外部 Redis Cluster 时，在 `redis.external.cluster` 下配置 Helm values。你可以：

* 在 `values.yaml` 中直接提供节点 URI 和（可选）密码。
* 或引用包含节点 URI 和密码的现有 Kubernetes `Secret`。

<CodeGroup>

```yaml Helm（内联值）
redis:
  external:
    enabled: true
    cluster:
      enabled: true
      # 集群节点 URI 列表。格式：redis://host:port
      nodeUris:
        - "redis://redis-node-0:6379"
        - "redis://redis-node-1:6379"
        - "redis://redis-node-2:6379"
      # 可选。如果你的集群需要身份验证，请设置密码或使用 Secret（推荐）。
      password: "your_redis_password"
      # TLS 默以为启用。如果你的集群不使用 TLS，请设置为 false。
      tlsEnabled: true
```

```yaml Helm（使用现有 Secret）
redis:
  external:
    enabled: true
    # 包含集群连接详情的现有 Secret 的名称
    existingSecretName: "my-redis-cluster-secret"
    cluster:
      enabled: true
      # Secret 中的键。显示默认值；如果你的 Secret 使用不同的键，请覆盖。
      nodeUrisSecretKey: "redis_cluster_node_uris"
      passwordSecretKey: "redis_cluster_password"
      tlsEnabled: true
```

</CodeGroup>

如果使用现有 Secret，它应包含：

<CodeGroup>

```yaml Kubernetes Secret
apiVersion: v1
kind: Secret
metadata:
  name: my-redis-cluster-secret
type: Opaque
stringData:
  # 节点 URI 的 JSON 数组（作为字符串）
  redis_cluster_node_uris: '["redis://redis-node-0:6379","redis://redis-node-1:6379","redis://redis-node-2:6379"]'
  # 如果你的集群需要密码
  redis_cluster_password: "your_redis_password"
```

</CodeGroup>

## Azure 托管 Redis

[Azure Managed Redis](https://azure.microsoft.com/en-us/products/managed-redis) 支持两种影响 LangSmith 连接方式的集群策略。根据实例的集群策略选择以下配置。

### OSS Cluster

LangSmith 使用 Redis Cluster 模式连接到 OSS 集群策略实例。

从 LangSmith helm chart 版本 **0.13.33** 开始，支持将 `ssl_check_hostname=false` 作为节点 URI 参数。在我们的测试中，OSS 集群策略需要禁用 SSL 主机名验证。Azure 的代理将连接解析为不在证书 SAN 中的内部节点 IP，导致主机名验证失败。

```yaml
redis:
  external:
    enabled: true
    cluster:
      enabled: true
      nodeUris:
        - "redis://<node_url>:10000?ssl_check_hostname=false"
      tlsEnabled: true
```

### EnterpriseCluster

从 LangSmith helm chart 版本 **0.13.33** 开始，LangSmith 支持具有 EnterpriseCluster 策略的 Azure Managed Redis。此策略公开一个处理分片的单一端点。LangSmith 必须作为独立（单实例）客户端连接，但它不支持 MULTI/EXEC 等集群不安全操作。设置 `redis.external.clusterSafeMode: true` 以禁用不安全的集群操作。

```yaml
redis:
  external:
    enabled: true
    connectionUrl: "rediss://<azure-redis-host>:6380"
    # EnterpriseCluster 需要：使用单实例客户端并禁用不安全的集群操作
    clusterSafeMode: true
```

有关 EnterpriseCluster 的 Microsoft Entra (IAM) 身份验证，请参阅 [IAM 身份验证中的 Azure 选项卡](#azure-cache-for-redis) 并在你的 Helm values 中包含 `clusterSafeMode: true`。

## TLS 和 Redis

使用本节配置 Redis 连接的 TLS。有关挂载内部/公共 CA 以便 LangSmith 信任你的 Redis 服务器证书，请参阅[配置自定义 TLS 证书](/langsmith/self-host-custom-tls-certificates#mount-internal-cas-for-tls)。

### 服务器 TLS（单向）

要验证 Redis 服务器证书：

- 使用 `config.customCa.secretName` 和 `config.customCa.secretKey` 提供 CA 包。
- 对于独立 Redis，在连接 URL 中使用 `rediss://`。
- 对于 Redis Cluster，`redis.external.cluster.tlsEnabled` 默认为 `true`。确保它没有设置为 `false`。

<Warning>
仅在 Redis 服务器使用内部或私有 CA 时才挂载自定义 CA。公共可信 CA 不需要此配置。
</Warning>

<CodeGroup>

```yaml Helm（独立 - 服务器 TLS）
config:
  customCa:
    secretName: "langsmith-custom-ca"  # 包含你的 CA 包的 Secret
    secretKey: "ca.crt"    # Secret 中包含 CA 包的键
redis:
  external:
    enabled: true
    # 使用 rediss:// 并在服务器需要时包含密码
    connectionUrl: "rediss://host:6380/0?password=<PASSWORD>"
```

```yaml Helm（Cluster - 服务器 TLS）
config:
  customCa:
    secretName: "langsmith-custom-ca"  # 包含你的 CA 包的 Secret
    secretKey: "ca.crt"    # Secret 中包含 CA 包的键
redis:
  external:
    enabled: true
    cluster:
      enabled: true
      tlsEnabled: true
      nodeUris:
        - "redis://redis-node-0:6379"
        - "redis://redis-node-1:6379"
        - "redis://redis-node-2:6379"
      password: "<PASSWORD>"
```

```yaml Kubernetes Secret（CA 包）
apiVersion: v1
kind: Secret
metadata:
  name: langsmith-custom-ca
type: Opaque
stringData:
  ca.crt: |
    -----BEGIN CERTIFICATE-----
    <ROOT_OR_INTERMEDIATE_CA_CERT_CHAIN>
    -----END CERTIFICATE-----
```

</CodeGroup>

### 带有客户端身份验证的相互 TLS (mTLS)

从 LangSmith helm chart 版本 **0.12.29** 开始，我们支持 Redis 客户端的 mTLS。对于 mTLS 中的服务器端身份验证，除了以下客户端证书配置外，还使用[服务器 TLS 步骤](#server-tls-one-way)（自定义 CA）。

如果你的 Redis 服务器需要客户端证书身份验证：

- 使用你的客户端证书和密钥提供一个 Secret。
- 通过 `redis.external.clientCert.secretName` 引用它，并使用 `certSecretKey` 和 `keySecretKey` 指定密钥。
- 对于独立 Redis，继续在连接 URL 中使用 `rediss://`。
- 对于 Redis Cluster，`redis.external.cluster.tlsEnabled` 默认为 `true`。确保它没有设置为 `false`。

<CodeGroup>

```yaml Helm（客户端身份验证）
redis:
  external:
    enabled: true
    clientCert:
      secretName: "redis-mtls-secret"
      certSecretKey: "tls.crt"
      keySecretKey: "tls.key"
    # 独立示例：
    # connectionUrl: "rediss://host:6380/0?password=<PASSWORD>"
    # 或者，对于 Cluster：
    cluster:
      enabled: true
      tlsEnabled: true
      nodeUris:
        - "redis://redis-node-0:6379"
        - "redis://redis-node-1:6379"
        - "redis://redis-node-2:6379"
      password: "<PASSWORD>"
```

```yaml Kubernetes Secret（客户端证书/密钥）
apiVersion: v1
kind: Secret
metadata:
  name: redis-mtls-secret
type: Opaque
stringData:
  tls.crt: |
    -----BEGIN CERTIFICATE-----
    <CLIENT_CERT>
    -----END CERTIFICATE-----
  tls.key: |
    -----BEGIN PRIVATE KEY-----
    <CLIENT_KEY>
    -----END PRIVATE KEY-----
```

</CodeGroup>

#### 证书卷的 Pod 安全上下文

mTLS 挂载的证书卷受文件访问限制保护。为了确保所有 LangSmith pod 可以读取证书文件，你必须在 pod 安全上下文中设置 `fsGroup: 1000`。

你可以通过两种方式之一配置此设置：

**选项 1：使用 `commonPodSecurityContext`**

在顶层设置 `fsGroup` 以将其应用到所有 pod：

```yaml
commonPodSecurityContext:
  fsGroup: 1000
```

**选项 2：添加到单个 pod 安全上下文**

如果你需要更细粒度的控制，请将 `fsGroup` 分别添加到每个 pod 的安全上下文中。请参阅 [mtls 配置示例](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/mtls_config.yaml) 获取完整参考。

## IAM 身份验证

从 LangSmith helm chart 版本 **0.12.34** 开始，我们支持 Redis 的 IAM 身份验证。这允许你使用云提供商的工作负载身份而不是静态密码。

<Note>
IAM 身份验证支持独立 Redis 和 Redis Cluster 配置。但是，并非所有云提供商都支持所有 Redis 产品的 IAM 身份验证。检查你的云提供商的文档以验证你的特定 Redis 设置的 IAM 支持（例如，GCP 仅支持 Memorystore Cluster 的 IAM，不支持独立 Memorystore）。
</Note>

### ElastiCache for Redis IAM 身份验证

ElastiCache for Redis 支持 [IAM 身份验证](https://docs.aws.amazon.com/AmazonElastiCache/latest/red-ug/auth-iam.html)，允许你使用 AWS IAM 凭据而不是 Redis AUTH 密码进行身份验证。

#### 前置条件

1. 在你的 Kubernetes 集群中使用 [AWS IRSA](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html) 或 [EKS Pod Identity](https://docs.aws.amazon.com/eks/latest/userguide/pod-identities.html) 配置工作负载身份
2. 在你的 ElastiCache 实例上启用 IAM 身份验证并授予对你的工作负载身份的访问权限

#### 配置

**独立 Redis：**

```yaml
redis:
  external:
    enabled: true
    existingSecretName: "redis-secret"
    iamAuthProvider: "aws"
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: redis-secret
type: Opaque
stringData:
  # IAM 连接 URL - 标识作为用户名，无密码
  connection_url: "rediss://<iam-identity>@<elasticache-host>:6380"
```

**Redis Cluster：**

```yaml
redis:
  external:
    enabled: true
    existingSecretName: "redis-cluster-secret"
    iamAuthProvider: "aws"
    cluster:
      enabled: true
      nodeUrisSecretKey: "redis_cluster_node_uris"
      tlsEnabled: true
```

#### 必需的注释

你必须将 AWS IRSA 要求的 ServiceAccount 注释应用到所有连接到 Redis 的 LangSmith 组件：

**部署：** `backend`、`queue`、`platformBackend`、`hostBackend`、`ingestQueue`

示例配置：

```yaml
backend:
  serviceAccount:
    annotations:
      eks.amazonaws.com/role-arn: "arn:aws:iam::<account-id>:role/<role-name>"

queue:
  serviceAccount:
    annotations:
      eks.amazonaws.com/role-arn: "arn:aws:iam::<account-id>:role/<role-name>"

platformBackend:
  serviceAccount:
    annotations:
      eks.amazonaws.com/role-arn: "arn:aws:iam::<account-id>:role/<role-name>"

hostBackend:
  serviceAccount:
    annotations:
      eks.amazonaws.com/role-arn: "arn:aws:iam::<account-id>:role/<role-name>"

ingestQueue:
  serviceAccount:
    annotations:
      eks.amazonaws.com/role-arn: "arn:aws:iam::<account-id>:role/<role-name>"
```

### Memorystore for Redis IAM 身份验证

Memorystore for Redis 支持 [IAM 身份验证](https://docs.cloud.google.com/memorystore/docs/cluster/about-iam-auth)，**仅适用于 Cluster 实例**（不包括独立 Memorystore）。这允许你使用 GCP 服务账户进行身份验证。

<Note>
IAM 身份验证仅适用于 Memorystore Cluster，不适用于独立 Memorystore 实例。
</Note>

#### 前置条件

1. 在你的 Kubernetes 集群中使用 [GCP Workload Identity](https://cloud.google.com/kubernetes-engine/docs/how-to/workload-identity) 配置工作负载身份
2. 在你的 Memorystore Cluster 上启用 IAM 身份验证并授予对你的工作负载身份的访问权限

#### 配置

**带 IAM 的 Memorystore Cluster：**

```yaml
redis:
  external:
    enabled: true
    existingSecretName: "redis-cluster-secret"
    iamAuthProvider: "gcp"
    cluster:
      enabled: true
      nodeUrisSecretKey: "redis_cluster_node_uris"
      tlsEnabled: true
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: redis-cluster-secret
type: Opaque
stringData:
  redis_cluster_node_uris: '["redis://node-0:6379","redis://node-1:6379","redis://node-2:6379"]'
```

#### 必需的注释

你必须将 GCP Workload Identity 要求的 ServiceAccount 注释应用到所有连接到 Redis 的 LangSmith 组件：

**部署：** `backend`、`queue`、`platformBackend`、`hostBackend`、`ingestQueue`

示例配置：

```yaml
backend:
  serviceAccount:
    annotations:
      iam.gke.io/gcp-service-account: "<service-account>@<project>.iam.gserviceaccount.com"

queue:
  serviceAccount:
    annotations:
      iam.gke.io/gcp-service-account: "<service-account>@<project>.iam.gserviceaccount.com"

platformBackend:
  serviceAccount:
    annotations:
      iam.gke.io/gcp-service-account: "<service-account>@<project>.iam.gserviceaccount.com"

hostBackend:
  serviceAccount:
    annotations:
      iam.gke.io/gcp-service-account: "<service-account>@<project>.iam.gserviceaccount.com"

ingestQueue:
  serviceAccount:
    annotations:
      iam.gke.io/gcp-service-account: "<service-account>@<project>.iam.gserviceaccount.com"
```

### 使用 Microsoft Entra 身份验证的 Azure Cache for Redis

Azure Cache for Redis 支持 [Microsoft Entra 身份验证](https://learn.microsoft.com/en-us/azure/azure-cache-for-redis/cache-azure-active-directory-for-authentication)，允许你使用 Azure 托管标识进行身份验证。

#### 前置条件

1. 在你的 Kubernetes 集群中使用 [Azure Workload Identity](https://learn.microsoft.com/en-us/azure/aks/workload-identity-overview) 配置工作负载身份
2. 在你的 Azure Cache for Redis 上启用 Microsoft Entra 身份验证并授予对你的工作负载身份的访问权限

#### 配置

**独立 Redis：**

```yaml
redis:
  external:
    enabled: true
    existingSecretName: "redis-secret"
    iamAuthProvider: "azure"
    # 如果使用 EnterpriseCluster 策略，请包含。请参阅 Azure 托管 Redis 部分了解更多详情。
    # clusterSafeMode: true
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: redis-secret
type: Opaque
stringData:
  # IAM 连接 URL - 托管标识作为用户名，无密码
  connection_url: "rediss://<managed-identity>@<azure-redis-host>:6380"
```

**Redis Cluster：**

```yaml
redis:
  external:
    enabled: true
    existingSecretName: "redis-cluster-secret"
    iamAuthProvider: "azure"
    cluster:
      enabled: true
      nodeUrisSecretKey: "redis_cluster_node_uris"
```

**部署：** `backend`、`queue`、`platformBackend`、`hostBackend`、`ingestQueue`

```yaml
    annotations:
      azure.workload.identity/client-id: "<managed-identity-client-id>"

    labels:
      azure.workload.identity/use: "true"

  serviceAccount:
    annotations:
      azure.workload.identity/client-id: "<managed-identity-client-id>"

      azure.workload.identity/use: "true"
```
