当你在自动化操作中添加 webhook URL 时，LangChain 会在定义的规则匹配到任何新运行时，向你的 webhook 端点发送 POST 请求。

![Webhook](/langsmith/images/webhook.png)

## Webhook 负载

LangChain 发送到 webhook 端点的负载包含：

- `"rule_id"`：发送此负载的自动化 ID。
- `"start_time"` 和 `"end_time"`：LangChain 找到匹配运行的时间边界。
- `"runs"`：这是一个运行数组，每个运行都是一个字典。如果需要获取每个运行的更多信息，请在端点中使用 SDK 从 API 获取。
- `"feedback_stats"`：这是运行的反馈统计字典。该字段的示例负载如下面的代码块所示。

```json
"feedback_stats": {
    "about_langchain": {

        "values": {}

            "CONCEPTUAL": 1
```

<Note>
**从 S3 URL 获取数据**

根据运行的最新程度，`inputs_s3_urls` 和 `outputs_s3_urls` 字段可能包含指向实际数据的 S3 URL，而不是数据本身。

可以通过 `inputs_s3_urls` 和 `outputs_s3_urls` 中提供的 `ROOT.presigned_url` 来获取 `inputs` 和 `outputs`。
</Note>

## 安全性

向 webhook URL 添加一个密钥查询字符串参数，并在每个传入请求上进行验证。这样可以确保即使有人发现了你的 webhook URL，你也能将那些调用与真实的 webhook 通知区分开来。

例如：

```
https://api.example.com/langsmith_webhook?secret=38ee77617c3a489ab6e871fbeb2ec87d
```

### Webhook 自定义 HTTP 头

如果你想随 webhook 发送任何特定的头，可以为每个 URL 进行配置。设置方法是点击 URL 字段旁边的 `Headers` 选项，然后添加你的头。

<Note>
头以加密格式存储。
</Note>

![Webhook 头](/langsmith/images/webhook-headers.png)

### Webhook 投递

在将事件投递到 webhook 端点时，LangChain 遵循以下准则：

- 如果 LangChain 无法连接到你的端点，LangChain 会在宣布投递失败之前重试传输连接最多 2 次。
- 如果你的端点响应时间超过 5 秒，LangChain 宣布投递失败，不重试。
- 如果你的端点在 5 秒内返回 5xx 状态码，LangChain 会以指数退避方式重试最多 2 次。
- 如果你的端点返回 4xx 状态码，LangChain 宣布投递失败，不重试。
- 端点返回的主体中的任何内容都将被忽略。

## 确保评估在 webhook 触发前完成

默认情况下，自动化规则独立运行。一个 webhook 规则和一个在线评估器规则扫描同一个项目时，可能会在不同时间拾取同一个运行，因此 webhook 可能在评估器有机会对运行评分之前就触发了。

推荐的解决方案是向 webhook 规则添加一个 _反馈过滤器_。这告诉 LangChain 只在运行已携带预期评分时才将其发送到 webhook，无论何时评估。

例如，你有一个产生 `answer_usefulness` 评分的在线评估器，以及一个应该仅在该评分存在后才触发的 webhook 规则。

1. 在追踪项目的 **Automations** 选项卡中打开 webhook 自动化规则。
1. 编辑规则的过滤器以要求反馈键。在过滤器构建器中，添加一个条件：

   ```
   has(feedback_key, "answer_usefulness")
   ```

1. 保存规则。

现在 webhook 规则将跳过任何尚未有 `answer_usefulness` 评分的运行。当评估器规则运行并附加评分时，webhook 规则的下一次轮询周期将拾取那些运行并将其发送到你的端点。

<Tip>
你也可以按评分值本身进行过滤，而不仅仅是其存在。例如，只将低有用性评分的运行发送到你的端点：

```
has(feedback_key, "answer_usefulness") and feedback_score < 0.5
```

有关完整的过滤器语法，请参阅 [Filter traces](/langsmith/filter-traces-in-application)。
</Tip>

<Note>
在单个自动化规则中，操作按固定顺序执行：标注队列 → 数据集 → webhook → 评估。这意味着如果你的 webhook 和评估器配置在**同一个**规则上，webhook 总是在该规则的评估完成之前触发。为了确保 webhook 收到评估评分，请将 webhook 和评估器保持为**单独的规则**，并如示例中所述在 webhook 规则上使用反馈过滤器。
</Note>

## Modal 示例

### 设置

有关如何进行此设置的示例，本指南使用 [Modal](https://modal.com/)。Modal 为推理和微调提供自动扩展 GPU、安全容器化代码代理和无服务器 Python Web 端点。本指南重点介绍 Web 端点。

首先，创建一个 Modal 账户。然后，在本地安装 Modal SDK：

<CodeGroup>
```bash pip
pip install modal
```

```bash uv
uv add modal
```
</CodeGroup>

要完成账户设置，请运行命令：

```shell
modal setup
```

按照说明完成账户设置。

### 密钥

接下来，你需要在 Modal 中设置一些密钥。

首先，LangChain 需要通过传递密钥来对 Modal 进行身份验证。最简单的方法是在查询参数中传递密钥。要验证此密钥，请在 _Modal_ 中添加一个密钥进行验证。方法是[创建一个 Modal 密钥](https://modal.com/docs/guide/secrets)。将密钥命名为 `ls-webhook`，并设置名为 `LS_WEBHOOK` 的环境变量。

你也可以设置 LangChain 密钥——幸运的是已经有一个集成模板了！

![LangChain Modal 模板](/langsmith/images/modal-langsmith-secret.png)

### 服务

之后，你可以创建一个 Python 文件作为端点。下面的代码块中有一个示例，并附有解释正在发生的事情的注释：

```python
from fastapi import HTTPException, status, Request, Query
from modal import Secret, Stub, web_endpoint, Image

stub = Stub("auth-example", image=Image.debian_slim().pip_install("langsmith"))


@stub.function(
    secrets=[Secret.from_name("ls-webhook"), Secret.from_name("my-langsmith-secret")]
)
# We want this to be a `POST` endpoint since we will post data here
@web_endpoint(method="POST")
# We set up a `secret` query parameter
def f(data: dict, secret: str = Query(...)):
    # You can import dependencies you don't have locally inside Modal functions
    from langsmith import Client

    # First, we validate the secret key we pass
    import os

    if secret != os.environ["LS_WEBHOOK"]:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect bearer token",
            headers={"WWW-Authenticate": "Bearer"},
        )

    # This is where we put the logic for what should happen inside this webhook
    ls_client = Client()
    runs = data["runs"]
    ids = [r["id"] for r in runs]
    feedback = list(ls_client.list_feedback(run_ids=ids))
    for r, f in zip(runs, feedback):
        try:
            ls_client.create_example(
                inputs=r["inputs"],
                outputs={"output": f.correction},
                dataset_name="classifier-github-issues",
            )
        except Exception:
            raise ValueError(f"{r} and {f}")
    # Function body
    return "success!"
```

使用 `modal deploy ...` 进行部署（请参阅 [管理 Modal 部署](https://modal.com/docs/guide/managing-deployments)）。

### 将其连接起来

使用你之前创建的函数 URL 并将其添加为 webhook。请记住也将密钥作为查询参数传递。把它们放在一起，应该看起来像这样：

```
https://hwchase17--auth-example-f-dev.modal.run?secret={SECRET}
```

将 `{SECRET}` 替换为你创建的用于访问 Modal 服务的密钥。
