[**LangSmith Fleet**](/langsmith/fleet/index) 是一个企业代理平台，用于在整个组织中构建、共享和管理代理。本页将其与类似平台进行对比，帮助您为团队选择合适的平台。

<div className="compact-first-col">

| **平台** | **选择理由** |
| ------------ | ---------------- |
| [LangSmith Fleet](/langsmith/fleet/index) | 您想要在整个组织中构建和共享专用代理，保持模型无关性，并通过 LangSmith 保持完整的可观测性。**Fleet** 是唯一具有自托管部署路径和通过 [Deep Agents](/oss/deepagents/overview) 将代理导出为代码的能力的选项。 |
| Claude Cowork | 您想要将开放式任务委托给桌面上的 Claude 用于个人知识工作，并且设备上的数据存储满足您的隐私要求。 |
| Amazon Quick | 您已在 AWS 上并希望获得直接访问 AWS 数据源和企业集成的 AI 助手。 |
| Google Workspace Studio | 您的组织在 Google Workspace 上运行，您想要与 Gmail、Drive 和 Sheets 原生集成的无代码代理，而无需离开 Google 生态系统。 |

</div>

### 目标用户

**Fleet** 涵盖组织范围和个人用例。团队可以构建在整个组织中共享的专用代理（例如，为整个运营部门服务的供应商入职代理，或为每个客户经理每周一节省三十分钟的每周报告代理），任何用户都可以通过 Fleet 的通用默认聊天使用任何工具获得任何任务的帮助。

Claude Cowork 专为个人工作流程设计：每个用户在自己的机器上运行 Claude 进行开放式任务委托，而不是在团队中构建和共享代理。

Amazon Quick 和 Google Workspace Studio 是围绕问答和工作流自动化构建的企业级平台，但主要不是为构建和共享专用代理而设计的。

**Fleet** 还允许您设置工具级别的批准要求，以便代理在执行敏感步骤之前与您确认，并通过[集中收件箱](https://smith.langchain.com/agents/inbox)审查、编辑和批准所有代理的操作。

Claude Cowork 采用类似的方法，使用"先给我看计划"模式。Amazon Quick 提供通知，但没有用于跨所有代理审查操作的集中收件箱。

### 企业控制和访问

**Fleet** 提供 RBAC、基于属性的访问控制以及每个代理的共享权限（克隆、运行和编辑），这是 Claude Cowork 所没有的。对于需要管理哪些团队可以访问、运行或修改特定代理的组织来说，这是一个重大差异。

Amazon Quick 和 Google Workspace Studio 继承自其各自的云平台（AWS IAM 和 Google Workspace 角色）的访问控制，但都没有提供 Fleet 的每代理权限模型。

**Fleet** 在工作区级别管理支出，而不是通过每用户或每团队上限。Claude Cowork、Amazon Quick 和 Google Workspace Studio 都提供更细粒度的支出控制。对于企业计费选项，[联系销售](https://www.langchain.com/contact-sales)。

### 模型灵活性

**Fleet** 通过 OpenAI 或 Anthropic 聊天规范支持任何大型语言模型，包括来自 OpenAI、Anthropic、Google 和自托管提供商的模型。

Claude Cowork 锁定为 Claude。Google Workspace Studio 使用 Gemini 3。Amazon Quick 支持的模型尚未从公开文档中确认。

Google Workspace Studio 包含在 Google Workspace Business 和 Enterprise 计划中，无需单独购买，但它仅在 Google 生态系统中工作。Amazon Quick 需要现有的 AWS 基础设施，不包含捆绑的生产力套件。

**Fleet** 和 Claude Cowork 在很大程度上与生态系统无关。

### 内存、自我更新和学习

**Fleet** 代理可以使用专用内存系统在对话之间保留上下文，并且可以随着从交互中学习而更新自己的指令、添加工具或删除工具。在四个比较平台中，只有 Fleet 支持代理自我修改。

### 可观测性和治理

**Fleet** 最明显的优势是其与 LangSmith 的原生连接。每个代理运行都在 LangSmith 中进行跟踪，使调试性能和大规模运行评估变得容易。

Claude Cowork、Amazon Quick 和 Google Workspace Studio 都有审计和活动日志，但都没有通过专用可观测性平台匹配 Fleet 的跟踪、评估和调试深度。

### 代码导出和托管

**Fleet** 让您可以通过 [Deep Agents](/oss/deepagents/overview)（Fleet 运行的开源代理运行时）将您构建的任何代理导出为代码。导出的代理采用 MIT 许可，可以独立于 Fleet 部署、在代码中修改或通过 [API](/langsmith/fleet/code) 直接集成到您自己的应用程序中。本比较中的其他平台都不提供代码导出路径。

**Fleet** 是此比较中唯一具有自托管部署选项的平台。对于有合规要求的团队，自托管和 BYOC（使用您自己的云）配置让您可以在自己的基础设施内完全运行 Fleet。

Amazon Quick 提供企业级 AWS 基础设施。Google Workspace Studio 遵守 Google Workspace 数据承诺。Claude Cowork 在设备上本地存储数据，使其成为此比较中唯一将数据完全保存在外部服务器外的平台。
