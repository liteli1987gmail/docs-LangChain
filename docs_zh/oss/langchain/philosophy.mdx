LangChain 受到几个核心信念的驱动：

- 大型语言模型（LLM）是伟大而强大的新技术。
- 当你将大型语言模型与外部数据源结合时，它们会变得更好。
- 大型语言模型将改变未来应用的模样。具体来说，未来的应用将越来越具有代理性（agentic）。
- 在这场转型中，我们仍然处于非常早期的阶段。
- 虽然构建这些代理应用的原型很容易，但构建可靠到可以投入生产的代理仍然非常困难。

如今开发者可以选择如何构建代理：使用 [LangChain](/oss/langchain/overview) 以获得最大的灵活性和控制力，或使用 [Deep Agents](/oss/langchain/overview)，它提供类似的灵活性和控制力，但带有固执己见的内置规划、文件系统工具、子代理和上下文管理。两者都建立在 [LangGraph](/oss/langgraph/overview) 之上。

对于 LangChain，我们有两个核心重点：

<Steps>
    <Step title="我们希望使开发者能够使用最好的模型进行构建。">
        不同的提供商公开不同的 API，具有不同的模型参数和不同的消息格式。
        标准化这些模型输入和输出是一个核心重点，使开发者能够轻松切换到最新的最先进的模型，避免锁定。
    </Step>
    <Step title="我们希望使使用模型来编排与其他数据和计算交互的更复杂流程变得容易。">
        模型应该不仅用于*文本生成*——它们还应该用于编排与其他数据交互的更复杂流程。LangChain 使定义大型语言模型可以动态使用的[工具](/oss/langchain/tools)变得容易，同时还帮助解析和访问非结构化数据。
    </Step>
</Steps>

## 历史

鉴于该领域不断变化的速度，LangChain 也随着时间的推移而发展。下面是 LangChain 如何随着年代变化而变化的简要时间线，与构建大型语言模型应用的含义演变相伴：

<Update label="2022-10-24" description="v0.0.1">
    在 ChatGPT 一个月前，**LangChain 作为 Python 包推出**。它由两个主要组件组成：

    - 大型语言模型抽象
    - "链"，或用于常见用例的计算预定步骤。例如 - RAG：运行检索步骤，然后运行生成步骤。

    LangChain 这个名字来自 "Language"（如语言模型）和 "Chains"。
</Update>

<Update label="2022-12">
    第一个通用代理被添加到 LangChain。

    这些通用代理基于 [ReAct 论文](https://arxiv.org/abs/2210.03629)（ReAct 代表 Reasoning and Acting）。它们使用大型语言模型生成表示工具调用的 JSON，然后解析该 JSON 以确定要调用哪些工具。
</Update>

<Update label="2023-01">
    OpenAI 发布了 "Chat Completion" API。

    之前，模型接受字符串并返回字符串。在 ChatCompletions API 中，它们演变为接受消息列表并返回消息。其他模型提供商纷纷效仿，LangChain 更新为与消息列表配合使用。
</Update>

<Update label="2023-01">
    LangChain 发布 JavaScript 版本。

    大型语言模型和代理将改变应用的构建方式，而 JavaScript 是应用开发者的语言。
</Update>

<Update label="2023-02">
    **LangChain Inc. 作为一家公司成立**，围绕开源 LangChain 项目。

    主要目标是"使智能代理无处不在"。团队认识到，虽然 LangChain 是一个关键部分（LangChain 使开始使用大型语言模型变得简单），但也需要其他组件。
</Update>

<Update label="2023-03">
    OpenAI 在其 API 中发布了 "function calling"。

    这允许 API 显式生成表示工具调用的有效载荷。其他模型提供商纷纷效仿，LangChain 被更新为使用此作为工具调用的首选方法（而不是解析 JSON）。
</Update>

<Update label="2023-06">
    **LangSmith 发布**作为 LangChain Inc. 的闭源平台，提供可观察性和评估。

    构建代理的主要问题是让它们变得可靠，而 LangSmith——提供可观察性和评估——是为了解决这一需求而构建的。LangChain 被更新为与 LangSmith 无缝集成。
</Update>

<Update label="2024-01" description="v0.1.0">
    **LangChain 发布 0.1.0**，这是其第一个非 0.0.x 版本。

    行业从原型成熟到生产，因此 LangChain 增加了对稳定性的关注。
</Update>

<Update label="2024-02">
    **LangGraph 发布**作为开源库。

    原始 LangChain 有两个重点：大型语言模型抽象，以及用于入门常见应用的高级接口；然而，它缺少一个允许开发者控制代理确切流程的低级编排层。这就引出了：LangGraph。

    在构建 LangGraph 时，我们从构建 LangChain 的经验中学习，并添加了我们发现需要的功能：流式传输、持久执行、短期记忆、人在环等。
</Update>

<Update label="2024-10">
    LangGraph 成为构建任何超出单个大型语言模型调用的人工智能应用的首选方式。

    当开发者尝试提高应用的可靠性时，他们需要比高级接口提供的更多的控制。LangGraph 提供了那种低级灵活性。大多数链和代理在 LangChain 中被标记为已弃用，并有迁移到 LangGraph 的指南。仍然在 LangGraph 中创建的一个高级抽象是：代理抽象。它建立在低级 LangGraph 之上，与来自 LangChain 的 ReAct 代理具有相同的接口。
</Update>

</Update>

<Update label="2026-03-15" description="v0.5.3">
    **Deep Agents 发布**作为建立在 LangGraph 之上的开源代理测试平台。

    虽然 LangChain 为自定义代理架构提供了灵活的构建块，[Deep Agents](/oss/langchain/overview) 为研究和编码等复杂、长时运行任务提供了电池包含选项。它添加了内置规划工具、具有可插拔后端（内存、磁盘、LangGraph 存储、沙箱）的虚拟文件系统，以及用于上下文隔离的子代理生成。使用 Deep Agents 用于具有预定义工具的更自主代理；使用 LangChain 以完全控制您的代理架构。
</Update>
