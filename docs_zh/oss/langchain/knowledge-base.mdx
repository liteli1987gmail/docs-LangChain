## 概述

本教程将帮助你熟悉 LangChain 的[文档加载器](/oss/integrations/document_loaders)、[嵌入](/oss/integrations/embeddings)和[向量存储](/oss/integrations/vectorstores)抽象。这些抽象设计用于支持从（向量）数据库和其他来源检索数据，以便与大型语言模型工作流集成。这对于在模型推理过程中需要推理数据的应用很重要，例如检索增强生成或 [RAG](/oss/langchain/retrieval)。

在这里，我们将构建一个针对 PDF 文档的搜索引擎。这将允许我们检索与输入查询相似的 PDF 段落。本指南还包括在搜索引擎之上构建的最小 RAG 实现。

### 概念

本指南专注于文本数据的检索。我们将涵盖以下概念：

- [文档和文档加载器](/oss/integrations/document_loaders)；
- [文本分割器](/oss/integrations/splitters)；
- [嵌入](/oss/integrations/embeddings)；
- [向量存储](/oss/integrations/vectorstores)和[检索器](/oss/integrations/retrievers)。

## 1. 文档和文档加载器

LangChain 实现了一个 @[Document] 抽象，旨在表示一段文本及其相关元数据。它有三个属性：

:::python
- `page_content`：表示内容的字符串；
- `metadata`：包含任意元数据的字典；
- `id`：（可选）文档的字符串标识符。
:::
:::js
- `pageContent`：表示内容的字符串；
- `metadata`：包含任意元数据的字典；
- `id`：（可选）文档的字符串标识符。
:::

`metadata` 属性可以捕获有关文档来源、与其他文档的关系以及其他信息。请注意，一个单独的 @[`Document`] 对象通常代表较大文档的一个块。

我们可以在需要时生成示例文档：

:::python
```python

documents = [

        metadata={"source": "mammal-pets-doc"},

        page_content="Cats are independent pets that often enjoy their own space.",
        metadata={"source": "mammal-pets-doc"},
    ),
]
```

### 分割

对于信息检索和下游问答目的，单个页面可能太粗粒了。我们的最终目标是检索回答输入查询的 @[`Document`] 对象，进一步分割 PDF 将有助于确保文档相关部分的意义不会因周围文本而被"冲淡"。

我们可以使用[文本分割器](/oss/integrations/splitters)来实现这个目的。这里我们将使用一个简单的文本分割器，基于字符进行分区。我们将把文档分割成 1000 个字符的块，
块之间有 200 个字符的重叠。这种重叠有助于
减少将语句与其相关的重要上下文分离的可能性。我们使用
`RecursiveCharacterTextSplitter`，
它将使用常见的分隔符（如换行符）递归地分割文档，
直到每个块达到合适的大小。这是用于通用文本用例的
推荐文本分割器。

:::python
我们设置 `add_start_index=True`，以便每个
分割的 Document 在原始 Document 中开始的字符索引被保留为
元数据属性 "start_index"。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200, add_start_index=True
)
all_splits = text_splitter.split_documents(docs)

print(len(all_splits))
```
:::
:::js
```typescript
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";

const textSplitter = new RecursiveCharacterTextSplitter({
  chunkSize: 1000,
  chunkOverlap: 200,
});

const allSplits = await textSplitter.splitDocuments(docs);

console.log(allSplits.length);
```
:::

```text
514
```


## 2. 嵌入

向量搜索是存储和搜索非结构化数据（如非结构化文本）的常用方法。其思想是存储与文本关联的数值向量。给定一个查询，我们可以[嵌入](/oss/integrations/embeddings)它为相同维度的向量，并使用向量相似性度量（如余弦相似性）来识别相关文本。

LangChain 支持来自[数十个提供商](/oss/integrations/embeddings/)的嵌入。这些模型指定了文本应如何转换为数值向量。让我们选择一个模型：

:::python
<EmbeddingsTabsPy />

```python
vector_1 = embeddings.embed_query(all_splits[0].page_content)
vector_2 = embeddings.embed_query(all_splits[1].page_content)

assert len(vector_1) == len(vector_2)
print(f"Generated vectors of length {len(vector_1)}\n")
print(vector_1[:10])
```
:::
:::js
<EmbeddingsTabsJS />

```typescript
const vector1 = await embeddings.embedQuery(allSplits[0].pageContent);
const vector2 = await embeddings.embedQuery(allSplits[1].pageContent);

assert vector1.length === vector2.length;
console.log(`Generated vectors of length ${vector1.length}\n`);
console.log(vector1.slice(0, 10));
```

## 3. 向量存储

LangChain @[VectorStore] 对象包含用于向存储添加文本和 @[`Document`] 对象的方法，以及使用各种相似性度量进行查询的方法。它们通常使用[嵌入](/oss/integrations/embeddings)模型初始化，这些模型决定如何将文本数据转换为数值向量。

LangChain 包含一套与不同向量存储技术集成的[集成](/oss/integrations/vectorstores)。一些向量存储由提供商托管（如各种云提供商），需要特定的凭证才能使用；一些（如 [Postgres](/oss/integrations/vectorstores/pgvector)）可以在独立的基础设施中运行，可以在本地或通过第三方运行；其他可以在内存中运行以用于轻量级工作负载。让我们选择一个向量存储：

## 4. 检索器

LangChain @[`VectorStore`] 对象不继承 @[Runnable]。LangChain @[Retrievers] 是 Runnable，因此它们实现了一组标准方法（例如同步和异步的 `invoke` 和 `batch` 操作）。虽然我们可以从向量存储构建检索器，但检索器也可以与非向量存储的数据来源接口（如外部 API）。

:::python
我们可以创建一个简单的版本，而不继承 `Retriever`。如果我们选择我们希望用于检索文档的方法，我们可以轻松地创建一个 runnable。下面的我们将围绕 `similarity_search` 方法构建一个：

```python
from typing import List

from langchain_core.documents import Document
from langchain_core.runnables import chain


@chain
def retriever(query: str) -> List[Document]:
    return vector_store.similarity_search(query, k=1)


retriever.batch(
    [
        "How many distribution centers does Nike have in the US?",
        "When was Nike incorporated?",
    ],
)
```

```python
retriever = vector_store.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 1},
)

)
```
