LangChain 实现了一个流式传输系统以呈现实时更新。

流式传输对于增强建立在大型语言模型上的应用程序的响应能力至关重要。通过在完整响应准备好之前就开始显示输出，流式传输显著改善了用户体验（UX），特别是在处理大型语言模型的延迟时。

## 概述

LangChain 的流式传输系统让你从代理运行向你的应用程序呈现实时反馈。

使用 LangChain 流式传输可以做什么：

* <Icon icon="brain" size={16} /> [**流式传输代理进度**](#agent-progress)— 在每个代理步骤后获取状态更新。
* <Icon icon="binary" size={16} /> [**流式传输大型语言模型 token**](#llm-tokens)— 在生成时流式传输语言模型 token。
* <Icon icon="bulb" size={16} /> [**流式传输思考/推理 token**](#streaming-thinking-/-reasoning-tokens)— 在生成时呈现模型推理。
* <Icon icon="table" size={16} /> [**流式传输自定义更新**](#custom-updates)— 发出用户定义的信号（例如 `"Fetched 10/100 records"`）。
* <Icon icon="stack-push" size={16} /> [**流式传输多种模式**](#stream-multiple-modes)— 从 `updates`（代理进度）、`messages`（大型语言模型 token + 元数据）或 `custom`（任意用户数据）中进行选择。

请参阅下面的[常见模式](#common-patterns)部分以获取更多端到端示例。

## 支持的流式传输模式

:::python
将以下流式传输模式中的一个或多个作为列表传递给 @[`stream`][CompiledStateGraph.stream] 或 @[`astream`][CompiledStateGraph.astream] 方法：
:::

:::js
将以下流式传输模式中的一个或多个作为列表传递给 @[`stream`][CompiledStateGraph.stream] 方法：
:::

| 模式 | 描述 |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| `updates` | 在每个代理步骤后流式传输状态更新。如果在同一步骤中进行了多个更新（例如，运行了多个节点），这些更新会单独流式传输。 |
| `messages` | 从任何调用大型语言模型的图节点流式传输 `(token, metadata)` 元组。 |
| `custom` | 使用流写入器从你的图节点内部发出自定义数据。 |

## 代理进度

:::python
要流式传输代理进度，请使用 @[`stream`][CompiledStateGraph.stream] 或 @[`astream`][CompiledStateGraph.astream] 方法并使用 `stream_mode="updates"`。这在每个代理步骤后发出一个事件。
:::

:::js
要流式传输代理进度，请使用 @[`stream`][CompiledStateGraph.stream] 方法并使用 `streamMode: "updates"`。这在每个代理步骤后发出一个事件。
:::

例如，如果你有一个调用一次工具的代理，你应该看到以下更新：

* **大型语言模型节点**：@[`AIMessage`]，其中包含工具调用请求
* **工具节点**：@[`ToolMessage`]，其中包含执行结果
* **大型语言模型节点**：最终人工智能响应

:::python

```python title="流式传输代理进度"
from langchain.agents import create_agent


def get_weather(city: str) -> str:
    """获取给定城市的天气。"""

    return f"It's always sunny in {city}!"

agent = create_agent(
    model="gpt-5-nano",
    tools=[get_weather],
)
for chunk in agent.stream(  # [!code highlight]
    {"messages": [{"role": "user", "content": "What is the weather in SF?"}]},
    stream_mode="updates",
    version="v2",  # [!code highlight]
):
    if chunk["type"] == "updates":  # [!code highlight]
        for step, data in chunk["data"].items():  # [!code highlight]
            print(f"step: {step}")
            print(f"content: {data['messages'][-1].content_blocks}")
```

## 自定义更新

:::python
要在大语言模型执行时从工具流式传输更新，你可以使用 @[`get_stream_writer`]。

```python title="流式传输自定义更新"
from langchain.agents import create_agent
from langgraph.config import get_stream_writer  # [!code highlight]


def get_weather(city: str) -> str:
    """获取给定城市的天气。"""
    writer = get_stream_writer()  # [!code highlight]
    # 流式传输任意数据
    writer(f"Looking up data for city: {city}")
    writer(f"Acquired data for city: {city}")
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[get_weather],
)

for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "What is the weather in SF?"}]},
    stream_mode="custom",  # [!code highlight]
    version="v2",  # [!code highlight]
):
    if chunk["type"] == "custom":  # [!code highlight]
        print(chunk["data"])  # [!code highlight]
```

```shell title="Output"
Looking up data for city: San Francisco
Acquired data for city: San Francisco
```

<Note>
    如果你在工具中添加 @[`get_stream_writer`]，你将无法在 LangGraph 执行上下文之外调用该工具。
</Note>
:::

:::js
要在大语言模型执行时从工具流式传输更新，你可以使用配置中的 `writer` 参数。

```typescript
import z from "zod";
import { tool, createAgent } from "langchain";
import { LangGraphRunnableConfig } from "@langchain/langgraph";

const getWeather = tool(
    async (input, config: LangGraphRunnableConfig) => {
        // 流式传输任意数据
        config.writer?.(`Looking up data for city: ${input.city}`);
        // ... 获取城市数据
        config.writer?.(`Acquired data for city: ${input.city}`);
        return `It's always sunny in ${input.city}!`;
    },
    {
        name: "get_weather",
        description: "Get weather for a given city.",
        schema: z.object({
        city: z.string().describe("The city to get weather for."),
        }),
    }
);

const agent = createAgent({
    model: "gpt-5.4-mini",
    tools: [getWeather],
});

for await (const chunk of await agent.stream(
    { messages: [{ role: "user", content: "what is the weather in sf" }] },
    { streamMode: "custom" }
)) {
    console.log(chunk);
}
```

```shell title="Output"

Acquired data for city: San Francisco
```

<Note>
    如果你将 `writer` 参数添加到你的工具，你将无法在不提供写入器函数的情况下在 LangGraph 执行上下文之外调用该工具。
</Note>

## 流式传输多种模式

:::python
你可以通过将流模式作为列表传递来指定多种流式传输模式：`stream_mode=["updates", "custom"]`。

每个流式传输的块是一个带有 `type`、`ns` 和 `data` 键的 `StreamPart` 字典。使用 `chunk["type"]` 确定流模式，使用 `chunk["data"]` 访问 payload。

```python title="流式传输多种模式"
from langchain.agents import create_agent
from langgraph.config import get_stream_writer


def get_weather(city: str) -> str:
    """获取给定城市的天气。"""
    writer = get_stream_writer()
    writer(f"Looking up data for city: {city}")
    writer(f"Acquired data for city: {city}")
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="gpt-5-nano",
    tools=[get_weather],
)

for chunk in agent.stream(  # [!code highlight]
    {"messages": [{"role": "user", "content": "What is the weather in SF?"}]},
    stream_mode=["updates", "custom"],
    version="v2",  # [!code highlight]
):
    print(f"stream_mode: {chunk['type']}")  # [!code highlight]
    print(f"content: {chunk['data']}")  # [!code highlight]
    print("\n")
```

### 流式传输思考/推理 token

一些模型在产生最终答案之前进行内部推理。你可以通过过滤[标准内容块](/oss/langchain/messages#standard-content-blocks)中类型为 `"reasoning"` 的内容来在生成时流式传输这些思考/推理 token。

<Note>
推理输出必须在模型上启用。

请参阅[推理部分](/oss/langchain/models#reasoning)和你的[提供商集成页面](/oss/integrations/providers/overview)以获取配置详情。

要快速检查模型的推理支持，请参阅 [models.dev](https://models.dev)。
</Note>

:::python

要流式传输代理的思考 token，请使用 `stream_mode="messages"` 并过滤推理内容块：

<StreamingReasoningTokensPy />

```shell title="Output"

[thinking]  available to get this information. Let me call the get_weather tool
[thinking]  with "San Francisco" as the city parameter.

```

:::

要直接从聊天模型流式传输推理 token（不使用代理或图），请参阅[使用聊天模型进行流式传输](/oss/langchain/models#reasoning)。

### 流式传输工具调用

你可能希望流式传输两者：

1. 作为[工具调用](/oss/langchain/models#tool-calling)生成时的部分 JSON
2. 已执行的实际解析工具调用

指定 [`stream_mode="messages"`](#llm-tokens) 将流式传输由代理中所有大型语言模型调用生成的部分[消息块](/oss/langchain/messages#streaming-and-chunks)。要访问带有解析工具调用的已完成消息：

1. 如果那些消息被跟踪在[状态](/oss/langchain/agents#memory)中（如 [`create_agent`](/oss/langchain/agents) 的模型节点中），使用 `stream_mode=["messages", "updates"]` 通过[状态更新](#agent-progress)访问已完成消息（如下所示）。
2. 如果那些消息没有被跟踪在状态中，使用[自定义更新](#custom-updates)或在流式传输循环中聚合块（请参阅[下一节](#accessing-completed-messages)。

<Note>
如果你的代理包含多个大型语言模型，请参阅下面关于[从子代理流式传输](#streaming-from-sub-agents)的部分。
</Note>

```python
from typing import Any

from langchain.agents import create_agent
from langchain.messages import AIMessage, AIMessageChunk, AnyMessage, ToolMessage


def get_weather(city: str) -> str:
    """获取给定城市的天气。"""

    return f"It's always sunny in {city}!"


agent = create_agent("openai:gpt-5.4", tools=[get_weather])


def _render_message_chunk(token: AIMessageChunk) -> None:
    if token.text:
        print(token.text, end="|")
    if token.tool_call_chunks:
        print(token.tool_call_chunks)
    # N.B. all content is available through token.content_blocks


def _render_completed_message(message: AnyMessage) -> None:
    if isinstance(message, AIMessage) and message.tool_calls:
        print(f"Tool calls: {message.tool_calls}")
    if isinstance(message, ToolMessage):
        print(f"Tool response: {message.content_blocks}")


input_message = {"role": "user", "content": "What is the weather in Boston?"}
for chunk in agent.stream(
    {"messages": [input_message]},
    stream_mode=["messages", "updates"],  # [!code highlight]
    version="v2",  # [!code highlight]
):
    if chunk["type"] == "messages":  # [!code highlight]
        token, metadata = chunk["data"]  # [!code highlight]
        if isinstance(token, AIMessageChunk):
            _render_message_chunk(token)  # [!code highlight]
    elif chunk["type"] == "updates":  # [!code highlight]
        for source, update in chunk["data"].items():  # [!code highlight]
            if source in ("model", "tools"):  # `source` captures node name
                _render_completed_message(update["messages"][-1])  # [!code highlight]
```

#### 访问已完成的消息

<Note>
如果已完成的消息被跟踪在代理的[状态](/oss/langchain/agents#memory)中，你可以使用 `stream_mode=["messages", "updates"]` 正如在[流式传输工具调用](#streaming-tool-calls)部分演示的那样在流式传输期间访问已完成的消息。
</Note>

在某些情况下，已完成的消息不会反映在[状态更新](#agent-progress)中。如果你有权访问代理内部，你可以在流式传输期间使用[自定义更新](#custom-updates)访问这些消息。否则，你可以在流式传输循环中聚合消息块（请参阅下文）。

考虑下面的例子，我们在一个简化的[护栏中间件](/oss/langchain/guardrails#after-agent-guardrails)中加入流写入器。此中间件演示了工具调用以生成结构化的"safe / unsafe"评估（你也可以使用[结构化输出](/oss/langchain/models#structured-output)来实现）：
```python
from typing import Any, Literal

from langchain.agents.middleware import after_agent, AgentState
from langgraph.runtime import Runtime
from langchain.messages import AIMessage
from langchain.chat_models import init_chat_model
from langgraph.config import get_stream_writer  # [!code highlight]
from pydantic import BaseModel


class ResponseSafety(BaseModel):
    """将响应评估为安全或 unsafe。"""
    evaluation: Literal["safe", "unsafe"]


safety_model = init_chat_model("openai:gpt-5.4")

@after_agent(can_jump_to=["end"])
def safety_guardrail(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """基于模型的护栏：使用大型语言模型评估响应安全性。"""
    stream_writer = get_stream_writer()  # [!code highlight]
    # 获取模型响应
    if not state["messages"]:
        return None

    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage):
        return None

    # 使用另一个模型来评估安全性
    model_with_tools = safety_model.bind_tools([ResponseSafety], tool_choice="any")
    result = model_with_tools.invoke(
        [
            {
                "role": "system",
                "content": "Evaluate this AI response as generally safe or unsafe."
            },
            {
                "role": "user",
                "content": f"AI response: {last_message.text}"
            }
        ]
    )
    stream_writer(result)  # [!code highlight]

    tool_call = result.tool_calls[0]
    if tool_call["args"]["evaluation"] == "unsafe":
        last_message.content = "I cannot provide that response. Please rephrase your request."

    return None
```
然后我们可以将这个中间件合并到我们的代理中并包含其自定义流事件：

```python

    {"messages": [input_message]},
    stream_mode=["messages", "updates"],
    version="v2",  # [!code highlight]
):

        if isinstance(token, AIMessageChunk):
            _render_message_chunk(token)
            full_message = token if full_message is None else full_message + token  # [!code highlight]
            if token.chunk_position == "last":  # [!code highlight]

                _render_completed_message(update["messages"][-1])
```

### 流式传输与人在环

要处理人在环[中断](/oss/langchain/human-in-the-loop)，我们在上面的[以上示例](#streaming-tool-calls)基础上构建：

1. 我们使用[人在环中间件和检查点器](/oss/langchain/human-in-the-loop#configuring-interrupts)配置代理
2. 我们收集 `"updates"` 流模式期间产生的中断
3. 我们用[命令](/oss/langchain/human-in-the-loop#responding-to-interrupts)响应这些中断

```python
    if isinstance(message, ToolMessage):
```

### 从子代理流式传输

当代理中任何时候有多个大型语言模型时，通常需要区分消息源，因为它们是生成的。

为此，在创建时向每个代理传递一个 [`name`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent(name))。然后，在以 `"messages"` 模式流式传输时，可以通过 `lc_agent_name` 键在元数据中获取此名称。

下面，我们更新[流式传输工具调用](#streaming-tool-calls)示例：

1. 我们将工具替换为内部调用代理的 `call_weather_agent` 工具
2. 我们为每个代理添加一个 `name`
3. 我们在创建流时指定 [`subgraphs=True`](/oss/langgraph/use-subgraphs#stream-subgraph-outputs)
4. 我们的流处理与之前相同，但我们添加逻辑使用 `create_agent` 的 `name` 参数来跟踪活动代理

<Tip>
当你在代理上设置 `name` 时，该名称也会附加到该代理生成的任何 `AIMessage`s 上。
</Tip>


首先我们构建代理：

## 禁用流式传输

在某些应用中，你可能需要禁用单个 token 的流式传输。当：

- 使用[多代理](/oss/langchain/multi-agent)系统来控制哪些代理流式传输其输出
- 将支持流式传输的模型与不支持流式传输的模型混合
- 部署到 [LangSmith](/langsmith/home) 并希望防止某些模型输出被流式传输到客户端

:::python
初始化模型时设置 `streaming=False`。

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="gpt-5.4",
    streaming=False  # [!code highlight]
)
```
:::

:::js
初始化模型时设置 `streaming: false`。

```typescript
import { ChatOpenAI } from "@langchain/openai";

const model = new ChatOpenAI({
  model: "gpt-5.4",
  streaming: false,  // [!code highlight]
});
```
:::

<Tip>
部署到 LangSmith 时，在你不想流式传输到客户端的任何模型上设置 `streaming=False`。这在你的图形代码中配置，然后在部署前完成。
</Tip>

:::python
<Note>
并非所有聊天模型集成都支持 `streaming` 参数。如果你的模型不支持，请改用 `disable_streaming=True`。此参数可通过基类在所有聊天模型上使用。
</Note>
:::

:::js
<Note>
并非所有聊天模型集成都支持 `streaming` 参数。如果你的模型不支持，请改用 `disableStreaming: true`。此参数可通过基类在所有聊天模型上使用。
</Note>

## v2 流式传输格式

<Note>
需要 LangGraph >= 1.1。
</Note>

将 `version="v2"` 传递给 `stream()` 或 `astream()` 以获取统一的输出格式。每个块是一个带有 `type`、`ns` 和 `data` 键的 `StreamPart` 字典——无论流模式或模式数量如何，形状都相同：

<CodeGroup>
```python v2 (new)
# 统一格式 — 不再需要元组解包
for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "What is the weather in SF?"}]},
    stream_mode=["updates", "custom"],
    version="v2",
):
    print(chunk["type"])  # "updates" or "custom"
    print(chunk["data"])  # payload
```
```python v1 (current default)
# 必须解包 (mode, data) 元组
for mode, chunk in agent.stream(
    {"messages": [{"role": "user", "content": "What is the weather in SF?"}]},
    stream_mode=["updates", "custom"],
):
    print(mode)   # "updates" or "custom"
    print(chunk)  # payload
```
</CodeGroup>

v2 格式还改进了 `invoke()` — 它返回一个带有 `.value` 和 `.interrupts` 属性的 `GraphOutput` 对象，清晰地分离状态和中断元数据：

```python
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Hello"}]},
    version="v2",
)
print(result.value)       # state (dict, Pydantic model, or dataclass)
print(result.interrupts)  # tuple of Interrupt objects (empty if none)
```

请参阅 [LangGraph 流式传输文档](/oss/langgraph/streaming#stream-output-format-v2) 获取有关 v2 格式的更多详情，包括类型收窄、Pydantic/dataclass 强制转换和子图流式传输。
