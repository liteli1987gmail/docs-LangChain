本页解释 [LangChain 深度代理](/oss/deepagents/overview) 与 [Claude Agent SDK](https://platform.anthropic.com/docs/en/agent-sdk/overview) 的比较。两者都是用于构建自定义代理的 harness，但在执行环境、部署和供应商耦合方面做出了不同的权衡。

<Info>
深度代理被 [OpenSWE](https://github.com/langchain-ai/open-swe) 和 [LangSmith Fleet](/langsmith/fleet/index) 在生产中使用。
</Info>

## 一览

| | **深度代理** | **Claude Agent SDK** |
| --- | --- | --- |
| **代理运行在哪里** | 在沙箱内，或在沙箱外远程执行命令 | 在其运行的沙箱本地文件系统内 |
| **执行后端** | 可插拔：[本地、虚拟文件系统、远程沙箱或自定义](/oss/deepagents/backends) | 运行所在的沙箱的本地文件系统 |
| **模型提供商** | 任意（Anthropic、OpenAI、Google、100+ 其他） | Claude（Anthropic、Bedrock、Vertex、Azure） |
| **每个提供商/模型调优** | [Harness 配置文件](/oss/deepagents/profiles)（beta）：声明式 bundle 的系统提示词、工具、中间件和子代理调整，按提供商或特定模型注册 | 在每个模型调用站点通过代码配置 |
| **部署** | 通过 [`deepagents deploy`](/oss/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/langgraph/deploy)，或通过 [`langgraph build`](/langsmith/cli#build) 自托管[独立镜像](/langsmith/deploy-standalone-server) | [自托管](https://code.claude.com/docs/en/agent-sdk/hosting)。您构建服务器、身份验证和流式传输层。[Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview) 是单独的产品 |
| **多租户** | [内置](/oss/deepagents/going-to-production#multi-tenancy)：作用域线程、每用户沙箱、RBAC | 自己构建 |
| **许可证** | MIT | MIT（Claude Code 本身是专有的） |

## 主要差异

### 代理和执行环境

[有两种模式用于将代理连接到沙箱](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)：在沙箱**内部**运行代理，或在沙箱外部运行代理并**将沙箱用作工具**。

Claude Agent SDK 仅支持第一种。您的代理在沙箱内运行，并对沙箱的本地文件系统执行工具。Anthropic 的托管模型 [Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview) 使用解耦模型，这反映了生产代理架构的发展方向。

深度代理支持两者，并让您选择[后端](/oss/deepagents/backends#quickstart)来连接它们。实际上，这意味着您可以：

- 在沙箱内运行代理（与 Claude Agent SDK 相同的模式）。
- 在长寿命容器中运行代理并[将远程沙箱用作工具](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)，通过网络执行命令。
- 为测试交换虚拟文件系统，或为您自己的基础设施交换自定义后端。

### 多租户

当您将应用程序生产化时，您通常会将其暴露给许多最终用户，并且必须为每个用户隔离环境。

在 Claude Agent SDK 中，SDK 将代理与其沙箱绑定。要给每个用户提供隔离的执行环境，您必须构建一个 API 包装器，为每个用户旋转一个沙箱，跟踪哪个沙箱属于谁，然后在之后拆除它。

深度代理直接处理这个问题：在 harness 中为[每个用户或每个助手](/oss/deepagents/going-to-production#lifecycle)配置沙箱，包含作用域线程、运行历史和 [RBAC](/langsmith/rbac)。如果您使用 [LangSmith Sandbox](/langsmith/sandbox-auth-proxy)，您还可以开箱即用地获得一个身份验证代理，因此最终用户可以从沙箱调用第三方 API，而无需您为每个用户配置凭证。

### 生产代理服务器

要将[自托管 Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/hosting) 应用程序暴露给最终用户，您编写自己的 HTTP/WebSocket 或 SSE 服务器，调用代理、将 token 流回并管理对话线程。那个服务器由您构建、运营和保护。

深度代理部署包含开箱即用的[代理服务器](/langsmith/agent-server)：流式端点、线程管理、运行历史、Webhook 和[身份验证](/langsmith/auth)。

### 托管云或自托管

Claude Agent SDK 部署是[自托管](https://code.claude.com/docs/en/agent-sdk/hosting) 的。SDK 和 [Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview) 是单独的产品。针对 SDK 编写的代码不能直接部署到托管产品。

深度代理可以在两种模式下运行，无需代码更改：

- **托管：** 使用 [`deepagents deploy`](/oss/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/langgraph/deploy)。
- **自托管：** 运行 [`langgraph build`](/langsmith/cli#build) 生成一个[独立 Docker 镜像](/langsmith/deploy-standalone-server)，您可以部署到任何地方。

<Tip>
[Claude 托管代理](https://platform.claude.com/docs/en/managed-agents/overview) 在 Anthropic 生态系统内运作良好；对于 LangChain 中类似的低摩擦、模型无关路径，请使用 [LangSmith Fleet](/langsmith/fleet/index)。
</Tip>

### LLM

Claude Agent SDK 执行捆绑模型、后端和部署，并优化所有三者之间的支持。

使用深度代理，您独立选择模型提供商、执行后端和部署目标。通过选择这个 harness，您可以保留模型和基础设施选择的最大灵活性。

### 生态系统

Claude Agent SDK 专为 Claude 和 Anthropic 的产品表面而构建。如果您已经标准化使用 Anthropic 生态系统（Claude API 和相关平台功能），保持在官方 SDK 上可能意味着更少的移动部件、一个供应商提供代理功能和支持，以及端到端相同堆栈的文档。

## 总结

- **选择深度代理**，如果您想要模型和基础设施灵活性、内置多租户部署，以及无需代码更改即可托管或自托管的选项。
- **选择 Claude Agent SDK**，如果您已经投资于 Anthropic 生态系统并希望自托管并自己构建 API、身份验证和多租户层。
