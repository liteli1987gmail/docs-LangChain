## 拉取请求要求

<Warning>
    **所有拉取请求必须链接到一个 issue 或讨论，其中维护者已批准解决方案。** 未经事先批准的 PR 将被关闭。
</Warning>

所有拉取请求都应该展示有意义的努力和上下文理解。**如果创建拉取请求所需的努力少于维护者审查它所需的努力，则不应提交该贡献。** 低投入的顺便贡献——无论它们是如何产生的——在上下文相关性、准确性和质量方面往往达不到目标。大规模自动贡献对我们的工作量来说是一种拒绝服务攻击。

所有外部拉取请求必须满足以下要求：

* 拉取请求必须链接到一个 issue 或讨论，其中维护者已批准解决方案。
* 拉取请求必须填写仓库的拉取请求模板。

如果这些要求未满足，维护者有权在不评论的情况下关闭 PR。**我们将关闭看起来是低投入垃圾邮件的拉取请求和问题。**

## 语言政策

所有贡献——问题、拉取请求、代码审查和讨论——必须使用英语。这使我们的全球贡献者社区可以访问和搜索通信。

如果英语不是你的第一语言，不用担心。我们重视清晰沟通胜过完美语法，欢迎使用翻译工具。

## 可接受的 LLM 使用

你可以在**验证每个更改**时使用 AI 助手帮助起草或修改贡献：运行和测试代码，根据代码库和官方提供商文档检查事实，并确保结果符合仓库风格。不要提交批量、未审查生成的内容。无论如何产生的，我们都会关闭看起来是低投入或垃圾邮件的拉取请求。
