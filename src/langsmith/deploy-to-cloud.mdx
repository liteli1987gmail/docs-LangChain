这是将应用程序部署到 LangSmith Cloud 的综合设置和管理指南。它涵盖两种部署方法：[LangSmith UI](https://smith.langchain.com)，它从连接的 GitHub 仓库部署，以及 [`langgraph deploy` CLI 命令](/langsmith/cli#deploy)，它直接从本地机器构建和推送。

<Callout icon="bolt" color="#4F46E5" iconType="regular">
**如果您正在寻找快速设置**，请先尝试[快速入门指南](/langsmith/deployment-quickstart)。
</Callout>

在设置之前，请查看[云概述页面](/langsmith/cloud)以了解云托管模型。

## 先决条件

- [Plus 计划或更高版本](https://www.langchain.com/pricing)上的 LangSmith 帐户。
- [验证 LangGraph API 是否在本地运行](/langsmith/local-dev-testing)。如果 API 未成功运行（即 `langgraph dev`），则部署到 LangSmith 也将失败。

## 创建新部署

选择适合您工作流的部署方法——LangSmith UI 连接到 GitHub 仓库并支持推送时自动部署，而 `langgraph deploy` CLI 命令直接从本地项目目录构建和部署。

<Tabs>
  <Tab title="LangSmith UI">
    <Note>
    **需要一次性设置**：GitHub 组织所有者或管理员必须在 LangSmith UI 中完成 OAuth 流程，以授权 `hosted-langserve` GitHub 应用程序。这每个工作区只需完成一次。初始 OAuth 授权后，所有具有部署权限的开发人员都可以创建和管理部署，无需 GitHub 管理员访问权限。
    </Note>

    从 [LangSmith UI](https://smith.langchain.com) 开始，在左侧导航面板中选择 **Deployments**。在右上角，选择 **+ New Deployment** 创建一个新部署：

    1. 在 **Create New Deployment** 面板中，填写必填字段。对于 **Deployment details**：
        1. 选择 **Import from GitHub** 并遵循 GitHub OAuth 工作流来安装和授权 LangChain 的 `hosted-langserve` GitHub 应用程序以访问选定的仓库。安装完成后，返回 **Create New Deployment** 面板并从下拉菜单中选择要部署的 GitHub 仓库。
            <Note> 安装 LangChain 的 `hosted-langserve` GitHub 应用程序的 GitHub 用户必须是组织的[所有者](https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization#organization-owners)或帐户。此授权每个 LangSmith 工作区只需完成一次——后续部署可以由任何具有部署权限的用户创建。</Note>
        1. 指定部署的名称。
        1. 指定所需的 **Git Branch**。部署链接到一个分支。创建新修订版时，链接分支的代码将被部署。以后可以在 [Deployment Settings](#deployment-settings) 中更新分支。
        1. 指定[LangGraph API 配置文件](/langsmith/cli#configuration-file)的完整路径，包括文件名。例如，如果文件 `langgraph.json` 在仓库的根目录中，请指定 `langgraph.json`。
        1. 使用复选框 **Automatically update deployment on push to branch**。如果选中，则在将更改推送到指定 **Git Branch** 时，部署将自动更新。您可以在 [LangSmith UI](https://smith.langchain.com) 的 [Deployment Settings](#deployment-settings) 中启用或禁用此设置。
        对于 **Deployment Type**：
            - Development 部署适用于非生产用例，并使用最少资源进行配置。
            - Production 部署可以处理多达 500 请求/秒，并配置了具有自动备份的高可用性存储。
        1. 确定部署是否应该 **Shareable through Studio**。
            1. 如果未选中，部署只能通过[工作区](/langsmith/administration-overview#workspaces)的有效 LangSmith API 密钥访问。
            1. 如果选中，部署将通过 [Studio](/langsmith/studio) 对任何 LangSmith 用户可访问。将提供一个直接 URL 以与其他 LangSmith 用户共享。
        1. 指定 **Environment Variables** 和 secrets。要为部署配置其他变量，请参阅[环境变量参考](/langsmith/env-var)。
            1. 敏感值（如 API 密钥，例如 `OPENAI_API_KEY`）应指定为 secrets。
            1. 也可以指定其他非秘密环境变量。
        1. 将使用与部署相同的名称自动创建一个新的 LangSmith[追踪项目](/langsmith/observability)。
    1. 在右上角，选择 **Submit**。几秒钟后，**Deployment** 视图出现，新部署将排队等待配置。
  </Tab>
  <Tab title="LangGraph CLI">
    <Note>
    `langgraph deploy` 命令处于**测试阶段**。它需要安装并运行 [Docker](https://docs.docker.com/get-docker/)。在 Apple Silicon（M1/M2/M3）上，还需要 [Docker Buildx](https://docs.docker.com/build/install-buildx/) 用于交叉编译到 `linux/amd64`。
    </Note>

    1. 安装 [LangGraph CLI](/langsmith/cli)：
        ```shell
        uv tool install langgraph-cli
        ```
    1. 将您的 LangSmith API 密钥添加到项目根目录的 `.env` 文件中：
        ```shell
        LANGSMITH_API_KEY=lsv2_...
        ```
    1. 从项目目录运行部署命令：
        ```shell
        langgraph deploy
        ```
        这会创建一个以项目目录命名的 `dev` 部署。使用 `--name` 指定不同名称或 `--deployment-type prod` 进行生产部署：
        ```shell
        langgraph deploy --name my-agent --deployment-type prod
        ```
        命令完成后，部署将排队等待配置。部署创建后，可以通过 [LangSmith UI](https://smith.langchain.com) 或在 [`langgraph.json` 的 `env` 字段中](/langsmith/cli#configuration-file)配置环境变量。
  </Tab>
</Tabs>

## 创建新修订版

创建[新部署](#create-new-deployment)时，默认会创建一个新修订版。您可以创建后续修订版以部署新的代码更改。

<Tabs>
  <Tab title="LangSmith UI">
    从 [LangSmith UI](https://smith.langchain.com) 开始，在左侧导航面板中选择 **Deployments**。选择一个现有部署以为其创建新修订版。

    1. 在 **Deployment** 视图中，在右上角选择 **+ New Revision**。
    1. 在 **New Revision** 模态框中，填写必填字段。
        1. 指定[API 配置文件](/langsmith/cli#configuration-file)的完整路径，包括文件名。例如，如果文件 `langgraph.json` 在仓库的根目录中，请指定 `langgraph.json`。
        1. 确定部署是否应该 **Shareable through Studio**。
            - 如果未选中，部署只能通过[工作区](/langsmith/administration-overview#workspaces)的有效 LangSmith API 密钥访问。
            - 如果选中，部署将通过 [Studio](/langsmith/studio) 对任何 LangSmith 用户可访问。将提供一个直接 URL 以与其他 LangSmith 用户共享。
        1. 指定 **Environment Variables** 和 secrets。现有 secrets 和环境变量会被预填充。要为修订版配置其他变量，请参阅[环境变量参考](/langsmith/env-var)。
            1. 添加新的 secrets 或环境变量。
            1. 删除现有的 secrets 或环境变量。
            1. 更新现有 secrets 或环境变量的值。
    1. 选择 **Submit**。几秒钟后，**New Revision** 模态框将关闭，新修订版将排队等待部署。
  </Tab>
  <Tab title="LangGraph CLI">
    从项目目录重新运行 `langgraph deploy`。该命令通过名称找到现有部署并使用最新代码更改创建新修订版：

    ```shell
    langgraph deploy
    ```

    要按 ID 而不是名称定位特定部署，请使用 `--deployment-id`：

    ```shell
    langgraph deploy --deployment-id <DEPLOYMENT_ID>
    ```

    使用 `langgraph deploy list` 查看所有部署并找到其 ID：

    ```shell
    langgraph deploy list
    ```

    <Note>
    `langgraph deploy` 只能更新最初由 `langgraph deploy` 创建的部署。通过 LangSmith UI 或 GitHub 集成创建的部署无法使用此命令更新。
    </Note>
  </Tab>
</Tabs>

## 查看构建和服务器日志

每个修订版都有可用的构建和服务器日志。

<Tabs>
  <Tab title="LangSmith UI">
    从 **Deployments** 视图开始：

    1. 从 **Revisions** 表中选择所需的修订版。面板从右侧滑出，默认选择 **Build** 选项卡，显示修订版的构建日志。
    1. 在面板中，选择 **Server** 选项卡以查看修订版的服务器日志。服务器日志仅在修订版部署后才可用。
    1. 在 **Server** 选项卡中，根据需要调整日期/时间范围选择器。默认情况下，日期/时间范围选择器设置为 **Last 7 days**。
  </Tab>
  <Tab title="LangGraph CLI">
    使用 `langgraph deploy logs` 获取部署的日志。

    查看服务器（运行时）日志：

    ```shell
    langgraph deploy logs
    ```

    查看构建日志：

    ```shell
    langgraph deploy logs --type build
    ```

    连续尾随日志：

    ```shell
    langgraph deploy logs --follow
    ```

    按时间范围、日志级别或搜索字符串筛选日志：

    ```shell
    langgraph deploy logs --start-time 2026-03-01T00:00:00Z --level ERROR
    ```

    如果您有多个部署，按名称或 ID 指定目标：

    ```shell
    langgraph deploy logs --name my-agent
    langgraph deploy logs --deployment-id <DEPLOYMENT_ID>
    ```

    有关所有可用选项，请参阅[`deploy logs` CLI 参考](/langsmith/cli#deploy-logs)。
  </Tab>
</Tabs>

## 查看部署指标

部署上线后，您可以从 [LangSmith UI](https://smith.langchain.com) 监控其性能。

从 LangSmith UI 开始：

1. 在左侧导航面板中选择 **Deployments**。
1. 选择要监控的现有部署。
1. 选择 **Monitoring** 选项卡以查看部署指标。请参阅[所有可用指标](/langsmith/control-plane#monitoring)列表。
1. 在 **Monitoring** 选项卡中，根据需要使用日期/时间范围选择器。默认情况下，日期/时间范围选择器设置为 **Last 15 minutes**。

## 中断修订版

中断修订版将停止修订版的部署。

<Warning>
**未定义行为**
中断的修订版具有未定义的行为。这仅在您需要部署新修订版但已有修订版"卡住"时才有用。将来，此功能可能会被删除。
</Warning>

从 **Deployments** 视图开始：

1. 从 **Revisions** 表中所需修订版行右侧选择菜单图标（三个点）。
1. 从菜单中选择 **Interrupt**。
1. 将出现一个模态框。查看确认消息。选择 **Interrupt revision**。

## 删除部署

<Tabs>
  <Tab title="LangSmith UI">
    从 [LangSmith UI](https://smith.langchain.com) 开始：

    1. 在左侧导航面板中选择 **Deployments**，其中包含现有部署列表。
    1. 选择所需部署行右侧的菜单图标（三个点）并选择 **Delete**。
    1. 将出现 **Confirmation** 模态框。选择 **Delete**。
  </Tab>
  <Tab title="LangGraph CLI">
    使用 `langgraph deploy list` 找到要删除的部署的 ID：

    ```shell
    langgraph deploy list
    ```

    然后按 ID 删除：

    ```shell
    langgraph deploy delete <DEPLOYMENT_ID>
    ```

    要跳过确认提示，请使用 `--force`：

    ```shell
    langgraph deploy delete --force <DEPLOYMENT_ID>
    ```
  </Tab>
</Tabs>

## 部署设置

从 **Deployments** 视图开始：

1. 在右上角选择齿轮图标（**Deployment Settings**）。
1. 将 `Git Branch` 更新为所需的分支。
1. 选中/取消选中复选框 **Automatically update deployment on push to branch**。
    1. 分支创建/删除和标签创建/删除事件不会触发更新。只有对现有分支的推送才会触发更新。
    1. 快速连续推送到分支将排队后续更新。一旦构建完成，最近的提交将开始构建，其他排队的构建将被跳过。

## 添加或删除 GitHub 仓库

安装并授权 LangChain 的 `hosted-langserve` GitHub 应用程序后，可以修改应用程序的仓库访问权限以添加新仓库或删除现有仓库。如果创建了新仓库，可能需要明确添加。

1. 从 GitHub 个人资料中，导航到 **Settings** > **Applications** > `hosted-langserve` > 点击 **Configure**。
1. 在 **Repository access** 下，选择 **All repositories** 或 **Only select repositories**。如果选择了 **Only select repositories**，则必须明确添加新仓库。
1. 点击 **Save**。
1. 创建新部署时，下拉菜单中的 GitHub 仓库列表将更新以反映仓库访问权限的更改。
