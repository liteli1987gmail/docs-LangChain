下面，我们将讨论对几种流行类型 LLM 应用程序的评估。

## 代理

[由 LLM 驱动的自主代理](https://lilianweng.github.io/posts/2023-06-23-agent/)结合了三个组件：（1）工具调用、（2）记忆和（3）规划。代理使用工具调用（通常通过提示进行规划）和记忆（例如，通常是短期消息历史）来生成响应。[工具调用](https://docs.langchain.com/oss/python/langchain/tools)允许模型通过生成两件事来响应给定提示：（1）要调用的工具和（2）所需的输入参数。

![工具使用](/langsmith/images/tool-use.png)

下面是 [LangGraph](https://langchain-ai.github.io/langgraph/tutorials/introduction/) 中的一个工具调用代理。`assistant 节点` 是一个 LLM，用于根据输入决定是否调用工具。`tool condition` 查看是否有工具被 `assistant 节点` 选中，如果有，则路由到 `tool 节点`。`tool 节点` 执行工具并将输出作为工具消息返回给 `assistant 节点`。只要 `assistant 节点` 选择工具，此循环就会继续。如果未选择工具，则代理直接返回 LLM 响应。

![代理](/langsmith/images/langgraph-agent.png)

这为用户通常感兴趣的三种一般类型的代理评估设置了条件：

* `最终响应`：评估代理的最终响应。
* `单步`：单独评估任何代理步骤（例如，是否选择了适当的工具）。
* `轨迹`：评估代理是否采取了预期路径（例如，工具调用）来达到最终答案。

![代理评估](/langsmith/images/agent-eval.png)

下面我们将介绍这些是什么，每个所需的组件（输入、输出、评估器），以及您应该何时考虑这些。请注意，您可能希望进行多种（如果不是全部！）这些类型的评估——它们并不相互排斥！

### 评估代理的最终响应

评估代理的一种方法是评估其在任务上的整体性能。这基本上涉及将代理视为黑盒，简单地评估它是否完成任务。

输入应该是用户输入和（可选）工具列表。在某些情况下，工具是硬编码为代理的一部分，不需要传入。在其他情况下，代理更通用，这意味着它没有固定的工具集，需要在运行时传入工具。

输出应该是代理的最终响应。

评估器根据您要求代理完成的任务而有所不同。许多代理执行相对复杂的步骤集，输出是最终的文本响应。与 RAG 类似，LLM-as-judge 评估器通常对评估这些情况有效，因为它们可以直接从文本响应评估代理是否完成了工作。

但是，这种评估类型有几个缺点。首先，它通常需要一段时间才能运行。其次，您没有评估代理内部发生的任何事情，因此很难调试失败发生的位置。第三，有时可能很难定义适当的评估指标。

### 评估代理的单个步骤

代理通常执行多个操作。虽然端到端评估它们很有用，但评估这些单独的操作也很有用。这通常涉及评估代理的单个步骤——即决定下一步做什么的 LLM 调用。

输入应该是单个步骤的输入。根据您正在测试的内容，这可能只是原始用户输入（例如，提示和/或一组工具），也可以包括先前完成的步骤。

输出只是该步骤的输出，这通常是 LLM 响应。LLM 响应通常包含工具调用，指示代理下一步应采取什么行动。

这方面的评估器通常是一些二元分数，用于判断是否选择了正确的工具调用，以及工具输入是否正确的某些启发式。参考工具可以简单地指定为字符串。

这种评估类型有几个好处。它允许您评估单独的操作，这让您能够专注于应用程序可能失败的环节。它们也相对快速运行（因为它们只涉及单个 LLM 调用），评估通常使用相对于参考工具的工具选择的简单启发式评估。一个缺点是它们没有捕获完整的代理——只有一个特定的步骤。另一个缺点是数据集创建可能具有挑战性，特别是如果您想在代理输入中包含历史记录。对于代理轨迹早期的步骤创建数据集非常容易（例如，这可能只包括输入提示），但对于轨迹后期的步骤创建数据集可能很困难（例如，包括许多先前的代理操作和响应）。

### 评估代理的轨迹

评估代理的轨迹涉及评估代理采取的所有步骤。

输入再次是整体代理的输入（用户输入，以及可选的工具列表）。

输出是工具调用的列表，可以表述为"精确"轨迹（例如，工具调用的预期顺序）或简单地是预期的工具调用集（以任何顺序）。

这里的评估器是所采取步骤的某种函数。评估"精确"轨迹可以使用单个二元分数来确认序列中每个工具名称的精确匹配。这很简单，但有一些缺陷。有时可能有多种正确的路径。这种评估也无法捕获轨迹偏离单个步骤与完全错误的轨迹之间的差异。

为了解决这些缺陷，评估指标可以集中在采取的"不正确"步骤的数量上，这更好地解释了接近与显著偏离的轨迹。评估指标也可以集中在是否以任何顺序调用了所有预期的工具。

但是，这些方法都没有评估工具的输入；它们只关注所选的工具。为了说明这一点，另一种评估技术是将完整代理的轨迹（以及参考轨迹）作为一组消息（例如，所有 LLM 响应和工具调用）传递给 LLM-as-judge。这可以评估代理的完整行为，但这是最难编译的参考（幸运的是，使用 LangGraph 这样的框架可以提供帮助！）。另一个缺点是评估指标可能有点棘手提出。

## 检索增强生成（RAG）

检索增强生成（RAG）是一种通过根据用户输入检索相关文档并将其传递给语言模型进行处理来增强大型语言模型的有力技术。RAG 使 AI 应用程序能够通过利用外部知识生成更知情和上下文相关的响应。

<Info>
有关 RAG 概念的全面评论，请参阅我们的[`RAG From Scratch` 系列](https://github.com/langchain-ai/rag-from-scratch)。
</Info>

### 数据集

在评估 RAG 应用程序时，一个关键考虑因素是您是否拥有（或可以轻松获取）每个输入问题的参考答案。参考答案作为评估生成响应正确性的基本事实。然而，即使没有参考答案，仍然可以执行各种评估使用不需要参考答案的免参考 RAG 评估提示（如下例所示）。

### 评估器

`LLM-as-judge` 是 RAG 常用的评估器，因为它是评估文本之间的事实准确性或一致性的有效方式。

![rag-types.png](/langsmith/images/rag-types.png)

在评估 RAG 应用程序时，您可以有需要参考输出和不需要参考输出的评估器：

1. **需要参考输出**：将 RAG 链生成的答案或检索与参考答案（或检索）进行比较以评估其正确性。
2. **不需要参考输出**：使用不需要参考答案的提示执行自一致性检查（在上图中用橙色、绿色和红色表示）。

### 应用 RAG 评估

应用 RAG 评估时，请考虑以下方法：

1. `离线评估`：对任何依赖参考答案的提示使用离线评估。这最常用于 RAG 答案正确性评估，其中参考是基本事实（正确）答案。

2. `在线评估`：对任何免参考提示使用在线评估。这允许您评估实时场景中 RAG 应用程序的性能。

3. `成对评估`：利用成对评估来比较不同 RAG 链生成的答案。此评估侧重于用户指定的标准（例如，答案格式或样式）而非正确性，可以使用自一致性或基本事实参考进行评估。

### RAG 评估摘要

| 评估器           | 详情                                            | 需要参考输出 | LLM-as-judge？                                                                         | 成对相关 |
| ------------------- | -------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------- | ----------------- |
| 文档相关性  | 文档与问题相关吗？           | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/rag-document-relevance)   | 否                |
| 答案忠实性 | 答案基于文档吗？          | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/rag-answer-hallucination) | 否                |
| 答案有用性  | 答案有助于解决问题吗？        | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/rag-answer-helpfulness)   | 否                |
| 答案正确性  | 答案与参考答案一致吗？ | 是                    | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/rag-answer-vs-reference)  | 否                |
| 成对比较 | 多个答案版本如何比较？          | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/pairwise-evaluation-rag)  | 是               |

## 摘要

摘要是特定类型的自由形式写作。评估目标通常是根据一组标准检查写作（摘要）。

通常使用文本的`开发者策划示例`进行评估摘要（请参阅[摘要数据集示例](https://smith.langchain.com/public/659b07af-1cab-4e18-b21a-91a69a4c3990/d)）。但是，可以将生产（摘要）应用程序的`用户日志`与以下任何`免参考`评估提示用于在线评估。

`LLM-as-judge` 通常用于评估摘要（以及其他类型的写作），使用遵循提供标准的`免参考`提示对摘要进行评分。提供特定`参考`摘要较少见，因为摘要是创造性任务，可能有許多可能的正确答案。

`在线`或`离线`评估都是可行的，因为使用了`免参考`提示。`成对`评估也是在不同的摘要链（例如，不同的摘要提示或 LLM）之间执行比较的强大方式：

| 用例         | 详情                                                                     | 需要参考输出 | LLM-as-judge？                                                                                | 成对相关 |
| ---------------- | -------------------------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------- | ----------------- |
| 事实准确性 | 摘要相对于源文档准确吗？                  | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/summary-accurancy-evaluator)     | 是               |
| 忠实性     | 摘要是基于源文档的吗（例如，没有幻觉）？ | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/summary-hallucination-evaluator) | 是               |
| 有用性      | 摘要有助于用户需求吗？                                  | 否                     | 是 - [提示](https://smith.langchain.com/hub/langchain-ai/summary-helpfulness-evaluator)   | 是               |

## 分类和标记

分类和标记对给定输入应用标签（例如，用于毒性检测、情感分析等）。分类/标记评估通常采用以下组件，下面我们将详细回顾：

分类/标记评估的核心考虑因素是您是否有带有`参考`标签的数据集。如果没有，用户通常希望定义一个使用标准的评估器来将标签（例如，毒性等）应用于输入（例如，文本、用户问题等）。但是，如果提供了基本事实类标签，则评估目标集中在相对于基本事实类标签（例如，使用精确度、召回率等指标）对分类/标记链进行评分。

如果提供了基本事实参考标签，则通常简单地定义一个[自定义启发式评估器](/langsmith/code-evaluator-ui)来将基本事实标签与链输出进行比较。然而，鉴于 LLM 的出现，简单地使用 `LLM-as-judge` 执行基于指定标准的输入分类/标记（没有基本事实参考）变得越来越普遍。

当使用带有 `免参考` 提示的 `LLM-as-judge` 时，`在线`或`离线`评估都是可行的。特别地，当用户想要标记/分类应用程序输入（例如，用于毒性等）时，这非常适合`在线`评估。

| 用例  | 详情              | 需要参考输出 | LLM-as-judge？ | 成对相关 |
| --------- | ------------------- | ---------------------- | ------------- | ----------------- |
| 精确度  | 标准定义 | 是                    | 否            | 否                |
| 精确率 | 标准定义 | 是                    | 否            | 否                |
| 召回率    | 标准定义 | 是                    | 否            | 否                |
