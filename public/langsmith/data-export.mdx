<Info>
**计划限制适用**

请注意，数据导出功能仅支持 [LangSmith Plus 或 Enterprise 层级](https://www.langchain.com/pricing-langsmith)。
</Info>

LangSmith 的批量数据导出允许您将追踪数据从特定项目和日期范围导出到 S3 兼容的存储桶，格式为 [Parquet](https://parquet.apache.org/docs/overview/)，与[运行数据格式](/langsmith/run-data-format)中的字段匹配。这对于在 BigQuery、Snowflake、Redshift 或 Jupyter Notebooks 等工具中进行离线分析很有用。

本页涵盖如何：

- 创建导出目标
- 创建和配置导出作业，包括计划导出和字段过滤
- 监控导出进度

**在开始之前：** 根据数据量，导出可能需要一些时间，LangSmith 限制可以同时运行的导出数量。批量导出有 72 小时的运行时超时——请参阅[自动重试行为](/langsmith/data-export-monitor#automatic-retry-behavior)了解详情。启动后，LangSmith 自动处理导出的编排和[弹性](/langsmith/data-export-monitor#failure-modes-and-retry-policy)。

## 1. 创建目标

目标告诉 LangSmith 将导出数据写入何处。在发出此请求之前，您需要：

- 您的 [LangSmith API 密钥](/langsmith/create-account-api-key) 和[工作区 ID](/langsmith/set-up-hierarchy#set-up-a-workspace)。
- 授予 LangSmith **写入权限**的 S3 或 S3 兼容存储桶（请参阅[所需权限](/langsmith/data-export-destinations#permissions-required)）。
- 存储桶名称、前缀，以及 AWS 区域（用于 AWS S3）或端点 URL（用于 GCS、MinIO 或其他 S3 兼容提供商）。
- 存储桶的访问密钥和秘密密钥。

```bash
curl --request POST \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports/destinations' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID' \
  --data '{
    "destination_type": "s3",
    "display_name": "My S3 Destination",
    "config": {
      "bucket_name": "your-s3-bucket-name",
      "prefix": "root_folder_prefix",
      "region": "your aws s3 region",
      "endpoint_url": "your endpoint url for s3 compatible buckets"
    },
    "credentials": {
      "access_key_id": "YOUR_S3_ACCESS_KEY_ID",
      "secret_access_key": "YOUR_S3_SECRET_ACCESS_KEY"
    }
  }'
```

凭据以加密形式安全存储。API 将在保存前验证目标和凭据是否有效。如果请求失败，请参阅[调试目标错误](/langsmith/data-export-destinations#debug-destination-errors)。

保存响应中的 `id`；在创建导出作业时需要它。

请参阅[管理批量导出目标](/langsmith/data-export-destinations)了解权限设置、提供商特定配置（AWS S3、GCS、MinIO）和凭据选项。

## 2. 创建导出作业

导出作业针对特定项目和日期范围。您将需要：

- [上一步](#1-create-a-destination)中的目标 `id`。
- 项目 ID（`session_id`）——从 [**Tracing Projects** 列表](https://smith.langchain.com)中的各个项目视图复制。
- UTC ISO 8601 格式的 `start_time` 和 `end_time`。

```bash
curl --request POST \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID' \
  --data '{
    "bulk_export_destination_id": "your_destination_id",
    "session_id": "project_uuid",
    "start_time": "2024-01-01T00:00:00Z",
    "end_time": "2024-01-03T00:00:00Z",
    "format_version": "v2_beta"
  }'
```

`start_time` 是包含性的，`end_time` 是排除性的。导出将包括所有 `run.start_time >= start_time` 和 `run.start_time < end_time` 的运行。

保存响应中的 `id` 以监控导出的进度。

您可以选择添加 `filter` 表达式来缩小导出的运行集。请参阅我们的[过滤查询语言](/langsmith/trace-query-syntax#filter-query-language)和[示例](/langsmith/export-traces#use-filter-query-language)了解语法。不设置 `filter` 字段将导出所有运行。

### 安排定期导出

<Note>
需要 LangSmith Helm 版本 >= `0.10.42`（应用程序版本 >= `0.10.109`）
</Note>

定期导出定期收集运行并导出到配置的目标。要创建定期导出，请包含 `interval_hours` 并省略 `end_time`：

```bash
curl --request POST \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID' \
  --data '{
    "bulk_export_destination_id": "your_destination_id",
    "session_id": "project_uuid",
    "start_time": "2024-01-01T00:00:00Z",
    "interval_hours": 1,
    "format_version": "v2_beta"
  }'
```

- `interval_hours` 必须在 1 到 168（1 周）之间（含）。
- 定期导出必须省略 `end_time`；一次性导出仍需要它。
- 每个生成的导出覆盖 `start_time` 到 `start_time + interval_hours`，然后每次后续运行按 `interval_hours` 推进。由于 `end_time` 是排除性的，连续导出不会重叠。
- 生成的导出在 `end_time + 10 分钟` 运行，以考虑最近以 `end_time` 提交的运行。
- 生成的导出具有填充的 `source_bulk_export_id` 属性。如果需要，必须单独取消——取消源导出**不会**取消已生成的导出。
- 要停止定期导出，[取消它](/langsmith/data-export-monitor#stop-an-export)。

**示例**

如果创建定期批量导出时 `start_time=2025-07-16T00:00:00Z` 和 `interval_hours=6`：

| 导出 | 开始时间 | 结束时间 | 运行时间 |
| ------ | -------------------- | -------------------- | -------------------- |
| 1      | 2025-07-16T00:00:00Z | 2025-07-16T06:00:00Z | 2025-07-16T06:10:00Z |
| 2      | 2025-07-16T06:00:00Z | 2025-07-16T12:00:00Z | 2025-07-16T12:10:00Z |
| 3      | 2025-07-16T12:00:00Z | 2025-07-16T18:00:00Z | 2025-07-16T18:10:00Z |

### 限制导出字段

<Note>
需要 LangSmith Helm 版本 >= `0.12.11`（应用程序版本 >= `0.12.42`）。在一次性导出和定期导出中都支持。
</Note>

您可以使用 `export_fields` 参数限制包含的字段来提高导出速度并减小文件大小。省略时，将包含所有字段。

```bash
curl --request POST \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID' \
  --data '{
    "bulk_export_destination_id": "your_destination_id",
    "session_id": "project_uuid",
    "start_time": "2024-01-01T00:00:00Z",
    "end_time": "2024-01-03T00:00:00Z",
    "export_fields": ["id", "name", "run_type", "start_time", "end_time", "status", "total_tokens", "total_cost"],
    "format_version": "v2_beta"
  }'
```

<Tip>
排除 `inputs` 和 `outputs` 可以显著提高导出性能并减小文件大小，特别是对于大型运行。仅在分析需要这些字段时才包含它们。
</Tip>

### 可导出字段

默认情况下，批量导出为每个运行包含以下字段：

**标识符和层次结构：**

| 字段 | 描述 |
|-------|-------------|
| `id` | 运行 ID |
| `tenant_id` | 工作区/租户 ID |
| `session_id` | 项目/会话 ID |
| `trace_id` | 追踪 ID |
| `parent_run_id` | 父运行 ID |
| `parent_run_ids` | 所有父运行 ID 的列表 |
| `reference_example_id` | 如果是数据集的一部分，则为示例的引用 |

**基本元数据：**

| 字段 | 描述 |
|-------|-------------|
| `name` | 运行名称 |
| `run_type` | 运行类型（例如"chain"、"llm"、"tool"） |
| `start_time` | 开始时间戳（UTC） |
| `end_time` | 结束时间戳（UTC） |
| `status` | 运行状态（例如"success"、"error"） |
| `is_root` | 这是否是根级运行 |
| `dotted_order` | 层次排序字符串 |
| `trace_tier` | 追踪层级/保留级别 |

**运行数据：**

| 字段 | 描述 |
|-------|-------------|
| `inputs` | 运行输入（JSON） |
| `outputs` | 运行输出（JSON） |
| `error` | 失败时的错误消息 |
| `extra` | 额外元数据（JSON） |
| `events` | 运行事件（JSON） |

**标签和反馈：**

| 字段 | 描述 |
|-------|-------------|
| `tags` | 标签列表 |
| `feedback_stats` | 反馈统计（JSON）。请参阅以下关于聚合限制的说明。 |

<Note>
**`feedback_stats` 聚合限制**

`feedback_stats` 字段仅包括字符串类型反馈的值细分。非字符串值（数字、布尔值、复杂类型）的反馈不包括在这些细分中。要分析非字符串反馈值，请单独导出原始反馈数据。
</Note>

**令牌使用量和成本：**

| 字段 | 描述 |
|-------|-------------|
| `total_tokens` | 总令牌数 |
| `prompt_tokens` | 提示令牌数 |
| `completion_tokens` | 完成令牌数 |
| `total_cost` | 总成本 |
| `prompt_cost` | 提示成本 |
| `completion_cost` | 完成成本 |
| `first_token_time` | 首个令牌时间 |

### 分区方案

数据使用以下 Hive 分区结构导出到您的存储桶：

```
<bucket>/<prefix>/export_id=<export_id>/tenant_id=<tenant_id>/session_id=<session_id>/runs/year=<year>/month=<month>/day=<day>
```

## 3. 监控您的导出

使用[上一步](#2-create-an-export-job)中的 `id` 轮询导出状态：

```bash
curl --request GET \
  --url 'https://api.smith.langchain.com/api/v1/bulk-exports/{export_id}' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'X-Tenant-Id: YOUR_WORKSPACE_ID'
```

响应中的 `status` 字段将是 `CREATED`、`RUNNING`、`COMPLETED`、`FAILED`、`CANCELLED` 或 `TIMEDOUT` 之一。根据数据量，导出可能需要一些时间。一旦状态为 `COMPLETED`，Parquet 文件即可在您的存储桶中使用。

请参阅[监控和排查批量导出](/langsmith/data-export-monitor)了解如何列出运行、停止导出和诊断失败。
