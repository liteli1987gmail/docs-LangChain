title: 可扩展性和弹性
sidebarTitle: 可扩展性和弹性
---

LangSmith 的设计可随您的工作负载水平扩展。服务的每个实例都是无状态的，不会在内存中保留任何资源。该服务设计为可以优雅地处理添加或删除新实例，包括硬关闭情况。

## 服务器可扩展性

当您向服务添加更多实例时，只要在它们前面放置适当的负载均衡器机制，它们就会分担 HTTP 负载。在大多数部署模式中，我们自动为服务配置负载均衡器。在"无控制平面的自托管"模式中，由您负责添加负载均衡器。由于实例是无状态的，任何负载均衡策略都会起作用，不需要（也不推荐）会话粘性。服务器的任何一个实例都可以与任何队列实例通信（通过 Redis PubSub），这意味着取消或流式传输正在进行的运行的请求可以由任意一个实例处理。

## 队列可扩展性

当您向服务添加更多实例时，它们将线性增加运行吞吐量，因为每个实例都配置为处理一组并发运行（默认情况下为 10）。每次运行的每次尝试都将由单个实例处理，通过 Postgres 的 MVCC 模型强制执行恰好一次语义（有关崩溃弹性详细信息，请参阅下面的部分）。由于瞬态数据库错误而失败的尝试最多重试 3 次。我们不使用长期事务或锁，这使我们能够更有效地利用 Postgres 资源。

## 弹性

当运行由队列实例处理时，该队列工作线程将在 Redis 中定期记录心跳时间戳。

当收到优雅关闭请求（SIGINT）时，实例进入关闭模式，这会

- 停止接受新的 HTTP 请求
- 给任何正在进行的运行有限的秒数来完成（如果没有完成，它将被放回队列）
- 停止实例从队列中获取更多运行

如果由于服务器崩溃或基础设施故障而发生硬关闭，任何正在进行的运行都将由内部清理任务拾取，该任务查找超过心跳窗口的正在进行的运行。清理任务每 2 分钟运行一次，并将运行放回队列中以供另一个实例拾取。

## Postgres 弹性

对于我们管理 Postgres 数据库的部署模式，我们有定期备份和用于自动故障转移的持续复制备用副本。此 Postgres 配置仅在[云部署选项](/langsmith/cloud)的[`生产`部署类型](/langsmith/control-plane#deployment-types)中可用。

与 Postgres 的所有通信都对可重试错误实施重试。如果 Postgres 暂时不可用，例如在数据库重启期间，大多数/所有流量应该继续成功。 Postgres 长期故障将使 Agent Server 不可用。

## Redis 弹性

所有需要持久存储的数据都存储在 Postgres 中，而不是 Redis 中。Redis 仅用于临时元数据和实例之间的通信。因此我们对 Redis 没有持久性要求。

与 Redis 的所有通信都对可重试错误实施重试。如果 Redis 暂时不可用，例如在数据库重启期间，大多数/所有流量应该继续成功。 Redis 长期故障将使 Agent Server 不可用。
