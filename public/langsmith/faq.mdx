## 可观测性

### *我无法在 UI 中创建 API 密钥或管理用户，这是怎么回事？*

* 您很可能部署 LangSmith 时没有设置 SSO。LangSmith 需要 SSO 来管理用户和 API 密钥。您可以在[配置部分](/langsmith/self-host-sso)找到有关设置 SSO 的更多信息。

### *负载均衡/入口是如何工作的？*

* 您需要将前端容器/服务暴露给您的应用程序/用户。这将处理到所有下游服务的路由。
* 您需要在入口级别终止 SSL。我们建议使用托管服务，如 AWS ALB、GCP Load Balancer 或 Nginx。

### *我们如何对应用程序进行身份验证？*

* 目前，我们的自托管解决方案支持使用 OAuth2.0 和 OIDC 作为身份验证解决方案的 SSO。请注意，我们确实提供了无身份验证解决方案，但强烈建议在投入生产之前设置 oauth。

您可以在[配置部分](/langsmith/self-host-sso)找到有关设置 SSO 的更多信息。

### *我可以使用外部存储服务吗？*

* 您可以配置 LangSmith 使用外部版本的所有存储服务。在生产环境中，我们强烈建议使用外部存储服务。请查看[配置部分](/langsmith/self-hosted)获取更多信息。

### *我的应用程序需要出口才能正常运行吗？*

我们的部署只需要为少数事项提供出口（其中大部分可以驻留在您的 VPC 内）：

* 获取镜像（如果您在镜像化您的镜像，则可能不需要）
* 与任何 LLM 端点通信
* 与您可能已配置的任何外部存储服务通信
* 获取 OAuth 信息
* 订阅指标和操作元数据（如果不处于离线模式）
  * 需要出口到 `https://beacon.langchain.com`
  * 有关更多信息，请参阅[出口](/langsmith/self-host-egress)

您的 VPC 可以设置规则来限制任何其他访问。注意：我们要求允许将 `X-Organization-Id` 和 `X-Tenant-Id` 标头传递到后端服务。这些标头用于确定请求所属的组织和工作区（以前称为"租户"）。

### *应用程序的资源要求是什么？*

* 在 kubernetes 中，我们推荐最小的 helm 配置，您可以在[中等大小示例](https://github.com/langchain-ai/helm/blob/main/charts/langsmith/examples/medium_size.yaml)中看到。对于 docker，我们推荐最少 16GB RAM 和 4 个 CPU。
* 对于 Postgres，我们推荐最少 8GB RAM 和 2 个 CPU。
* 对于 Redis，我们推荐 4GB RAM 和 2 个 CPU。
* 对于 ClickHouse，我们推荐 32GB RAM 和 8 个 CPU。

### SAML SSO 常见问题

#### *如何更改 SAML SSO 用户的邮箱地址？*

一些身份提供商会保留原始 `User ID` 通过邮箱更改，而有些则不会，因此我们建议您遵循这些步骤以避免在 LangSmith 中出现重复用户：

1. 从组织中移除用户（请参阅[管理用户](/langsmith/set-up-hierarchy#manage-users)）
2. 在 IdP 中更改他们的邮箱地址
3. 让他们再次通过 SAML SSO 登录 LangSmith——这将使用他们的新邮箱地址触发通常的 [JIT 配置](/langsmith/user-management#just-in-time-jit-provisioning)流程

目前不支持通过 SCIM 或其他方式为具有多个链接登录方法的用户更改邮箱地址。会显示此错误消息：`email update not supported with linked login methods`。例如，如果用户之前通过邮箱/密码或 Google 社交登录登录，然后通过同一邮箱地址通过 SSO 添加，则不支持更改他们的邮箱地址。这适用于自托管和云。

#### *我可以更改身份提供商吗？*

请通过我们的门户联系 LangChain 支持团队 [https://support.langchain.com](https://support.langchain.com) 获取迁移支持。

#### *如何修复"405 method not allowed"？*

确保您使用的是正确的 ACS URL：[https://auth.langchain.com/auth/v1/sso/saml/acs](https://auth.langchain.com/auth/v1/sso/saml/acs)

### SCIM 常见问题

#### *我可以不使用 SAML SSO 使用 SCIM 吗？*

* **云**：不行，云部署中的 SCIM 需要 SAML SSO
* **自托管**：可以，SCIM 可以与 OAuth 客户端密钥身份验证模式一起使用

#### *如果我同时启用了 JIT 配置和 SCIM 会怎样？*

JIT 配置和 SCIM 可能相互冲突。我们建议在启用 SCIM 之前禁用 JIT 配置，以确保一致的用户配置行为。

#### *如何更改用户的角色或工作区访问权限？*

在您的 IdP 中更新用户的组成员资格。更改将根据[角色优先级规则](/langsmith/user-management#role-precedence)同步到 LangSmith。

#### *当用户从所有组中移除时会发生什么？*

用户将根据您的 IdP 的取消配置设置从 LangSmith 组织中取消配置。

#### *我可以使用的自定义组名称吗？*

可以。如果您的身份提供商支持将备用字段同步到 `displayName` 组属性，您可以使用备用属性（如 `description`）作为 LangSmith 中的 `displayName`，并保留身份提供商组名的完全自定义性。否则，组必须遵循[组命名约定](/langsmith/user-management#group-naming-convention)部分中描述的特定命名约定，才能正确映射到 LangSmith 角色和工作区。

您也可以[配置自定义分隔符](/langsmith/user-management#configure-custom-separator)（例如 `-`、`_`、`&`）而不是默认的冒号（`:`）来适应对组名字符有限制的身份提供商。

#### _为什么我的 Okta 集成不工作？_

请在此处查看 Okta 的故障排除指南：https://help.okta.com/en-us/content/topics/users-groups-profiles/usgp-group-push-troubleshoot.htm。

### *支持降级吗？*

不支持正式降级。LangSmith 升级可能包括数据库迁移和其他不向后兼容的更改。如果您需要回滚到以前的版本，请联系[支持](mailto:support@langchain.dev)获取指导。

## 部署

### 我需要使用 LangChain 才能使用 LangGraph 吗？有什么区别？

不。LangGraph 是一个用于复杂代理系统的编排框架，比 LangChain 代理更低级和可控。LangChain 提供了与模型和其他组件交互的标准接口，对简单的链和检索流程很有用。

### LangGraph 与其他代理框架有何不同？

其他代理框架可以用于简单的通用任务，但在满足公司需求的复杂任务上表现不足。LangGraph 提供了更富有表现力的框架来处理公司的独特任务，而不将用户限制在单一的黑盒认知架构中。

### LangGraph 会影响我的应用程序的性能吗？

LangGraph 不会为您的代码增加任何开销，并且专门为流式工作流设计。

### LangGraph 是开源的吗？免费吗？

是的。LangGraph 是一个 MIT 许可的开源库，免费使用。

### LangGraph 和 LangSmith 有何不同？

LangGraph 是一个有状态的编排框架，为代理工作流带来额外的控制。LangSmith 是一个用于部署和扩展代理应用程序的服务，具有用于构建代理 UX 的固执己见的 API，以及集成的开发者 UI。

| 功能 | LangGraph（开源） | LangSmith |
|---------------------|-----------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| 描述 | 用于代理应用程序的有状态编排框架 | 用于部署 LangGraph 应用程序的可扩展基础设施 |
| SDK | Python 和 JavaScript | Python 和 JavaScript |
| HTTP API | 无 | 有——用于检索和更新状态或长期记忆，或创建可配置助手 |
| 流式 | 基本 | 专用模式，用于逐标记消息 |
| Checkpointer | 社区贡献 | 开箱即用支持 |
| 持久层 | 自我管理 | 托管 Postgres with 高效存储 |
| 部署 | 自我管理 | • 云 <br /> • 免费自托管 <br /> • 企业（付费自托管） |
| 可扩展性 | 自我管理 | 任务队列和服务器自动扩展 |
| 容错 | 自我管理 | 自动重试 |
| 并发控制 | 简单线程 | 支持双重文本 |
| 调度 | 无 | Cron 调度 |
| 监控 | 无 | 与 LangSmith 集成以实现可观测性 |
| IDE 集成 | Studio | Studio |

### LangSmith 是开源的吗？

不。LangSmith 是专有软件。

有免费的自托管版本 LangSmith，可访问基本功能。云部署选项和自托管部署选项是付费服务。[联系我们的销售团队](https://www.langchain.com/contact-sales)了解更多。

有关更多信息，请参阅我们的 [LangSmith 定价页面](https://www.langchain.com/pricing)。

### LangGraph 适用于不支持工具调用的 LLM 吗？

是的！您可以将 LangGraph 与任何 LLM 一起使用。我们使用支持工具调用的 LLM 的主要原因是，这是因为通常是最方便的方式让 LLM 做出关于做什么的决定。如果您的 LLM 不支持工具调用，您仍然可以使用它——您只需要写一点逻辑将原始 LLM 字符串响应转换为关于做什么的决定。

### LangGraph 适用于开源 LLM 吗？

是的！LangGraph 完全不在乎在幕后使用什么 LLM。我们在大多数教程中使用封闭 LLM 的主要原因是它们无缝支持工具调用，而开源 LLM 通常不支持。但工具调用不是必需的（请参阅[LangGraph 是否适用于不支持工具调用的 LLM？](#does-langgraph-work-with-llms-that-dont-support-tool-calling)），因此您完全可以将 LangGraph 与开源 LLM 一起使用。

### 我可以在不登录 LangSmith 的情况下使用 Studio 吗？

可以！您可以使用[Agent Server 的开发版本](/langsmith/local-dev-testing)在本地运行后端。
这将连接到作为 LangSmith 的一部分托管的 Studio 前端。
如果您设置环境变量 `LANGSMITH_TRACING=false`，则不会将追踪发送到 LangSmith。

### 什么是部署运行？

部署运行是通过 LangSmith 部署部署的 LangGraph 代理的一次端到端调用。节点和子图不单独计费。通过 RemoteGraph 或 LangGraph SDK 或直接通过 API 调用其他 LangGraph 代理会单独计费，计入托管被调用代理的部署。当恢复时，人工介入的中断会创建一个单独的部署运行。
