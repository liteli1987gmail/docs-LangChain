title: 模型提供商
description: 为深度代理 CLI 配置任何与 LangChain 兼容的模型提供商

深度代理 CLI 支持任何[与 LangChain 兼容的聊天模型提供商](/oss/python/integrations/chat)，解锁对 virtually 任何支持工具调用的 LLM 的使用。任何暴露 OpenAI 兼容或 Anthropic 兼容 API 的服务也可以开箱即用——请参阅[兼容的 API](/oss/python/deepagents/cli/configuration#compatible-apis)。

## 快速开始

CLI 自动与[以下模型提供商](#provider-reference)集成：除了安装相关提供商包外不需要额外配置。

1. **安装提供商包**

    每个模型提供商都需要安装其相应的 LangChain 集成包。这些作为安装 CLI 时的可选额外工具提供，有意保持应用程序轻量级：

    ```bash
    # 快速安装所选提供商
    # OpenAI、Anthropic 和 Gemini 默认包含
    DEEPAGENTS_EXTRAS="baseten,groq" curl -LsSf https://langch.in/gh-da-cli | bash

    # 或直接使用 uv 安装
    uv tool install 'deepagents-cli[baseten,groq]'

    # 稍后添加额外的包
    uv tool install deepagents-cli --with langchain-ollama

    # 所有提供商
    uv tool install 'deepagents-cli[anthropic,baseten,bedrock,cohere,deepseek,fireworks,google-genai,groq,huggingface,ibm,litellm,mistralai,nvidia,ollama,openai,openrouter,perplexity,vertexai,xai]'
    ```

2. **设置凭证**

    将 API 密钥存储在 `~/.deepagents/.env` 中，以便它们在所有项目中可用，或在您的 shell 中导出它们：

    ```bash
    ANTHROPIC_API_KEY=sk-ant-...
    OPENAI_API_KEY=sk-...
    ```

    某些提供商使用其他凭证（例如，Vertex AI 使用 `GOOGLE_CLOUD_PROJECT` 加 ADC）。请参阅下表了解每个提供商所需的环境变量。您也可以使用 [`DEEPAGENTS_CLI_` 前缀](/oss/python/deepagents/cli/configuration#deepagents_cli_-prefix) 将凭证限定于 CLI。

<Tip>
    **[模型配置文件](/oss/python/langchain/models#model-profiles)** 是一个元数据 bundle（模型名称、默认参数、能力等），随提供商包一起发布，主要由 [models.dev](https://models.dev/) 项目提供支持。

    提供模型配置文件的提供商会在交互式 `/model` 选择器中自动列出其模型，受[过滤条件](#which-models-appear-in-the-switcher)（特别是必须启用 `tool_calling`）的限制。没有模型配置文件的提供商需要您直接指定模型名称或通过 `config.toml` 添加模型。
</Tip>



### 模型路由器和代理

像 [OpenRouter](https://openrouter.ai/) 和 [LiteLLM](https://docs.litellm.ai/) 这样的模型路由器通过单一端点提供对多个提供商模型的访问。

使用这些服务的专用集成包：

| 路由器 | 包 | 配置 |
| --- | --- | --- |
| OpenRouter | [`langchain-openrouter`](/oss/python/integrations/chat/openrouter) | `openrouter:<模型>`（内置，请参阅[提供商参考](#provider-reference)） |
| LiteLLM | [`langchain-litellm`](/oss/python/integrations/chat/litellm) | `litellm:<模型>`（内置，请参阅[提供商参考](#provider-reference)） |




**OpenRouter** 是一个内置提供商——安装包并直接使用：

```bash
uv tool install 'deepagents-cli[openrouter]'
```

**LiteLLM** 也是一个内置提供商：

```bash
uv tool install 'deepagents-cli[litellm]'
```

### 切换模型

要在 CLI 中切换模型，请执行以下操作之一：

1. **使用交互式模型选择器** 与 `/model` 命令。这显示从每个已安装的 LangChain 提供商包的[模型配置文件](/oss/python/langchain/models#model-profiles)中获取的可用模型。

    <Note>
        并非所有模型都出现在这里。如果您的缺失，请直接传递模型名称（例如 `/model gpt-5.4`）。请参阅[哪些模型出现在选择器中](#which-models-appear-in-the-switcher)了解更多详情。
    </Note>
2. **直接指定模型名称** 作为参数，例如 `/model gpt-5.4`。您可以使用所选提供商支持的任何模型，无论它是否出现在选项 1 的列表中。模型名称将被传递给 API 请求。
3. **在启动时通过 `--model` 指定模型**，例如

    ```txt
    deepagents --model openai:gpt-5.4
    ```

### 哪些模型出现在选择器中

`/model` 选择器从已安装的提供商包动态构建其列表。展开以下内容查看完整标准和故障排除。

<Accordion title="选择器如何构建其模型列表" icon="list-search">
    交互式 `/model` 选择器动态构建其列表——它不是硬编码到 CLI 中的列表。当**所有**以下条件都为真时，模型会出现在选择器中：

    1. **提供商包已安装。** 每个提供商（例如 `langchain-anthropic`、`langchain-openai`）必须与 `deepagents-cli` 一起安装——作为[安装额外工具](/oss/python/deepagents/cli/providers#quick-start)（例如 `uv tool install 'deepagents-cli[ollama]'`）或稍后用 `uv tool install deepagents-cli --with <package>` 添加。如果包缺失，其整个提供商部分在选择器中缺失。
    2. **模型的配置文件已启用 `tool_calling`。** CLI 需要工具调用支持，因此没有 `tool_calling: true` 的模型会被排除。这是模型缺失列表的最常见原因。对于不捆绑配置文件的提供商（请参阅[提供商参考](#provider-reference)表），您可以在 `config.toml` 中定义一个：

        ```toml
        [models.providers.ollama.profile."qwen3:4b"]
        tool_calling = true
        max_input_tokens = 32768
        max_output_tokens = 8192
        ```

        这不是模型出现在选择器中的严格要求——将其添加到[`models` 列表](/oss/python/deepagents/cli/configuration#adding-models-to-the-interactive-switcher)也可以，而且更简单。当您希望 CLI 知道模型的上下文窗口和用于自动总结等功能的能力时，配置文件很有用。请参阅[配置文件覆盖](/oss/python/deepagents/cli/configuration#profile-overrides-advanced)了解所有可覆盖的字段。
    3. **模型接受并产生文本。** 其配置文件明确设置 `text_inputs` 或 `text_outputs` 为 `false` 的模型（例如嵌入或图像生成模型）被排除。

    在 `config.toml` 中 [`[models.providers.<name>].models`](/oss/python/deepagents/cli/configuration#adding-models-to-the-interactive-switcher) 下定义的模型绕过配置文件过滤器——无论配置文件元数据如何，它们始终出现在选择器中。这是推荐的方式，用于添加缺失的模型。

    <Tip>
        凭证状态**不会**影响模型是否被列出。选择器显示所有符合条件的模型，并在每个提供商标题旁边显示凭证指示器：已确认凭证的打勾、缺失凭证的警告，或凭证状态未知时的问号。您仍然可以选择凭证缺失的模型——提供商会在请求时报告身份验证错误。
    </Tip>

    #### 故障排除缺失的模型

    | 症状 | 可能原因 | 修复 |
    | --- | --- | --- |
    | 整个提供商从选择器中缺失 | 提供商包未安装 | 安装包（例如 `uv tool install deepagents-cli --with langchain-groq`） |
    | 提供商显示但特定模型缺失 | 模型配置文件的 `tool_calling: false` 或不存在配置文件 | 在 `config.toml` 的 `[models.providers.<name>].models` 中添加模型，或直接使用 `/model <提供商>:<模型>` |
    | 提供商显示 ⚠ "缺失凭证" | API 密钥环境变量未设置 | 从[提供商参考](#provider-reference)表设置凭证环境变量 |
    | 提供商显示 ? "凭证未知" | 提供商使用 CLI 无法验证的非标准身份验证 | 凭证可能仍然有效——尝试切换到模型。如果身份验证失败，请检查提供商的文档 |
</Accordion>

### 设置默认模型

您可以设置持久默认模型，该模型将用于所有未来 CLI 启动：

* **通过模型选择器：** 打开 `/model`，导航到所需的模型，然后按 `Ctrl+S` 将其固定为默认。再次在当前默认模型上按 `Ctrl+S` 会清除它。
* **通过命令：** `/model --default 提供商:模型`（例如 `/model --default anthropic:claude-opus-4-6`）
* **通过配置文件：** 在 `~/.deepagents/config.toml` 中设置 `[models].default`（请参阅[配置](/oss/python/deepagents/cli/configuration)）。
* **从 shell：**

    ```bash
    deepagents --default-model anthropic:claude-opus-4-6
    ```

要查看当前默认值：

```bash
deepagents --default-model
```

要清除默认值：

* **从 shell：**

    ```bash
    deepagents --clear-default-model
    ```

* **通过命令：** `/model --default --clear`
* **通过模型选择器：** 在当前固定默认模型上按 `Ctrl+S`。

没有默认时，CLI 将默认为最近使用的模型。

### 模型解析顺序

当 CLI 启动时，它按以下顺序解析使用哪个模型：

1. **`--model` 标志** 始终优先（当提供时）。
2. **`[models].default`** 在 `~/.deepagents/config.toml` 中——用户的长期偏好。
3. **`[models].recent`** 在 `~/.deepagents/config.toml` 中——通过 `/model` 最后切换的模型。自动写入；从不覆盖 `[models].default`。
4. **环境自动检测**：回退到按顺序检查的第一个可用启动凭证：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY`、`GOOGLE_CLOUD_PROJECT`（Vertex AI）。

此启动回退有意仅检查这四个凭证。其他支持的提供商（例如 Groq）仍可通过 `--model`、`/model` 和保存的默认值（`[models].default` / `[models].recent`）使用。
