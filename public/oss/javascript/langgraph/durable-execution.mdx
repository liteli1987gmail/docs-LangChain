---
title: 持久化执行
---



**持久化执行**是一种技术，其中进程或工作流程在关键点保存其进度，允许它暂停然后从中断处恢复。这在需要[人工介入](/oss/javascript/langgraph/interrupts)的场景中特别有用，用户可以在继续之前检查、验证或修改流程，以及在可能遇到中断或错误的长时运行任务中（例如，对大型语言模型的调用超时）。通过保留已完成的工作，持久化执行使进程能够无需重新处理先前步骤即可恢复——即使在很长时间延迟后（例如，一周后）。

LangGraph 内置的[持久化](/oss/javascript/langgraph/persistence)层为工作流程提供持久化执行，确保每个执行步骤的状态都保存到持久化存储中。此功能保证如果工作流程被中断——无论是由于系统故障还是[人工介入](/oss/javascript/langgraph/interrupts)交互——它都可以从其最后记录的状态恢复。

<Tip>
如果您正在使用带检查点的 LangGraph，您已经启用了持久化执行。您可以在任何时候暂停和恢复工作流程，即使在中断或故障后。
为了充分利用持久化执行，确保您的工作流程被设计为是[确定性的](#determinism-and-consistent-replay)和[幂等的](#determinism-and-consistent-replay)，并将任何副作用或非确定性操作包装在[任务](/oss/javascript/langgraph/functional-api#task)中。您可以同时使用[StateGraph（图 API）](/oss/javascript/langgraph/graph-api)和[函数式 API](/oss/javascript/langgraph/functional-api)中的[任务](/oss/javascript/langgraph/functional-api#task)。
</Tip>

## 要求

要在 LangGraph 中利用持久化执行，您需要：

1. 通过指定将保存工作流程进度的[检查点](/oss/javascript/langgraph/persistence#checkpointer-libraries)在您的工作流程中启用[持久化](/oss/javascript/langgraph/persistence)。
2. 在执行工作流程时指定一个[线程标识符](/oss/javascript/langgraph/persistence#threads)。这将跟踪工作流程特定实例的执行历史。

1. 将任何非确定性操作（例如随机数生成）或具有副作用的操作（例如文件写入、API 调用）包装在 [任务](https://reference.langchain.com/javascript/langchain-langgraph/index/task) 中，以确保当工作流程恢复时，这些操作不会为特定运行重复执行，而是从持久化层检索其结果。有关更多信息，请参阅[确定性和一致回放](#determinism-and-consistent-replay)。

## 确定性和一致回放

当您恢复工作流程运行时，代码**不会**从执行停止的**同一行代码**恢复；相反，它会从适当的[起点](#starting-points-for-resuming-workflows)识别以从中断处继续。这意味着工作流程将从[起点](#starting-points-for-resuming-workflows)重放所有步骤，直到达到它停止的点。

因此，在为持久化执行编写工作流程时，您必须将任何非确定性操作（例如随机数生成）和任何具有副作用的操作（例如文件写入、API 调用）包装在[任务](/oss/javascript/langgraph/functional-api#task)或[节点](/oss/javascript/langgraph/graph-api#nodes)中。

为确保您的工作流程是确定性的并且可以一致地回放，请遵循以下指南：

* **避免重复工作**：如果一个[节点](/oss/javascript/langgraph/graph-api#nodes)包含多个具有副作用的操作（例如日志记录、文件写入或网络调用），请将每个操作包装在一个单独的**任务**中。这确保当工作流程恢复时，操作不会重复，并且从持久化层检索其结果。
* **封装非确定性操作：** 将任何可能产生非确定性结果（例如随机数生成）的代码包装在**任务**或**节点**中。这确保在恢复时，工作流程遵循具有相同结果的精确记录步骤序列。
* **使用幂等操作**：尽可能确保副作用（例如 API 调用、文件写入）是幂等的。这意味着如果在工作流程中失败后重试操作，它将具有与第一次执行时相同的效果。这对于导致数据写入的操作尤为重要。如果一个**任务**开始但未能成功完成，工作流程的恢复将重新运行该**任务**，依赖记录的结果来保持一致性。使用幂等键或验证现有结果以避免意外的重复，确保顺利且可预测的工作流程执行。

有关要避免的陷阱的一些示例，请参阅函数式 API 中的[常见陷阱](/oss/javascript/langgraph/functional-api#common-pitfalls)部分，其中展示了如何使用**任务**构建代码以避免这些问题。相同的原则适用于 [StateGraph（图 API）](https://reference.langchain.com/javascript/langchain-langgraph/index/StateGraph)。

## 持久化模式

LangGraph 支持三种持久化模式，允许您根据应用程序要求在性能和数据一致性之间取得平衡。较高的持久化模式会增加工作流程执行的开销。您可以在调用任何图执行方法时指定持久化模式：



```typescript
await graph.stream(
  { input: "test" },
  { durability: "sync" }
)
```


持久化模式从最低到最高依次是：

* `"exit"`：LangGraph 仅在图执行成功退出、出错或由于人工介入中断时才持久化更改。这为长时间运行的图提供了最佳性能，但意味着不保存中间状态，因此您无法从执行中间发生的系统故障（如进程崩溃）中恢复。
* `"async"`：LangGraph 在下一步执行时异步持久化更改。这提供了良好的性能和持久化，但存在一个小风险，即 LangGraph 在执行期间进程崩溃时可能不写入检查点。
* `"sync"`：LangGraph 在下一步开始之前同步持久化更改。这确保 LangGraph 在继续执行之前写入每个检查点，以一些性能开销为代价提供高持久化。

## 在节点中使用任务

如果一个[节点](/oss/javascript/langgraph/graph-api#nodes)包含多个操作，您可能会发现将每个操作转换为一个**任务**比将操作重构为单独的节点更容易。



<Tabs>
    <Tab title="原始">
    ```typescript
    import { StateGraph, StateSchema, GraphNode, START, END, MemorySaver } from "@langchain/langgraph";
    import { v7 as uuid7 } from "uuid";
    import * as z from "zod";

    // 定义一个 StateSchema 来表示状态
    const State = new StateSchema({
      url: z.string(),
      result: z.string().optional(),
    });

    const callApi: GraphNode<typeof State> = async (state) => {
      const response = await fetch(state.url);  // [!code highlight]
      const text = await response.text();
      const result = text.slice(0, 100); // 副作用
      return {
        result,
      };
    };

    // 创建一个 StateGraph 构建器并为 callApi 函数添加一个节点
    const builder = new StateGraph(State)
      .addNode("callApi", callApi)
      .addEdge(START, "callApi")
      .addEdge("callApi", END);

    // 指定一个检查点
    const checkpointer = new MemorySaver();

    // 使用检查点编译图
    const graph = builder.compile({ checkpointer });

    // 使用线程 ID 定义配置。
    const threadId = uuid7();
    const config = { configurable: { thread_id: threadId } };

    // 调用图
    await graph.invoke({ url: "https://www.example.com" }, config);
```
    </Tab>
    <Tab title="使用任务">
    ```typescript
    import { StateGraph, StateSchema, GraphNode, START, END, MemorySaver, task } from "@langchain/langgraph";
    import { v7 as uuid7 } from "uuid";
    import * as z from "zod";

    // 定义一个 StateSchema 来表示状态
    const State = new StateSchema({
      urls: z.array(z.string()),
      results: z.array(z.string()).optional(),
    });

    const makeRequest = task("makeRequest", async (url: string) => {
      const response = await fetch(url);  // [!code highlight]
      const text = await response.text();
      return text.slice(0, 100);
    });

    const callApi: GraphNode<typeof State> = async (state) => {
      const requests = state.urls.map((url) => makeRequest(url));  // [!code highlight]
      const results = await Promise.all(requests);
      return {
        results,
      };
    };

    // 创建一个 StateGraph 构建器并为 callApi 函数添加一个节点
    const builder = new StateGraph(State)
      .addNode("callApi", callApi)
      .addEdge(START, "callApi")
      .addEdge("callApi", END);

    // 指定一个检查点
    const checkpointer = new MemorySaver();

    // 使用检查点编译图
    const graph = builder.compile({ checkpointer });

    // 使用线程 ID 定义配置。
    const threadId = uuid7();
    const config = { configurable: { thread_id: threadId } };

    // 调用图
    await graph.invoke({ urls: ["https://www.example.com"] }, config);
```
    </Tab>
</Tabs>


## 恢复工作流程

一旦您在自己的工作流程中启用了持久化执行，您可以为以下场景恢复执行：



* **暂停和恢复工作流程：** 使用 [interrupt](https://reference.langchain.com/javascript/langchain-langgraph/index/interrupt) 函数在特定点暂停工作流程，并使用 [`Command`](https://reference.langchain.com/javascript/langchain-langgraph/index/Command) 原语用更新的状态恢复它。请参阅[**中断**](/oss/javascript/langgraph/interrupts)了解更多详细信息。
* **从故障中恢复：** 在异常（例如大型语言模型提供商中断）后自动从最后一个成功检查点恢复工作流程。这涉及通过提供 `null` 作为输入值来使用相同的线程标识符执行工作流程（请参阅函数式 API 的[此示例](/oss/javascript/langgraph/use-functional-api#resuming-after-an-error)）。


## 恢复工作流程的起点

* 如果您使用的是 [StateGraph（图 API）](/oss/javascript/langgraph/graph-api)，则起点是执行停止的[**节点**](/oss/javascript/langgraph/graph-api#nodes)的开始。
* 如果您在节点内进行子图调用，则起点将是调用已停止的子图的**父**节点。
  在子图内部，起点将是执行停止的特定[**节点**](/oss/javascript/langgraph/graph-api#nodes)。
* 如果您使用的是函数式 API，则起点是执行停止的[**入口点**](/oss/javascript/langgraph/functional-api#entrypoint)的开始。
