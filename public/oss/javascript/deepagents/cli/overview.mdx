Deep Agents CLI 是一个基于[深度代理 SDK](/oss/javascript/deepagents/quickstart)构建的开源终端编码代理。
它保留持久记忆、跨会话维护上下文、学习项目约定、使用可自定义技能，并在执行代码时提供批准控制。

![Deep Agents CLI](/oss/images/deepagents/deepagents-cli.png)

Deep Agents CLI 具有以下内置功能：

* <Icon icon="file" size={16} /> **文件操作** - 使用使代理能够管理和修改代码及文档的工具来读取、写入和编辑文件。
* <Icon icon="terminal" size={16} /> **Shell 执行** - 执行命令以运行测试、构建项目、管理依赖项并与版本控制交互。
* <Icon icon="search" size={16} /> **Web 搜索** - 搜索网络获取最新信息和文档（需要 Tavily API 密钥）。
* <Icon icon="globe" size={16} /> **HTTP 请求** - 向 API 和外部服务发出 HTTP 请求以获取数据并进行集成任务。
* <Icon icon="list-check" size={16} /> **任务规划和跟踪** - 将复杂任务分解为离散步骤并跟踪进度。
* <Icon icon="brain" size={16} /> **记忆存储和检索** - 跨会话存储和检索信息，使代理能够记住项目约定和学习到的模式。
* <Icon icon="arrows-minimize" size={16} /> **上下文压缩和卸载** - 在长时间会话中总结旧对话消息并将原始内容卸载到存储，释放上下文窗口空间。
* <Icon icon="user" size={16} /> **人在回路中** - 需要人工批准敏感工具操作。
* <Icon icon="puzzle" size={16} /> **技能** - 使用自定义专业知识和指令扩展代理能力。
* <Icon icon="plug" size={16} /> **[MCP 工具](/oss/javascript/deepagents/cli/mcp-tools)** - 从 [Model Context Protocol](https://modelcontextprotocol.io/) 服务器加载外部工具。
* <Icon icon="chart-dots" size={16} /> **[追踪](/oss/javascript/deepagents/cli/overview#tracing-with-langsmith)** - 在 LangSmith 中追踪代理操作以便观察和调试。

<Accordion title="内置工具完整列表">
    ## 内置工具

    代理附带以下内置工具，无需配置即可使用：

    | 工具 | 描述 | 人在回路中 |
    |------|------|----------|
    | `ls` | 列出文件和目录 | - |
    | `read_file` | 读取文件内容；部分多模态内容适用于选定的模型 | - |
    | `write_file` | 创建或覆盖文件 | 必需<sup>1</sup> |
    | `edit_file` | 对现有文件进行有针对性的编辑 | 必需<sup>1</sup> |
    | `glob` | 查找匹配模式的文件 | - |
    | `grep` | 在文件中搜索文本模式 | - |
    | `execute` | 在本地或远程沙箱中执行 shell 命令 | 必需<sup>1</sup> |
    | `web_search` | 使用 Tavily 搜索网络 | 必需<sup>1</sup> |
    | `fetch_url` | 获取并转换网页为 markdown | 必需<sup>1</sup> |
    | `task` | 将工作委托给子代理进行并行执行 | 必需<sup>1</sup> |
    | `ask_user` | 向用户提出自由形式或多选问题 | - |
    | `compact_conversation` | 总结旧消息，将原始内容卸载到后端存储，并用摘要替换上下文中的内容 | 混合<sup>2</sup> |
    | `write_todos` | 为复杂工作创建和管理任务列表 | - |

    <sup>1</sup>：潜在破坏性操作需要在执行前获得用户批准。要绕过人工批准，您可以切换自动批准（Shift+Tab）或使用以下选项启动：

    ```bash
    deepagents -y
    # 或
    deepagents --auto-approve
    ```

    <Note>
        当以非交互方式运行 CLI（通过 `-n` 或管道 stdin）时，即使使用 `-y`/`--auto-approve`，shell 执行默认也是禁用的。使用 `-S`/`--shell-allow-list` 来允许列表特定命令（例如 `-S "pytest,git,make"`），`recommended` 获取安全默认值，或 `all` 允许任何命令。也支持 `DEEPAGENTS_CLI_SHELL_ALLOW_LIST` 环境变量。有关更多详细信息，请参阅[非交互模式和中](/oss/javascript/deepagents/cli/overview#non-interactive-mode-and-piping)。
    </Note>

    <sup>2</sup>：当 Token 使用量超过模型感知阈值时，CLI 会自动在后台卸载对话。卸载通过 LLM 总结旧消息，并将原始内容弹出到存储（`/conversation_history/{thread_id}.md`），用摘要替换上下文中的内容。如果需要，代理仍可以从卸载的文件中检索完整历史。`compact_conversation` 工具允许代理（或您）按需触发卸载。作为工具调用时，默认需要用户批准。
</Accordion>

<Tip>
    [观看演示视频](https://youtu.be/IrnacLa9PJc?si=3yUnPbxnm2yaqVQb) 了解 Deep Agents CLI 的工作方式。
</Tip>

<Note>
    Deep Agents CLI 官方不支持 Windows。Windows 用户可以尝试在 [Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/en-us/windows/wsl/install) 下运行。
</Note>

## 非交互模式和中

使用 `-n` 运行单个任务而不启动交互式 UI：

```bash
deepagents -n "Write a Python script that prints hello world"
```

您也可以通过 stdin 管道输入。当输入被管道传输时，CLI 会自动以非交互方式运行：

```bash
echo "Explain this code" | deepagents
cat error.log | deepagents -n "What's causing this error?"
git diff | deepagents -n "Review these changes"
git diff | deepagents --skill code-review -n 'summarize changes'
```

当您将管道输入与 `-n` 或 `-m` 结合使用时，管道内容首先出现，然后是您传递给标志的文本。

<Note>
    最大管道输入大小为 10 MiB。
</Note>

在非交互模式下，shell 执行默认被禁用。使用 `-S`/`--shell-allow-list` 启用特定命令（例如 `-S "pytest,git,make"`）、`recommended` 获取安全默认值，或 `all` 允许任何命令。

<AccordionGroup>
    <Accordion title="使用 `--max-turns` 限制轮次" icon="gauge">
        在 CI/CD 管道中，运行时间过长或不听话的代理可能会无限循环。`--max-turns N` 为运营商提供硬性上限，而无需触及 SDK 内部：

        ```bash
        deepagents -n "fix the failing tests" --max-turns 10
        ```

        `N` 必须是正整数，并覆盖内部安全默认值（否则限制失控循环）。当超出预算时退出代码 124（与 GNU `timeout` 匹配），因此 CI 可以将预算命中与通用失败区分开来。需要 `-n` 或管道 stdin；否则退出代码 2。
    </Accordion>

    <Accordion title="清洁输出和缓冲" icon="buffer">
        使用 `-q` 获取适合管道到其他命令的清洁输出，并使用 `--no-stream` 在写入 stdout 之前缓冲完整响应（而不是流式传输）：

        ```bash
        deepagents -n "Generate a .gitignore for Python" -q > .gitignore
        deepagents -n "List dependencies" -q --no-stream | sort
        ```

        在非交互模式下，代理被指示做出合理的假设并自主进行，而不是提出澄清问题。它还倾向于非交互式命令变体（例如 `npm init -y`、`apt-get install -y`）。
    </Accordion>

    <Accordion title="Shell 执行示例" icon="shield-check">
        ```bash
        # 允许特定命令（针对列表进行验证）
        deepagents -n "Run the tests and fix failures" -S "pytest,git,make"

        # 使用策划的安全命令列表
        deepagents -n "Build the project" -S recommended

        # 允许任何 shell 命令
        deepagents -n "Fix the build" -S all
        ```
    </Accordion>
</AccordionGroup>

<Warning>
    **谨慎使用。**

    `-S all`（或 `--shell-allow-list all`）允许代理执行任意 shell 命令而无需人工确认。
</Warning>

## 在启动时运行命令

使用 `--startup-cmd` 在会话接受其第一个提示词之前运行一次 shell 命令。输出在会话顶部显示给您，这对于在输入第一个提示词之前检查 `git status`、列出文件或验证环境设置很方便。

```bash
# 交互式：在第一个提示词前显示 git status
deepagents --startup-cmd "git status"

# 结合初始提示词——命令先运行，然后提交提示词
deepagents --startup-cmd "ls -la" -m "Summarize what's in this directory"

# 非交互式：在任务运行前查看环境状态
deepagents --startup-cmd "git diff --stat" -n "Review these changes"
```

命令在任何 `-m` 提示词或 `--skill` 调用被分派之前运行，并尊重您的 shell 环境。非零退出和超时发出警告但不会中止会话。在非交互模式下，命令有 60 秒超时。

<Note>
    输出**不会**注入到代理的消息历史中——LLM 看不到它。要将命令输出传递给代理，请通过 stdin 管道传输（例如 `git diff | deepagents -n "Review these changes"`）。
</Note>

## 切换模型

您可以使用 `/model` 命令在会话中切换模型而无需重启 CLI，或使用 `--model` 标志在启动时切换：

```txt
> /model anthropic:claude-opus-4-6
> /model openai:gpt-5.4
```

```bash
deepagents --model openai:gpt-5.4
```

运行 `/model` 打开交互式模型选择器，显示按提供商分组的可用模型。

有关切换模型、设置默认值和添加自定义模型提供商的完整详细信息，请参阅[模型提供商](/oss/javascript/deepagents/cli/providers)。

<AccordionGroup>
    <Accordion title="交互式模型选择器" icon="list">
        选择器为高亮的模型显示详情页脚，包括上下文窗口大小、输入模态（文本、图像、音频、PDF、视频）和能力（推理、工具调用、结构化输出）。

        通过 `--profile-override` 或 `config.toml` 覆盖的值带有黄色 `*` 前缀标记。
    </Accordion>

    <Accordion title="模型参数" icon="adjustments">
        在会话中切换时使用 `--model-params` 传递额外的模型构造函数参数：

        ```txt
        > /model --model-params '{"temperature": 0.7}' anthropic:claude-opus-4-7
        > /model --model-params '{"temperature": 0.7}'  # 打开选择器，将参数应用到所选模型
        ```

        这些是会话级覆盖，优先于配置文件 `params` 中的值。`--model-params` 不能与 `--default` 结合使用。
    </Accordion>
</AccordionGroup>

## 切换代理

运行 `/agents` 打开代理选择器并在不重启的情况下热切换到 `~/.deepagents/` 中的代理。切换会重置对话线程并刷新技能发现。该选择被保留，因此下一次裸 `deepagents` 启动会恢复同一代理。`-a`/`--agent` 始终覆盖；`-r`/`--resume` 恢复线程的原始代理。

## 配置

CLI 将所有配置存储在 `~/.deepagents/` 下。在该目录中，每个代理都有自己的子目录（默认：`agent`）：

| 路径 | 用途 |
|------|------|
| `~/.deepagents/config.toml` | 模型默认值、提供商设置、构造函数参数、配置文件覆盖、主题、更新设置、MCP 信任存储 |
| `~/.deepagents/.env` | 全局 API 密钥和密钥。请参阅[配置](/oss/javascript/deepagents/cli/configuration#environment-variables) |
| `~/.deepagents/hooks.json` | 生命周期事件钩子（会话开始/结束、任务完成等） |
| `~/.deepagents/<agent_name>/` | 每个代理的记忆、技能和对话线程 |
| `.deepagents/`（项目根目录） | 项目特定的记忆和技能，在 git 仓库内运行时加载 |

```bash
# 列出所有已配置的代理
deepagents agents list
```

有关完整参考——包括 `config.toml` 模式、提供商参数、配置文件覆盖和钩子配置——请参阅[配置](/oss/javascript/deepagents/cli/configuration)。

## 记忆

有两种主要方法可以自定义任何代理：

- **记忆**：`AGENTS.md` 文件和自动保存的记忆，跨会话持久化。使用记忆来存储通用编码风格、偏好和学习到的约定。
- **技能**：全局和项目特定的上下文、约定、指南或指令。在执行特定任务时才需要的上下文使用技能。

使用 `/remember` 明确提示代理从当前对话更新其记忆和技能。

<Tip>
    使用 SDK 构建自定义代理？请参阅[记忆](/oss/javascript/deepagents/memory)了解编程式记忆后端。
</Tip>

### 自动记忆

当您使用代理时，它会自动将信息存储在 `~/.deepagents/<agent_name>/memories/` 中作为 markdown 文件，使用记忆优先协议：

1. **研究**：在开始任务前搜索记忆中的相关上下文
2. **响应**：在执行过程中不确定时检查记忆
3. **学习**：自动保存新信息以供未来会话使用

代理按主题组织其记忆，使用描述性文件名：

```
~/.deepagents/backend-dev/memories/
├── api-conventions.md
├── database-schema.md
└── deployment-process.md
```

当您教代理约定时：

```bash
deepagents --agent backend-dev
> Our API uses snake_case and includes created_at/updated_at timestamps
```

它会记住以供将来会话使用：

```bash
> Create a /users endpoint
# 无需提示即可应用约定
```

### AGENTS.md 文件

[`AGENTS.md` 文件](https://agents.md/) 提供在会话开始时始终加载的持久上下文：

- **全局**：`~/.deepagents/<agent_name>/AGENTS.md` — 每个会话加载。
- **项目**：任何 git 项目根目录中的 `.deepagents/AGENTS.md` — 当 CLI 在该项目内运行时加载。

两个文件都在启动时附加到系统提示词。

<AccordionGroup>
    <Accordion title="记忆如何工作" icon="brain">
        代理在回答项目特定问题或您引用过去工作或模式时也可以读取其记忆文件。

        代理会在您提供关于它应如何行为的信息、对其工作的反馈或记住某些内容的指令时更新 `AGENTS.md`。
        如果它从您的交互中识别出模式或偏好，它也会更新其记忆。

        要在额外的记忆文件中添加更多结构化的项目知识，请将它们添加到 `.deepagents/` 中，并在 `AGENTS.md` 文件中引用它们。
        您必须在 `AGENTS.md` 文件中引用额外文件，代理才能知道它们。
        额外文件不会在启动时读取，但代理可以在需要时引用和更新它们。
    </Accordion>

    <Accordion title="何时使用全局 vs. 项目 AGENTS.md" icon="arrows-split">
        **全局 `AGENTS.md`**（`~/.deepagents/agent/AGENTS.md`）

        - 您的个性、风格和通用编码偏好
        - 通用语调和沟通风格
        - 通用编码偏好（格式化、类型提示等）
        - 适用于各地的工俱使用模式
        - 不因项目而异的工乍流程和方法论

        **项目 `AGENTS.md`**（项目根目录中的 `.deepagents/AGENTS.md`）

        - 项目特定的上下文和约定
        - 项目架构和设计模式
        - 此代码库特有的编码约定
        - 测试策略和部署流程
        - 团队指南和项目结构
    </Accordion>
</AccordionGroup>

## 使用技能

技能是可重用的代理能力，提供专门的工作流和领域知识。
您可以使用[技能](/oss/javascript/deepagents/skills)为您的深度代理提供新能力和专业知识。
深度代理技能遵循 [Agent Skills 标准](https://agentskills.io/)。
一旦添加了技能，您的深度代理将自动使用它们，并在您使用代理并向其提供额外信息时更新它们。

使用 `/remember` 明确提示代理从当前对话更新技能和记忆。

<AccordionGroup>
    <Accordion title="添加技能" icon="plus">
        1. 创建一个技能：

            ```bash
            # 用户技能（存储在 ~/.deepagents/<agent_name>/skills/）
            deepagents skills create test-skill

            # 项目技能（存储在 .deepagents/skills/）
            deepagents skills create test-skill --project
            ```

            这会生成：

            ```plaintext
            skills/
            └── test-skill
                └── SKILL.md
            ```

        2. 打开生成的 `SKILL.md` 并编辑文件以包含您的指令。

        3. （可选）将其他脚本或其他资源添加到 `test-skill` 文件夹。更多信息请参阅[示例](/oss/javascript/deepagents/skills#example)。

        您也可以直接将现有技能复制到代理的文件夹：

        ```bash
        mkdir -p ~/.deepagents/<agent_name>/skills
        cp -r examples/skills/web-research ~/.deepagents/<agent_name>/skills/
        ```
    </Accordion>

    <Accordion title="安装社区技能" icon="download">
        您可以使用 Vercel 的 [Skills CLI](https://github.com/vercel-labs/skills) 等工具来安装社区 [Agent Skills](https://agentskills.io/) 并使它们对您的深度代理可用：

        ```bash
        # 全局安装技能
        npx skills add vercel-labs/agent-skills --skill web-design-guidelines -a deepagents -g -y

        # 列出已安装的技能
        npx skills ls -a deepagents -g
        ```

        全局安装（`-g`）将技能符号链接到 `~/.deepagents/agent/skills/` — 默认代理的用户级技能目录。项目级安装（省略 `-g`）将技能放置在相对于当前目录的 `.deepagents/skills/`，使它们对在该项目中运行的任何代理可用，而不考虑代理名称。

        <Note>
            全局安装仅针对默认 `agent` 目录。如果您使用自定义名称的代理，要么使用项目级安装，要么手动将技能符号链接到 `~/.deepagents/{your-agent}/skills/`。
        </Note>
    </Accordion>

    <Accordion title="技能发现" icon="radar">
        在启动时，CLI 从 Deep Agents 和共享别名目录中发现技能：

        ```text
        ~/.deepagents/<agent_name>/skills/
        ~/.agents/skills/
        .deepagents/skills/
        .agents/skills/
        ~/.claude/skills/          (实验性)
        .claude/skills/            (实验性)
        ```

        当存在重复的技能名称时，后置目录优先于前置目录（请参阅[应用程序数据](/oss/javascript/deepagents/data-locations#skills)）。

        对于项目特定的技能，项目的根文件夹必须有 `.git` 文件夹。
        当您从项目文件夹内的任何地方启动 CLI 时，CLI 会通过检查包含的 `.git` 文件夹来找到项目的根文件夹。

        对于每个技能，CLI 从 `SKILL.md` 文件的 frontmatter 中读取名称和描述。
        当您使用 CLI 时，如果任务与技能描述匹配，代理将读取技能文件并遵循其指令。

        您也可以使用 `/skill:<name> [args]` 直接调用技能。技能发现在启动时运行，并在 `/reload` 时再次运行。
    </Accordion>

    <Accordion title="从命令行调用技能" icon="player-play">
        使用 `--skill` 在启动时调用技能，而无需交互输入斜杠命令：

        ```bash
        # 打开 TUI 并立即运行技能
        deepagents --skill code-review

        # 使用 -m 向技能传递请求
        deepagents --skill code-review -m 'review the auth module'

        # 将内容管道传输到技能
        cat diff.txt | deepagents --skill code-review

        # 管道传输内容并添加请求
        cat diff.txt | deepagents --skill code-review -m 'focus on security'
        ```

        `--skill` 在非交互模式下也能工作：

        ```bash
        # 无头运行技能
        deepagents --skill code-review -n 'review this patch'

        # 安静模式（仅 stdout 上的代理输出）
        deepagents --skill code-review -n 'review this patch' -q
        ```

        <Note>
            带有 `--quiet` 或 `--no-stream` 的 `--skill` 需要 `-n`（非交互模式）。
        </Note>
    </Accordion>

    <Accordion title="列出技能" icon="list">
        ```bash
        # 列出所有用户技能
        deepagents skills list

        # 列出项目技能
        deepagents skills list --project

        # 获取特定技能的详细信息
        deepagents skills info test-skill
        deepagents skills info test-skill --project
        ```
    </Accordion>
</AccordionGroup>

## 子代理

定义自定义[子代理](/oss/javascript/deepagents/subagents)为 markdown 文件，以便 CLI 代理可以将专门任务委托给它们。每个子代理驻留在自己的文件夹中，包含 `AGENTS.md` 文件：

```text
.deepagents/agents/{sub代理名称}/AGENTS.md   # 项目级
~/.deepagents/{agent}/agents/{sub代理名称}/AGENTS.md  # 用户级
```

项目子代理会覆盖具有相同名称的用户子代理（请参阅[优先级规则](/oss/javascript/deepagents/data-locations#subagents)）。

frontmatter 需要 `name` 和 `description`（与 [`SubAgent` 字典规范](/oss/javascript/deepagents/subagents#subagent-dictionary-based) 相同）。markdown 正文成为子代理的 `system_prompt`。除了基本规范外，`AGENTS.md` 文件还支持可选的 `model` frontmatter 字段，该字段为此子代理覆盖主代理的模型。使用 `提供商:模型名称` 格式（例如 `anthropic:claude-opus-4-6`、`openai:gpt-5.4`）。省略以继承主代理的模型。

<Note>
        其他 `SubAgent` 字段（`tools`、`middleware`、`interrupt_on`、`skills`）目前无法通过 `AGENTS.md` frontmatter 配置——以这种方式定义的自定义子代理继承主代理的工具。使用 SDK 获取完全控制。
</Note>

<AccordionGroup>
    <Accordion title="文件格式" icon="file">
        子代理 `AGENTS.md` 文件使用 YAML frontmatter 后跟 markdown 正文：

        ```markdown
        ---
        name: researcher
        description: Research topics on the web before writing content
        model: anthropic:claude-haiku-4-5-20251001
        ---

        You are a research assistant with access to web search.

        ## Your Process
        1. Search for relevant information
        2. Summarize findings clearly
        ```
    </Accordion>

    <Accordion title="示例：成本效益子代理">
        对简单的委托任务使用更便宜、更快的模型，同时将主代理保留在更有能力的模型上：

        ```markdown
        ---
        name: general-purpose
        description: General-purpose agent for research and multi-step tasks
        model: anthropic:claude-haiku-4-5-20251001
        ---

        You are a general-purpose assistant. Complete the task efficiently and return a concise summary.
        ```

        这会覆盖内置的通用目的子代理，将所有委托任务路由到更便宜的模型。请参阅[覆盖通用目的子代理](/oss/javascript/deepagents/subagents#override-the-general-purpose-subagent)了解更多。
    </Accordion>
</AccordionGroup>

## 使用 MCP 工具

使用来自外部 [MCP (Model Context Protocol)](https://modelcontextprotocol.io/) 服务器的工具扩展 CLI。在项目根目录放置一个 `.mcp.json`，CLI 会自动发现它。需要 OAuth 的服务器（Slack、GitHub、Linear、Notion 等）可以使用 `deepagents mcp login <server>` 进行一次性身份验证；令牌持久化到 `~/.deepagents/mcp-tokens/` 并自动刷新。请参阅 [MCP 工具指南](/oss/javascript/deepagents/cli/mcp-tools)了解配置格式、OAuth 登录、自动发现和故障排除。

        ```bash title="setup.sh"
        #!/bin/bash
        set -e

        # 使用 GitHub 令牌克隆仓库
        git clone https://x-access-token:${GITHUB_TOKEN}@github.com/username/repo.git $HOME/workspace

        cat >> ~/.bashrc <<'EOF'
        export GITHUB_TOKEN="${GITHUB_TOKEN}"
        export OPENAI_API_KEY="${OPENAI_API_KEY}"
        cd $HOME/workspace
        EOF
        source ~/.bashrc
        ```

        CLI 使用本地环境变量展开设置脚本中的 `${VAR}` 引用。将密钥存储在本地 `.env` 文件中以供设置脚本访问。

## 使用 LangSmith 进行追踪

启用 [LangSmith](https://smith.langchain.com/) 追踪以在 LangSmith 项目中查看代理操作、工具调用和决策。

将您的追踪密钥添加到 `~/.deepagents/.env`，以便在每个会话中启用追踪，而无需每个 shell 导出：

```bash title="~/.deepagents/.env"
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_PROJECT=optional-project-name  # 指定项目名称或默认为 "deepagents-cli"
```

要覆盖特定项目，请将相同的密钥添加到项目目录中的 `.env`。请参阅[环境变量](/oss/javascript/deepagents/cli/configuration#environment-variables)了解完整的加载顺序。

如果您愿意，也可以将它们设置为 shell 环境变量。Shell 导出始终优先于 `.env` 值，因此这是临时覆盖或测试的好选项：

```bash
export LANGSMITH_TRACING=false
```

<Accordion title="将代理追踪与应用追踪分开">
    当从 LangChain 应用程序以编程方式调用 CLI 时（例如作为非交互模式下的子进程），您的应用和 CLI 都会产生 LangSmith 追踪。默认情况下，这些都落在同一个项目中。

    要将 CLI 追踪发送到专用项目，请设置 `DEEPAGENTS_CLI_LANGSMITH_PROJECT`：

    ```bash title="~/.deepagents/.env"
    DEEPAGENTS_CLI_LANGSMITH_PROJECT=my-deep-agent-execution
    ```

    然后为您的父应用程序的追踪配置 `LANGSMITH_PROJECT`：

    ```bash title="~/.deepagents/.env"
    LANGSMITH_PROJECT=my-app-traces
    ```

    这可以保持您的应用级可观测性清晰，同时仍在单独的项目中捕获代理的内部执行。

    您也可以使用 [`DEEPAGENTS_CLI_` 前缀](/oss/javascript/deepagents/cli/configuration#deepagents_cli_-prefix) 将 LangSmith 凭证限定于 CLI（例如 `DEEPAGENTS_CLI_LANGSMITH_API_KEY`）。
</Accordion>

配置后，CLI 显示带有 LangSmith 项目链接的状态行。在支持的终端中，点击链接直接打开。您也可以使用 `/trace` 打印 URL 并在浏览器中打开。

```sh
✓ LangSmith tracing: 'my-project'
```

## 命令参考

```bash
# 使用特定的代理配置
deepagents --agent mybot

# 使用特定模型（提供商:模型格式或自动检测）
deepagents --model anthropic:claude-opus-4-7
deepagents --model gpt-5.4

# 自动批准工具使用（跳过人在回路中提示）
deepagents -y
```

<AccordionGroup>
    <Accordion title="命令行选项" icon="flag">
        | 选项 | 描述 |
        |------------------------|-------------------------------------------------------------|
        | `-a`, `--agent NAME` | 使用具有单独记忆的命名代理。覆盖 `config.toml` 中的 `[agents].recent`。默认：`agent`（或如果设置了 `[agents].recent` 则使用最近使用的代理） |
        | `-M`, `--model MODEL` | 使用特定模型（`提供商:模型`） |
        | `--model-params JSON` | 作为 JSON 字符串传递到模型的额外 kwargs（例如 `'{"temperature": 0.7}'`） |
        | `--default-model [MODEL]` | 设置默认模型 |
        | `--clear-default-model` | 清除默认模型 |
        | `-r`, `--resume [ID]` | 恢复会话：`-r` 用于最近的，`-r <ID>` 用于特定线程 |
        | `-m`, `--message TEXT` | 会话启动时自动提交的初始提示词（交互模式） |
        | `--skill NAME` | 在启动时调用技能 |
        | `--startup-cmd CMD` | 在第一个提示词之前在启动时运行的 shell 命令。输出在记录中呈现给您参考，但**不会**添加到代理的消息历史中。非零退出和超时警告但不会中止；非交互模式应用 60s 超时。请参阅[在启动时运行命令](#run-a-command-at-startup) |
        | `-n`, `--non-interactive TEXT` | 非交互地运行单个任务并退出。Shell 已被禁用除非设置了 `--shell-allow-list` |
        | `--max-turns N` | 在非交互模式中限制代理轮次。超出时退出代码 124。需要 `-n` 或管道 stdin。请参阅[使用 `--max-turns` 限制轮次](#non-interactive-mode-and-piping) |
        | `-q`, `--quiet` | 适合管道的清洁输出——只有代理的响应输出到 stdout。需要 `-n` 或管道 stdin |
        | `--no-stream` | 缓冲完整响应并一次性写入 stdout，而不是流式传输。需要 `-n` 或管道 stdin |
        | `--stdin` | 明确从 stdin 读取输入而不是自动检测。在 stdin 不可用或为 TTY 时清楚地报错 |
        | `-y`, `--auto-approve` | 自动批准所有工具调用而无需提示（禁用人在回路中）。在交互会话期间使用 `Shift+Tab` 切换 |
        | `-S`, `--shell-allow-list LIST` | 以逗号分隔的 shell 命令列表以自动批准，`'recommended'` 获取安全默认值，或 `'all'` 允许任何命令。适用于 `-n` 和交互模式 |
        | `--json` | 从管理子命令（`agents`、`threads`、`skills`、`update`）发出机器可读 JSON。输出信封：`{"schema_version": 1, "command": "...", "data": ...}` |
        | `--sandbox TYPE` | 代码执行的远程沙箱：`none`（默认）、`langsmith`、`agentcore`、`modal`、`daytona`、`runloop`。LangSmith 包含在内；AgentCore/Modal/Daytona/Runloop 需要额外工具 |
        | `--sandbox-id ID` | 重用现有沙箱（跳过创建和清理） |
        | `--sandbox-setup PATH` | 创建后在沙箱中运行的设置脚本路径 |
        | `--mcp-config PATH` | 添加显式 MCP 配置作为最高优先级来源（与自动发现的配置合并） |
        | `--no-mcp` | 禁用所有 MCP 工具加载 |
        | `--trust-project-mcp` | 信任具有 stdio 服务器的项目级 MCP 配置（跳过批准提示） |
        | `--profile-override JSON` | 覆盖模型配置文件字段作为 JSON 字符串（例如 `'{"max_input_tokens": 4096}'`）。在配置文件配置文件覆盖之上合并 |
        | `--acp` | 通过 stdio 作为 ACP 服务器运行，而不是启动交互式 UI |
        | `-v`, `--version` | 显示版本 |
        | `-h`, `--help` | 显示帮助 |
    </Accordion>

    <Accordion title="CLI 命令" icon="terminal">
        | 命令 | 描述 |
        |--------------------------------------|----------------------------------------|
        | `deepagents help` | 显示帮助 |
        | `deepagents agents list` | 列出所有代理（别名：`ls`） |
        | `deepagents agents reset --agent NAME` | 清除代理记忆并重置为默认值。支持 `--dry-run` |
        | `deepagents agents reset --agent NAME --target SOURCE` | 从另一个代理复制记忆 |
        | `deepagents update` | 检查并安装 CLI 更新 |
        | `deepagents skills list [--project]` | 列出所有技能（别名：`ls`） |
        | `deepagents skills create NAME [--project]` | 使用模板 `SKILL.md` 创建新技能。幂等——重新创建现有技能会打印信息性消息而不是错误 |
        | `deepagents skills info NAME [--project]` | 显示关于技能的详细信息 |
        | `deepagents skills delete NAME [--project] [-f]` | 删除技能及其内容。支持 `--dry-run` |
        | `deepagents threads list [--agent NAME] [--limit N]` | 列出会话（别名：`ls`）。默认限制：20。`-n` 是 `--limit` 的短标志。其他标志：`--sort {created,updated}`、`--branch TEXT`（按 git 分支筛选）、`-v`/`--verbose`（显示所有列包括分支、创建时间和初始提示词）、`-r`/`--relative`（相对时间戳） |
        | `deepagents threads delete ID` | 删除会话。支持 `--dry-run` |
        | `deepagents mcp login NAME [--config PATH]` | 为标记为 `auth: "oauth"` 的 MCP 服务器运行 OAuth 登录流程。请参阅 [MCP 工具](/oss/javascript/deepagents/cli/mcp-tools#oauth-login) |
        | `deepagents deploy` | 将您的代理部署到 LangSmith。请参阅[使用 CLI 部署](/oss/javascript/deepagents/deploy) |

        所有管理子命令都支持 `--json` 以获取机器可读的输出。请参阅[命令行选项](#command-line-options)了解更多详情。

        破坏性命令（`agents reset`、`skills delete`、`threads delete`）支持 `--dry-run` 以预览将要发生的事情而不进行更改。在 JSON 模式下，`--dry-run` 返回带有 `dry_run: true` 字段的相同信封。
    </Accordion>
</AccordionGroup>
