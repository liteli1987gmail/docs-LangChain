title: 实现 LangChain 集成
sidebarTitle: 实现

集成包是用户可以安装以在其项目使用的 Python 包。它们实现一个或多个符合 LangChain 接口标准的组件。

LangChain 组件是 [`langchain-core`](https://github.com/langchain-ai/langchain/tree/master/libs/core) 中基类的子类。示例包括[聊天模型](/oss/javascript/integrations/chat)、[工具](/oss/javascript/integrations/tools)、[检索器](/oss/javascript/integrations/retrievers)等等。

你的集成包通常会实现至少一个这些组件的子类。展开以下选项卡以查看每个的详细信息。

<Tabs>
    <Tab title="聊天模型">
        聊天模型是 [`BaseChatModel`](https://reference.langchain.com/javascript/langchain-core/language_models/chat_models/BaseChatModel) 类的子类。它们实现生成聊天补全、处理消息格式化和管理模型参数的方法。

        <Warning>

            聊天模型集成指南目前正在开发中。同时，请阅读[聊天模型概念指南](/oss/javascript/langchain/models)了解更多关于 LangChain 聊天模型如何工作的详细信息。你也可以参考 [LangChain 仓库](https://github.com/langchain-ai/langchainjs/tree/main/libs/providers)中的现有集成

        </Warning>
    </Tab>
    <Tab title="嵌入向量">
        嵌入向量模型是 [`Embeddings`](https://reference.langchain.com/javascript/langchain-core/embeddings/Embeddings) 类的子类。

        <Warning>
            嵌入向量模型集成指南目前正在开发中。同时，请阅读[嵌入向量模型概念指南](/oss/javascript/integrations/embeddings)了解更多关于 LangChain 嵌入向量模型如何工作的详细信息。
        </Warning>
    </Tab>
    <Tab title="工具">
        工具主要有两种使用方式：

        1. 定义"输入模式"或"参数模式"，与文本请求一起传递给聊天模型的工具调用功能，以便聊天模型可以生成"工具调用"，即调用工具的参数。
        2. 获取上面生成的"工具调用"，执行一些操作并返回可以作为 ToolMessage 传回给聊天模型的响应。

        工具类必须继承自 [`BaseTool`](https://reference.langchain.com/javascript/classes/_langchain_core.tools.StructuredTool.html) 基类。此接口有 3 个属性和 2 个方法，应在子类中实现。

        <Warning>
            工具集成指南目前正在开发中。同时，请阅读[工具概念指南](/oss/javascript/langchain/tools)了解更多关于 LangChain 工具如何工作的详细信息。
        </Warning>
    </Tab>
    <Tab title="中间件">
        [中间件](/oss/javascript/langchain/middleware/overview) 让你通过钩入模型调用、工具调用和代理生命周期事件来自定义代理行为。中间件类是 [`AgentMiddleware`](https://reference.langchain.com/javascript/langchain/index/AgentMiddleware) 基类的子类。

        在构建集成之前，请阅读[自定义中间件指南](/oss/javascript/langchain/middleware/custom)以了解钩子、状态更新和中间件模式。

        中间件集成通常分为两类：

        | 类型 | 描述 | 示例 |
        |------|-------------|---------|
        | **特定于提供商** | 利用提供商独特的能力 | 提示词缓存、本机工具执行、内容审核 |
        | **跨提供商** | 可与任何模型或工具配合使用 | 速率限制、PII 检测、日志记录、护栏 |

        特定于提供商的中间件位于提供商的集成包中（例如 `langchain-anthropic`）。跨提供商中间件可以作为独立包发布。

        你也可以使用这些现有的中间件集成作为参考：


        <CardGroup cols={2}>
            <Card title="Anthropic 中间件" icon="robot" href="/oss/javascript/integrations/middleware/anthropic">
                用于提示词缓存、工具、记忆和文件搜索的多个中间件类。
            </Card>
            <Card title="自定义中间件指南" icon="code" href="/oss/javascript/langchain/middleware/custom">
                钩子、状态更新和模式的完整参考。
            </Card>
        </CardGroup>


    </Tab>
    <Tab title="检查点保存器">
        检查点保存器在 LangGraph 中启用[持久化](/oss/javascript/langgraph/persistence)，允许代理保存和恢复跨交互的状态。

        在 [LangGraph 仓库](https://github.com/langchain-ai/langgraph/tree/main/libs)中查看现有的检查点保存器集成以获取实现示例。
    </Tab>
    <Tab title="沙盒">
        沙盒集成使 [Deep Agents](/oss/javascript/deepagents/overview) 能够在隔离环境中运行代码。


    </Tab>
</Tabs>
